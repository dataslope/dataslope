## 2. What Won't Work As-Is for DuckDB

### 2.1 Triggers — Completely Unsupported

DuckDB has **no trigger support**. Both existing playgrounds expose a "Triggers" section in the schema sidebar, and the SQLite engine has `listTriggers()` / `listTableTriggers()`. The ER diagram context menu also has a "Drop Trigger" path. These sections must be **omitted** in the DuckDB playground.

**Impact:** Remove `listTriggers`, trigger sidebar section, and trigger drop/DDL from `DuckDbEngine`.

---

### 2.2 VIRTUAL Generated Columns — Not Supported

The SQLite `ModifyStructureForm` exposes a `storageType` selector with `VIRTUAL` and `STORED` options. DuckDB only supports **STORED generated columns**. Presenting `VIRTUAL` as an option would silently produce invalid DDL.

**Impact:** Remove the `storageType` toggle in the Modify Structure drawer (DuckDB form should only offer STORED).

---

### 2.3 Row-Level Cell Editing via `rowid` — Not Applicable

`SqliteEngine.updateRows()` identifies a row to update using `rowid OFFSET rowIndex`, an internal SQLite-only construct. This avoids needing a primary key. DuckDB has **no implicit `rowid`**; every row update requires a PK-based `WHERE` clause.

**Impact:** Inline cell editing will require the result to have a primary-key column. The `DuckDbEngine.updateRows()` implementation must use PK values from the row rather than a row index. Tables without PKs will need to show "editing not available" in the result view.

---

### 2.4 SQLite PRAGMA Settings — Entirely Inapplicable

The `PragmaSettingsTab` component exposes six SQLite-specific pragmas (journal mode, synchronous, page size, etc.). None of these exist in DuckDB.

**Impact:** The Settings dialog for the DuckDB playground needs no "Database Settings" / PRAGMA tab. The general appearance settings (font size, theme, word wrap, clear before run) are still applicable.

---

### 2.5 `.sqlite` Database Export/Upload

`SqliteEngine.exportDatabase()` returns a `Uint8Array` of the raw SQLite file that users can download and re-upload. DuckDB-wasm doesn't expose a one-liner `export()`. The `exportFile('/path')` API exists but depends on the OPFS-backed virtual filesystem and requires the DB to be file-backed, not purely in-memory.

**Impact:** The "Download database" button from the SQLite playground can't be directly ported. See §3.4 for the DuckDB alternative.

---

### 2.6 CodeMirror SQL Dialect

Both existing playgrounds pass a specific dialect to `@codemirror/lang-sql`:
- SQLite playground: `SQLite` dialect
- Postgres playground: `PostgreSQL` dialect

There is no `DuckDB` dialect in `@codemirror/lang-sql`. The closest option is `StandardSQL` (or no dialect, which defaults to ANSI). DuckDB's `LIST`, `STRUCT`, `MAP`, `ENUM` types and functions like `read_parquet()`, `unnest()`, `pivot`, etc. won't appear as autocomplete suggestions out of the box.

**Impact:** Use `StandardSQL` dialect. Supplement `createSqlCompletionSource()` with a DuckDB-specific keyword/function list.

---

### 2.7 DDL Reconstruction

SQLite gets DDL from `sqlite_master.sql` (a raw CREATE statement string). Postgres reconstructs DDL from `information_schema` + `pg_catalog` queries. DuckDB has its own virtual catalog: `duckdb_tables()`, `duckdb_views()`, `duckdb_columns()`, `duckdb_indexes()`, `duckdb_constraints()`. The `getDDL()` function will need to be rewritten against these DuckDB-specific views.

**Impact:** Implement `getDDL()` in `DuckDbEngine` using `duckdb_tables`, `duckdb_columns`, `duckdb_constraints`, and `duckdb_indexes`.

---

### 2.8 Index/Constraint Introspection

Both engines use their respective catalog to enumerate indexes and column constraints. DuckDB exposes this via `duckdb_indexes()` and `duckdb_constraints()`, not via `PRAGMA index_list`/`PRAGMA foreign_key_list` (SQLite) or `information_schema.table_constraints` (Postgres). The column constraint query needs rewriting.

**Impact:** Rewrite `listIndexes()`, `listForeignKeys()`, and `getColumnConstraintInfo()` for DuckDB's catalog tables.

---

### 2.9 Synchronous vs. Asynchronous Execution Model

`SqliteEngine` methods are **synchronous** (sql.js runs on the main thread). `PostgresEngine` methods are **async** (PGlite uses worker messages). `duckdb-wasm` is always async (runs in a dedicated Web Worker). The existing `useQueryRunner` hook for SQLite calls `engine.exec()` synchronously inside a `try/catch`. That hook cannot be reused directly.

**Impact:** The DuckDB playground must use an async execution pattern throughout, similar to `PostgresPlayground.tsx`. All engine method calls need `await`.

---

### 2.10 Sync vs. Async Schema Refresh

After each SQL run, `useQueryRunner` (SQLite) calls `engine.listTables()` and `engine.listViews()` synchronously to refresh the sidebar. For DuckDB, all these calls must be awaited and chained.

**Impact:** The post-run schema refresh callback must be async and awaited.

---

## 3. DuckDB-Specific Features to Add

### 3.1 Native Parquet / CSV / JSON File Querying

DuckDB's standout browser feature is its ability to directly query files without importing them into tables:

```sql
SELECT * FROM read_parquet('uploaded.parquet');
SELECT * FROM read_csv_auto('uploaded.csv');
SELECT * FROM read_json_auto('uploaded.json');
```

Using `db.registerFileBuffer(name, buffer)` or `db.registerFileHandle(name, file, ...)`, the playground can let users drag-and-drop files and immediately run SQL against them — no explicit CREATE TABLE or INSERT needed.

**Implementation idea:** A "Query file" button in the import dialog that registers the file and opens a new tab pre-seeded with a `SELECT * FROM read_parquet(...)` query.

---

### 3.2 Richer Type System

DuckDB supports many more types than SQLite or Postgres. The Modify Structure drawer's type dropdown needs to include:

| Category | Types |
|---|---|
| Integer | `TINYINT`, `SMALLINT`, `INTEGER`, `BIGINT`, `HUGEINT`, `UBIGINT` |
| Float | `FLOAT`, `DOUBLE`, `DECIMAL(p,s)` |
| Text | `VARCHAR`, `TEXT`, `BLOB` |
| Boolean | `BOOLEAN` |
| Date/time | `DATE`, `TIME`, `TIMESTAMP`, `TIMESTAMP WITH TIME ZONE`, `INTERVAL` |
| Semi-structured | `JSON` |
| Collections | `INTEGER[]` (LIST), `STRUCT(...)`, `MAP(...)` |
| Special | `UUID`, `ENUM(...)`, `UNION(...)`, `BIT` |

The `COLUMN_TYPES` constant (currently in `app/_components/sql/constants.ts`) needs a DuckDB-specific counterpart.

---

### 3.3 Auto-Increment / Identity Columns

DuckDB supports identity columns (SQL standard) and `SEQUENCE` objects. Instead of SQLite's `INTEGER PRIMARY KEY AUTOINCREMENT` or Postgres's `serial`/`bigserial`, DuckDB uses:

```sql
id INTEGER PRIMARY KEY,                           -- manual
id INTEGER GENERATED ALWAYS AS IDENTITY,          -- identity (read-only)
id INTEGER GENERATED BY DEFAULT AS IDENTITY,      -- identity (overridable)
```

The Modify Structure form needs a DuckDB-appropriate auto-increment representation.

---

### 3.4 Database Export / Import

**Export:** Use `conn.query("COPY database TO '...' (FORMAT DUCKDB)")` or the `exportFile()` API on the virtual filesystem to download a `.duckdb` file. Alternatively, DuckDB's native Parquet export is a strong option:

```sql
COPY (SELECT * FROM my_table) TO 'export.parquet' (FORMAT PARQUET);
```

A simpler fallback is exporting each table as Parquet or CSV from the UI.

**Import:** Users can upload `.duckdb` files (`db.open()` from bytes), `.parquet`, `.csv`, or `.json` files (registered as virtual files and queried directly).

---

### 3.5 Sequences in Schema Sidebar

DuckDB supports `CREATE SEQUENCE`. The schema sidebar can show a "Sequences" section listing sequences from `duckdb_sequences()`. This is absent from both existing playgrounds but is a meaningful DuckDB concept.

---

### 3.6 EXPLAIN and Query Plan Visualization

DuckDB's `EXPLAIN` and `EXPLAIN ANALYZE` produce readable output. The result view handles this as plain text already, but a dedicated "Explain" button in the toolbar (like the SQLite PRAGMA runner does for special modes) would highlight DuckDB's query optimizer.

---

### 3.7 DuckDB-Specific Sample Databases

DuckDB ships built-in sample data:
- `FROM duckdb_settings()` — shows all runtime settings
- `CALL dbgen(sf=0.1)` — generates TPC-H data (with `tpch` extension)
- `CALL dsdgen(sf=0.1)` — generates TPC-DS data (with `tpcds` extension)
- `FROM 'https://...'` — DuckDB can query remote HTTP Parquet files directly in WASM

Suggested starter samples:
1. **Blank** — empty database
2. **E-Commerce** — orders/products/customers (port from SQLite CC sample, adapted to DuckDB types)
3. **TPC-H (tiny)** — inline SQL generated at init using `CALL dbgen(sf=0.01)` after loading the `tpch` extension, if that extension is available in the WASM build.
4. **Parquet demo** — a sample that showcases `read_parquet()` on a registered in-memory Parquet blob

---

### 3.8 DuckDB Settings Panel

Replace the SQLite PRAGMA panel with DuckDB-equivalent runtime settings that can be set via `SET` statements:

| Setting | SQL |
|---|---|
| Threads | `SET threads = N` |
| Memory limit | `SET memory_limit = '512MB'` |
| Null ordering | `SET default_null_order = 'NULLS LAST'` |
| Timezone | `SET TimeZone = 'UTC'` |

This is lower priority than the core features but adds instructional value.

## 4. Special Considerations

### 4.1 Web Worker Initialization in Next.js

DuckDB-wasm runs in a dedicated Web Worker. Bundlers (including Next.js / Webpack / Turbopack) may struggle to resolve the worker URL. The established pattern is:

```ts
const bundle = await duckdb.selectBundle(duckdb.getJsDelivrCdnBundles());
const workerUrl = URL.createObjectURL(
  new Blob([`importScripts("${bundle.mainWorker!}");`], { type: "text/javascript" }),
);
const worker = new Worker(workerUrl);
const db = new duckdb.AsyncDuckDB(new duckdb.ConsoleLogger(), worker);
await db.instantiate(bundle.mainModule, bundle.pthreadWorker);
```

Use the CDN bundles via jsDelivr (as the project already does for sql.js, parquet-wasm, wasm-xlsxwriter). Wrap initialization in a module-level promise so navigating away and back doesn't re-download.

Also add `next.config.ts` headers for `Cross-Origin-Opener-Policy: same-origin` and `Cross-Origin-Embedder-Policy: require-corp` if the multi-threaded EH bundle is used. The MVP bundle avoids this requirement.

### 4.2 Connection Model

`AsyncDuckDB` uses a connection object (`conn = await db.connect()`). The engine wrapper should hold a single persistent connection, closing and reopening it when the active database changes (similar to how `PostgresPlayground` closes `db` on DB switch).

### 4.3 Arrow Result Format

`conn.query(sql)` in duckdb-wasm returns an **Apache Arrow Table**, not the `QueryExecResult[]` format used throughout the UI. The engine adapter must convert Arrow tables to `QueryExecResult` objects:

```ts
function arrowToQueryExecResult(table: arrow.Table): QueryExecResult {
  const columns = table.schema.fields.map(f => f.name);
  const columnTypes = table.schema.fields.map(f => f.type.toString());
  const values = Array.from({ length: table.numRows }, (_, r) =>
    columns.map((_, c) => {
      const val = table.getChildAt(c)?.get(r);
      return val === undefined ? null : val;
    })
  );
  return { columns, columnTypes, values };
}
```

BigInt values (common in DuckDB `BIGINT`/`HUGEINT` columns) must be converted to `Number` or `string` since `QueryExecResult["values"]` is typed as `SqlValue[]` (number | string | null | Uint8Array).

### 4.4 Multi-Statement Execution

`conn.query()` in duckdb-wasm executes **one statement** at a time. Unlike sql.js's `db.run()` or PGlite's `db.exec()`, you cannot pass a semicolon-separated multi-statement string to a single call.

The engine's `exec(sql)` must split the SQL on statement boundaries and execute each statement in sequence, collecting results. A simple `sql.split(';')` is insufficient (semicolons inside string literals or comments). A proper statement splitter is needed — the existing `stripSqlComments` + semicolon split logic should work for most cases, or use DuckDB's own tokenizer: `conn.tokenize(sql)`.

### 4.5 No Transactions on Connection Close

PGlite supports `BEGIN`/`COMMIT` inside a single `exec()`. DuckDB-wasm also supports transactions, but `rebuildTable` (which uses `BEGIN`/`DROP`/`RENAME` in a transaction in the Postgres engine) must be adapted to use `conn.query("BEGIN")` etc., with explicit error handling and rollback.

### 4.6 File Registration for Imports

To import CSV/Parquet/JSON files with DuckDB's native functions, the file must be registered first:

```ts
await db.registerFileBuffer("upload.csv", new Uint8Array(await file.arrayBuffer()));
const result = await conn.query("SELECT * FROM read_csv_auto('upload.csv')");
```

This replaces the row-by-row INSERT pattern used by the SQLite and Postgres import paths.

### 4.7 Storage Prefix Conflicts

The SQLite playground uses `sqlite:` as its localStorage prefix. The Postgres playground uses `pg_postgres_`. The DuckDB playground should use a distinct prefix, e.g., `duckdb_`.

### 4.8 ER Diagram Compatibility

`ErDiagramPane` accepts `TableColumnInfo[]` and `ForeignKeyInfo[]` typed objects. As long as `DuckDbEngine.listColumns()` and `listForeignKeys()` return the same shapes (which they can, since these are just data contracts defined in `sqlite.ts`), the ER diagram component works unchanged.

### 4.9 `execAll` vs. Multi-Statement in SQL Playground

`SqlPlayground.tsx` calls `engine.execAll()` (SQLite-only) to get one result per statement, including `null` for non-SELECT statements. The DuckDB engine must expose an equivalent method that splits and sequentially executes statements, returning `(QueryExecResult | null)[]`.

## 7. Risk Register

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| Next.js/Turbopack can't resolve Worker URL | Medium | High | Use CDN blob-URL pattern for Worker; test early |
| COOP/COEP headers required for EH bundle | High | Medium | Use MVP bundle (no SharedArrayBuffer needed) |
| Arrow→QueryExecResult BigInt overflow | Medium | Medium | Convert BigInt to string in adapter; show warning |
| Multi-statement SQL splitting edge cases | Medium | Medium | Use DuckDB's tokenizer or conservative regex splitter; test with comments, string literals |
| No rowid → cell editing breaks for PKless tables | High | Low | Gate edit UI on PK detection; show tooltip |
| `exportFile()` unavailable in in-memory mode | High | Medium | Fall back to per-table CSV/Parquet export; document limitation |
| DuckDB WASM bundle size (~10 MB) slow cold load | Medium | Medium | Lazy-load + show progress bar; cache in browser |
| Rebuild of Modify Structure on type change | Low | Low | DuckDB `ALTER TABLE … ALTER COLUMN TYPE` exists for simple renames; use rebuild pattern as fallback |
