When a problem involves matching, nesting, or "most recent unclosed
thing," reach for a **stack**. Valid Parentheses is the textbook example
and a very common screen question.

## Challenge: Valid Parentheses

<ChallengeCard
  adapter="python"
  title="Valid Parentheses"
  instructions={`Implement \`is_valid(s)\` for a string \`s\` containing only the characters \`()\`, \`[]\`, and \`{}\`. Return \`True\` if every opening bracket is closed by the matching type in the correct order, otherwise \`False\`. An empty string is valid.

Example: \`is_valid("()[]{}")\` is \`True\`; \`is_valid("([)]")\` is \`False\`.`}
  files={[
    {
      filename: "main.py",
      starterCode: `def is_valid(s):
    # Return True if the brackets are balanced and correctly nested.
    pass`,
      solutionCode: `def is_valid(s):
    pairs = {")": "(", "]": "[", "}": "{"}
    stack = []
    for ch in s:
        if ch in "([{":
            stack.append(ch)
        elif ch in pairs:
            if not stack or stack.pop() != pairs[ch]:
                return False
    return len(stack) == 0`,
    },
  ]}

## Concept check

<MultipleChoice
  markdown={`Why is a **stack** the right data structure here, rather than just counting opening and closing brackets?

- Counting is fine; the bracket counts just have to be equal.
  > Equal counts aren't enough: \`"([)]"\` has matching counts but is invalid because the nesting order is wrong.
- [o] A stack enforces ordering — each closer must match the **most recently opened** bracket (LIFO), which is exactly the nesting rule.
  > Last-in-first-out matching is what catches interleaved brackets like \`"([)]"\` that a counter would wrongly accept.
- A queue (FIFO) would work just as well.
  > FIFO matches the *oldest* open bracket, which is the opposite of nesting; \`"([)]"\` would be accepted incorrectly.
- You need a hash map, not a stack.
  > A map is handy for looking up the matching pair, but it's the stack that enforces correct nesting order.`}
/>
