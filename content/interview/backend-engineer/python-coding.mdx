The single most common warm-up in a coding interview is **Two Sum**. It
looks trivial, but interviewers use it to see whether you reach for a
hash map to turn an O(n²) scan into O(n). Write it below and run the
tests.

## Challenge: Two Sum

    seen = {}
    for i, n in enumerate(nums):
        if target - n in seen:
            return [seen[target - n], i]
        seen[n] = i
    return []`,

## Concept check

<MultipleChoice
  markdown={`Your first solution uses two nested loops to check every pair — O(n²) time. How can a single pass with a hash map (dict) bring it to O(n)?

- It can't; comparing all pairs is fundamentally O(n²).
  > A hash map avoids comparing all pairs: you check each number once against what you've already seen.
- [o] As you scan, store each value's index in a dict and check whether \`target - num\` is already in it.
  > Each lookup/insert is O(1) on average, so one pass over n elements is O(n) time (and O(n) extra space) — the standard optimal Two Sum.
- Sort the array first, then binary search for each complement.
  > Sorting is O(n log n) and also loses the original indices the question asks for — slower than the hash-map pass and extra bookkeeping.
- Use recursion to divide the array in half.
  > Divide-and-conquer doesn't apply cleanly here, and it wouldn't beat the O(n) hash-map scan.`}
