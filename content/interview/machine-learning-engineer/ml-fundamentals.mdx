## Bias–variance

<MultipleChoice
  markdown={`You replace a linear model with a very deep decision tree. Training error drops to near zero but validation error rises. In bias–variance terms, what happened?

- You increased bias.
  > A more flexible model has *lower* bias, not higher — the symptom here (near-zero train error) reflects low bias.
- [o] You decreased bias but increased variance — the flexible model now overfits.
  > More capacity reduces bias but raises variance; the widening train/validation gap is the variance cost.
- Both bias and variance decreased.
  > If both fell, validation error would improve, not rise.
- Bias and variance are unrelated to model flexibility.
  > Model flexibility is precisely the knob that trades one for the other.`}
/>

## Regularization

<MultipleChoice
  markdown={`You want regularization that can drive some coefficients exactly to **zero**, effectively selecting features. Which penalty does that?

- L2 (ridge).
  > L2 shrinks coefficients toward zero but rarely sets them exactly to zero.
- [o] L1 (lasso).
  > The L1 penalty's geometry produces sparse solutions — some coefficients become exactly zero, which performs feature selection.
- Neither can zero out coefficients.
  > L1 specifically can; that's its defining property versus L2.
- Both zero out coefficients equally.
  > Only L1 reliably produces exact zeros; L2 keeps them small but nonzero.`}
/>
