## Q&A

### What is a window function, and how does the OVER clause work?

A window function computes a value **per row** while looking at a set of
related rows (the "window"), without collapsing the result the way
`GROUP BY` does. The `OVER(...)` clause defines the window with three
optional parts: `PARTITION BY` (which rows share a window), `ORDER BY`
(their order inside it), and a **frame** (which rows around the current
one are in scope).

### How do ROW_NUMBER, RANK, and DENSE_RANK differ?

All three number rows within an ordered window, but they treat ties
differently:

- `ROW_NUMBER`, always unique; ties break arbitrarily (1, 2, 3, 4).
- `RANK`, ties share a rank and the next value **skips** (1, 2, 2, 4).
- `DENSE_RANK`, ties share a rank with **no gap** (1, 2, 2, 3).

### What does PARTITION BY do versus ORDER BY inside OVER?

`PARTITION BY` splits rows into independent groups; the window resets at
each partition boundary (like `GROUP BY`, but rows are kept). `ORDER BY`
sequences rows **within** a partition, which is what ranking and running
calculations need. You can use either, both, or neither.

### How do you return the top N rows per group?

Rank inside each group with `ROW_NUMBER()` in a CTE, then filter in the
outer query. `ROW_NUMBER` guarantees exactly N rows even with ties; use
`RANK` if you want to keep all ties.

```sql
WITH ranked AS (
  SELECT *,
    ROW_NUMBER() OVER (PARTITION BY category ORDER BY revenue DESC) AS rn
  FROM products
)
SELECT * FROM ranked WHERE rn <= 3;
```

### What is a window frame, and how do ROWS and RANGE differ?

The frame is the slice of the partition the function sees, relative to
the current row, e.g. `ROWS BETWEEN 2 PRECEDING AND CURRENT ROW`. `ROWS`
counts **physical rows**; `RANGE` counts rows with **peer values** in the
`ORDER BY` (all ties are one unit). Use `ROWS` for a fixed N-row moving
window; the difference bites when the order column has duplicates.

### What is the default frame, and why does it matter?

When you add `ORDER BY` inside `OVER` without an explicit frame, the
default is `RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW`. That
turns `SUM(...) OVER (ORDER BY day)` into a **running total**, not the
partition total, a classic surprise. For a whole-partition total, omit
`ORDER BY` or write `ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED
FOLLOWING`.

### How do you compute a moving average?

Average over an explicit `ROWS` frame. A trailing 3-period average is
`AVG(x) OVER (ORDER BY day ROWS BETWEEN 2 PRECEDING AND CURRENT ROW)`,
current row plus the two before it. A centered average uses `1 PRECEDING
AND 1 FOLLOWING`. Early rows average fewer values because the frame is
clipped at the partition edge.

### What do LAG and LEAD do?

`LAG(col, n)` reads `col` from `n` rows **before** the current row in the
window order; `LEAD(col, n)` reads `n` rows **ahead**. They replace a
self-join for period-over-period comparisons. Both take an optional
default for when the offset falls off the edge.

```sql
SELECT day, revenue,
  LAG(revenue) OVER (ORDER BY day)                       AS prev_day,
  revenue - LAG(revenue) OVER (ORDER BY day)             AS day_over_day,
  (revenue - LAG(revenue) OVER (ORDER BY day))
    / LAG(revenue) OVER (ORDER BY day)                   AS pct_change
FROM daily_sales;
```

### What is NTILE and when do you use it?

`NTILE(n)` splits an ordered window into `n` roughly equal buckets and
labels each row with its bucket number, the standard way to build
quartiles, deciles, or percentile bands. If rows don't divide evenly, the
earlier buckets get one extra row.

### What do FIRST_VALUE, LAST_VALUE, and NTH_VALUE return, and what's the LAST_VALUE gotcha?

They return a specific row's value from within the frame. `LAST_VALUE`
surprises people: with the default frame ending at `CURRENT ROW`, the
"last value" is always the current row. To get the true partition
maximum, widen the frame to `ROWS BETWEEN UNBOUNDED PRECEDING AND
UNBOUNDED FOLLOWING`.

### Can you use a window function in a WHERE or HAVING clause?

No. Window functions are evaluated **after** `WHERE`, `GROUP BY`, and
`HAVING` (at the `SELECT` stage), so they can't be referenced there. Wrap
the query in a CTE/subquery and filter in the outer query, or use
`QUALIFY` where supported.

### What is QUALIFY?

`QUALIFY` filters on a window function the way `HAVING` filters on an
aggregate, no wrapping subquery needed. It's supported in DuckDB,
Snowflake, and BigQuery.

```sql
SELECT *,
  ROW_NUMBER() OVER (PARTITION BY category ORDER BY revenue DESC) AS rn
FROM products
QUALIFY rn <= 3;
```

### What is a CTE and when is it better than a subquery?

A Common Table Expression is a named result set defined with `WITH`
before the main query. Prefer a CTE over a nested subquery when the same
derived table is used more than once, when you want readable named steps,
or when chaining several transformations. CTEs also enable recursion.

### What is a recursive CTE and when would you use one?

A recursive CTE references itself to walk hierarchical or graph data,
org charts, category trees, bill-of-materials, or to generate sequences.
It has an **anchor** member (the starting rows) `UNION ALL` a
**recursive** member that joins back to the CTE until no new rows appear.

<SqlCodeBlock
  dialect="duckdb"
  initSql={`CREATE TABLE emp (id INT, name TEXT, manager_id INT);
INSERT INTO emp VALUES
  (1,'CEO',NULL),
  (2,'VP Eng',1), (3,'VP Sales',1), (4,'VP Finance',1),
  (5,'Eng Mgr Platform',2), (6,'Eng Mgr Product',2), (7,'Eng Mgr Data',2),
  (8,'Sales Dir East',3), (9,'Sales Dir West',3),
  (10,'Controller',4),
  (11,'Engineer A',5), (12,'Engineer B',5), (13,'Engineer C',6),
  (14,'Engineer D',6), (15,'Engineer E',7), (16,'Engineer F',7),
  (17,'AE East 1',8), (18,'AE East 2',8), (19,'AE West 1',9),
  (20,'AE West 2',9), (21,'Accountant',10),
  (22,'Intern Platform',11), (23,'Intern Data',15), (24,'Intern Product',13);`}
  starterCode={`WITH RECURSIVE org AS (
  SELECT id, name, manager_id, 1 AS depth
  FROM emp
  WHERE manager_id IS NULL           -- anchor: the top
  UNION ALL
  SELECT e.id, e.name, e.manager_id, o.depth + 1
  FROM emp e
  JOIN org o ON e.manager_id = o.id  -- recurse down one level
)
SELECT * FROM org ORDER BY depth, id;`}
/>

### How do you bucket timestamps by day, week, or month?

`DATE_TRUNC('unit', ts)` snaps a timestamp down to the start of a period
(`'day'`, `'week'`, `'month'`, `'quarter'`, `'year'`), which is the
idiomatic way to aggregate a time series. `EXTRACT`/`DATE_PART` pulls a
single component (year, month, day-of-week) when you want to group by,
say, hour-of-day across all dates.

```sql
SELECT
  DATE_TRUNC('month', order_ts) AS month,
  COUNT(*)                      AS orders,
  SUM(amount)                   AS revenue
FROM orders
GROUP BY 1
ORDER BY 1;
```

### How do you fill gaps in a date series (a date spine)?

Generate a complete calendar and `LEFT JOIN` your data onto it so missing
days show up as zero instead of vanishing. DuckDB and Postgres have
`generate_series`; other engines use a numbers/calendar table.

<SqlCodeBlock
  dialect="duckdb"
  initSql={`CREATE TABLE sales (day DATE, amount INTEGER);
INSERT INTO sales VALUES
  ('2024-03-01', 100), ('2024-03-03', 250), ('2024-03-04', 75),
  ('2024-03-06', 190), ('2024-03-07', 145), ('2024-03-10', 220),
  ('2024-03-11', 80),  ('2024-03-12', 310), ('2024-03-15', 125),
  ('2024-03-17', 265), ('2024-03-18', 95),  ('2024-03-20', 175),
  ('2024-03-21', 240), ('2024-03-24', 60),  ('2024-03-25', 205),
  ('2024-03-26', 130), ('2024-03-28', 285), ('2024-03-29', 110),
  ('2024-03-31', 160), ('2024-04-02', 195), ('2024-04-03', 70),
  ('2024-04-05', 250), ('2024-04-06', 140), ('2024-04-08', 300);`}
  starterCode={`WITH spine AS (
  SELECT unnest(generate_series(DATE '2024-03-01', DATE '2024-03-05', INTERVAL 1 DAY)) AS day
)
SELECT s.day, COALESCE(x.amount, 0) AS amount
FROM spine s
LEFT JOIN sales x ON x.day = s.day
ORDER BY s.day;`}
/>

### How do you pivot rows into columns?

Standard SQL has no portable `PIVOT`, so use **conditional aggregation**:
wrap a `CASE` inside `SUM` (or `MAX`) per target column. It's explicit and
runs everywhere.

<SqlCodeBlock
  dialect="duckdb"
  initSql={`CREATE TABLE sales (region TEXT, quarter TEXT, amount INTEGER);
INSERT INTO sales VALUES
  ('North','Q1',100), ('North','Q2',140), ('South','Q1',80),
  ('South','Q2',120), ('North','Q1',60),  ('South','Q2',30),
  ('East','Q1',95),   ('East','Q2',175),  ('West','Q1',110),
  ('West','Q2',65),   ('North','Q2',85),  ('South','Q1',145),
  ('East','Q1',40),   ('West','Q2',200),  ('North','Q1',75),
  ('South','Q2',55),  ('East','Q2',130),  ('West','Q1',90),
  ('North','Q2',115), ('South','Q1',35),  ('East','Q1',160),
  ('West','Q2',105),  ('North','Q1',50),  ('South','Q2',185);`}
  starterCode={`SELECT
  region,
  SUM(CASE WHEN quarter = 'Q1' THEN amount ELSE 0 END) AS q1,
  SUM(CASE WHEN quarter = 'Q2' THEN amount ELSE 0 END) AS q2
FROM sales
GROUP BY region
ORDER BY region;`}
/>

### How do you unpivot columns back into rows?

The portable pattern is a `UNION ALL` per column, or a `CROSS JOIN` /
`UNNEST` against a list of column values. It turns a wide "one row per
entity, one column per metric" table into a tidy long format.

```sql
SELECT region, 'q1' AS quarter, q1 AS amount FROM wide
UNION ALL
SELECT region, 'q2' AS quarter, q2 AS amount FROM wide;
```

### What are PERCENT_RANK and CUME_DIST?

Both express a row's relative standing in $[0, 1]$. `PERCENT_RANK` is
$(\text{rank} - 1)/(n - 1)$, so the first row is 0. `CUME_DIST` is the
fraction of rows at or below the current one, so it never returns 0.
They're handy for percentile thresholds ("top 10% of customers by spend").

### How do you deduplicate rows keeping the latest per key?

Rank each key's rows by a recency column with `ROW_NUMBER`, then keep
`rn = 1`. This is the standard "latest record per entity" pattern.

```sql
WITH ranked AS (
  SELECT *,
    ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY updated_at DESC) AS rn
  FROM events
)
SELECT * FROM ranked WHERE rn = 1;
```

## Concept checks

<MultipleChoice
  markdown={`Scores are \`90, 85, 85, 80\` ordered descending. What does \`DENSE_RANK()\` return for the \`80\`?

- \`5\`, because ties each consume a rank.
  > No function double-counts ties like that; ties share one rank value.
- \`2\`, the same as the tied rows.
  > The tied \`85\`s share rank 2; the \`80\` is strictly lower, so it advances to the next dense rank, 3.
- \`4\`, because there are three rows above it.
  > That's what \`RANK()\` returns, it skips a number after the tie at 85.
- [o] \`3\`, because \`DENSE_RANK\` doesn't skip after ties.
  > \`DENSE_RANK\` gives 1, 2, 2, 3, consecutive ranks with no gap after the tie.`}
/>

<MultipleChoice
  markdown={`You want only the top-selling product per category, but \`WHERE ROW_NUMBER() OVER (...) = 1\` throws an error. Why?

- \`ROW_NUMBER\` needs a \`PARTITION BY\` to work.
  > \`PARTITION BY\` is optional; the error is about clause evaluation order, not partitioning.
- \`ROW_NUMBER\` isn't a real function.
  > It's a standard window function; the problem is *where* you used it.
- You must add \`GROUP BY category\`.
  > Grouping would collapse rows and still wouldn't let \`WHERE\` see the window value.
- [o] Window functions are computed after \`WHERE\`, so they can't be referenced in it.
  > \`WHERE\` runs before the \`SELECT\`-stage window evaluation. Filter in an outer query/CTE or use \`QUALIFY\`.`}
/>

<MultipleChoice
  markdown={`You wrote \`SUM(amount) OVER (PARTITION BY region ORDER BY day)\` expecting each region's grand total on every row, but the numbers climb down the rows. What happened?

- \`SUM\` can't be used as a window function.
  > It can; aggregate functions become window functions with an \`OVER\` clause.
- [o] Adding \`ORDER BY\` set the default frame to \`UNBOUNDED PRECEDING\` to \`CURRENT ROW\`, making it a running total.
  > Drop the \`ORDER BY\` or use \`ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING\` for the full-partition total.
- The \`PARTITION BY\` is being ignored.
  > It isn't; each region still resets. The issue is the frame the \`ORDER BY\` implies.
- You need \`GROUP BY region\` instead.
  > That collapses rows; the goal here is to keep every row with the total attached, which the corrected frame does.`}
/>
