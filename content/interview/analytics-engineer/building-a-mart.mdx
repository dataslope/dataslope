The day-to-day of analytics engineering is turning raw fact and
dimension tables into clean, aggregated **marts**. Build one below: join
a fact table to a dimension and roll up.

## Challenge: category revenue mart

<SqlChallengeCard
  dialect="duckdb"
  title="Revenue by category"
  instructions={`Two tables are loaded: \`fact_orders\` (\`order_id\`, \`product_id\`, \`amount\`) and \`dim_product\` (\`product_id\`, \`category\`). Build a mart of **total revenue per category**: join the fact to the dimension and sum \`amount\`. Columns: \`category\`, \`revenue\`. Sort by \`revenue\` descending.`}
  initSql={`CREATE TABLE dim_product AS SELECT * FROM (VALUES
  (1, 'Books'),
  (2, 'Books'),
  (3, 'Electronics'),
  (4, 'Home')
) AS t(product_id, category);

CREATE TABLE fact_orders AS SELECT * FROM (VALUES
  (1001, 1,  20.00),
  (1002, 2,  15.00),
  (1003, 3, 200.00),
  (1004, 3, 150.00),
  (1005, 4,  60.00),
  (1006, 1,  25.00)
) AS t(order_id, product_id, amount);`}
  starterCode={`-- Join the fact to the dimension, then aggregate by category.
SELECT
  p.category
  -- , revenue here
FROM fact_orders f
-- join dim_product, group, order;`}
  solutionSql={`SELECT
  p.category,
  SUM(f.amount) AS revenue
FROM fact_orders f
JOIN dim_product p ON p.product_id = f.product_id
GROUP BY p.category
ORDER BY revenue DESC;`}
  tests={[
    {
      id: "row_count",
      name: "One row per category",
      description: "Three categories → three rows",
      expectedRowCount: 3,
    },
    {
      id: "columns",
      name: "Has the required columns",
      description: "category and revenue",
      expectedColumnsInclude: ["category", "revenue"],
    },
  ]}
/>

## Concept check

<MultipleChoice
  markdown={`The mart above has **one row per category**. In dimensional-modeling terms, what is the "grain" of this output table?

- One row per order.
  > That's the grain of the *source* \`fact_orders\`; the mart aggregates away individual orders.
- [o] One row per category.
  > Grain is the level of detail one row represents. After \`GROUP BY p.category\`, each row is exactly one category.
- One row per product.
  > Products are rolled up into categories here, so product is no longer the grain.
- Grain doesn't apply to aggregated tables.
  > Every table has a grain — defining it precisely (here, per category) is the first step in modeling a mart.`}
/>
