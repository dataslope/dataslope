"Design an experiment to test X" is a staple DS round. These cover the
design choices and traps interviewers look for.

## Q&A

### How would you design an A/B test for a new feature?

State the **hypothesis** and a single primary **metric** (a guardrail
metric or two on the side). **Randomize** users into control/treatment at
the right unit (usually user, not request, to avoid contamination).
Compute the **sample size** for your minimum detectable effect, power
(usually 0.8), and α (0.05) **before** running. Run for full business
cycles, then test for a significant difference and check guardrails.

### What is statistical power, and what drives it?

Power = probability of detecting a real effect (1 − β). It rises with
**larger sample size**, **larger true effect**, **lower variance**, and a
**higher α**. Underpowered tests waste traffic and miss real effects, so
you size the experiment to hit a target power for the smallest effect
worth detecting.

### Why fix the sample size in advance instead of "peeking"?

Repeatedly checking and stopping as soon as p < 0.05 (**peeking**)
massively inflates the false-positive rate — you'll eventually cross the
threshold by chance. Either fix n up front, or use methods designed for
continuous monitoring (sequential testing / always-valid p-values).

### What are common A/B testing pitfalls?

- **Novelty / primacy effects** — behavior changes just because something is new; run longer.
- **Sample ratio mismatch** — the split isn't actually 50/50, signaling a bug.
- **Network/interference effects** — treatment leaks to control (social features); use cluster randomization.
- **Multiple comparisons** — testing many metrics inflates false positives; correct for it.
- **Simpson's paradox** — an aggregate effect reverses within segments.

### The experiment shows no significant difference. What can you conclude?

Not "the feature does nothing" — only that you **failed to detect** an
effect at your power. Report the confidence interval: a tight CI around
zero supports "no meaningful effect," while a wide CI means the test was
underpowered and inconclusive.
