As components grow, you need ways to combine them without turning each
one into a pile of props. React's answer is **composition**: small
components nested inside each other, with the special `children` prop
doing most of the work.

## The `children` prop

Whatever you put *between* a component's tags arrives as its
`children` prop. That lets you build **wrapper** components, a `Card`,
a `Modal`, a `Panel`, that style or arrange whatever you place inside:

<CodeBlock
  adapter="react"
  files={[
    {
      filename: "main.tsx",
      starterCode: `import { createRoot } from "react-dom/client";
import type { ReactNode } from "react";

function Card({ children }: { children: ReactNode }) {
  return (
    <div
      style={{
        border: "1px solid #e2e8f0",
        borderRadius: 12,
        padding: 16,
        margin: 12,
        fontFamily: "system-ui",
      }}
    >
      {children}
    </div>
  );
}

function App() {
  return (
    <main>
      <Card>
        <h2>Trailblazer Boots</h2>
        <p>Waterproof and on sale.</p>
      </Card>
      <Card>
        <h2>Camp Mug</h2>
        <p>Holds 400ml.</p>
      </Card>
    </main>
  );
}

createRoot(document.getElementById("root")!).render(<App />);
`,
    },
  ]}
/>

`Card` knows nothing about boots or mugs. It just draws a bordered box
around *whatever* you hand it. That's composition: the wrapper owns the
frame, the caller owns the content.

The two panels below share one `Panel` wrapper. It owns the header bar
and padding; each caller supplies completely different `children`, a
paragraph in one, a bullet list in the other:

<ReactPreview
  code={`function Panel({ title, children }: {
  title: string;
  children: React.ReactNode;
}) {
  return (
    <section className="panel">
      <header>{title}</header>
      <div className="body">{children}</div>
    </section>
  );
}

function Panels() {
  return (
    <>
      <Panel title="Getting started">
        <p>Anything you nest between the tags arrives as children.</p>
      </Panel>
      <Panel title="Pro tip">
        <ul>
          <li>Composition beats configuration.</li>
          <li>Slots keep components flexible.</li>
        </ul>
      </Panel>
    </>
  );
}`}
>

## Composition over configuration

You could instead give `Card` a `title` prop, a `body` prop, an
`imageUrl` prop, a `footer` prop… and it would grow a new prop for
every layout. Composition sidesteps that. Pass content as children (or
as several named "slots" via props that hold JSX) and the component
stays small no matter how varied its uses:

<CodeBlock
  adapter="react"
  files={[
    {
      filename: "main.tsx",
      starterCode: `import { createRoot } from "react-dom/client";
import type { ReactNode } from "react";

// Two named slots, each is just JSX passed as a prop.
function SplitPanel({ left, right }: { left: ReactNode; right: ReactNode }) {
  return (
    <div
      style={{ display: "flex", gap: 16, fontFamily: "system-ui", margin: 16 }}
    >
      <div style={{ flex: 1 }}>{left}</div>
      <div style={{ flex: 1 }}>{right}</div>
    </div>
  );
}

function App() {
  return (
    <SplitPanel
      left={<img src="https://picsum.photos/200/140" alt="A placeholder" />}
      right={
        <div>
          <h2>Details</h2>
          <p>Slots let a component accept whole chunks of UI.</p>
        </div>
      }
    />
  );
}

createRoot(document.getElementById("root")!).render(<App />);
`,
    },
  ]}
/>

<Callout type="info" title="ReactNode is the type for 'any renderable thing'">
`children` and slot props are typed `ReactNode`, elements, strings,
numbers, arrays of them, or nothing. It's the catch-all type for
anything React can render.
</Callout>

`children` isn't opaque, React's `Children` helpers let a wrapper
*inspect* what it was given. The toolbar below counts its children and
renders them in a row:

<ReactPreview
  code={`import { Children, isValidElement, type ReactNode } from "react";

function Toolbar({ children }: { children: ReactNode }) {
  const count = Children.count(children);
  return (
    <div>
      <small>This toolbar has {count} buttons:</small>
      <div className="row">
        {Children.map(children, (child) =>
          isValidElement(child) ? child : null,
        )}
      </div>
    </div>
  );
}

function App() {
  return (
    <Toolbar>
      <button>Cut</button>
      <button>Copy</button>
      <button>Paste</button>
    </Toolbar>
  );
}`}
>
  <ChildrenCountDemo />
</ReactPreview>

Composition also builds *interactive* widgets. These tabs are one
component holding an `active` index in state and swapping the body,
click between them:

<ReactPreview
  code={`function Tabs({ tabs }: { tabs: { label: string; body: string }[] }) {
  const [active, setActive] = useState(0);
  return (
    <div>
      <div className="tabstrip">
        {tabs.map((t, i) => (
          <button
            key={t.label}
            aria-selected={active === i}
            onClick={() => setActive(i)}
          >
            {t.label}
          </button>
        ))}
      </div>
      <div className="tabbody">{tabs[active].body}</div>
    </div>
  );
}`}
>

</ReactPreview>

import type { ReactNode } from "react";
import "./styles.css";

function Alert({ children }: { children: ReactNode }) {
  return <div className="alert">{children}</div>;
}

function App() {
  return (
    <main style={{ fontFamily: "system-ui", margin: 24 }}>

Composition is how React apps stay readable at scale. The other half
of reuse is sharing *logic*, which is exactly what
[Custom hooks](/courses/react-from-the-ground-up/custom-hooks) are for.
