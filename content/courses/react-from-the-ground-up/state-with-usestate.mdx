Props come *in* from a parent and never change from the inside. But
components often need to remember something that changes over time: a
counter, whether a menu is open, what's typed in a box. That
remembered, changeable data is **state**, and `useState` is how a
component gets some.

## The `useState` hook

`useState(initial)` returns a pair: the **current value** and a
**setter** function. Calling the setter updates the value *and tells
React to re-render* the component with the new value.

```tsx
const [count, setCount] = useState(0);
//     ^value  ^setter          ^initial value
```

Click the buttons below, they're live. Each click calls the setter,
React re-renders the component, and the new `count` shows. You never
touch the DOM:

<ReactPreview

  const [count, setCount] = useState(0);

  return (
    <>
      <button onClick={() => setCount(count - 1)}>−</button>
      <span>{count}</span>
      <button onClick={() => setCount(count + 1)}>+</button>
    </>
  );
}`}
>

</ReactPreview>

import { createRoot } from "react-dom/client";

function Counter() {
  const [count, setCount] = useState(0);

  return (
    <main style={{ fontFamily: "system-ui", margin: 24 }}>
      <h1>Count: {count}</h1>
      <button onClick={() => setCount(count + 1)}>+1</button>{" "}

Each click calls `setCount`, React re-runs `Counter` with the new
`count`, and the heading reflects it. You never touched the DOM;
you changed *state*, and the UI followed.

## Setting state triggers a re-render

This is the key difference from a plain variable. A normal `let count`
would change in memory but the screen would never update. State is the
value React *watches*: change it through the setter and React redraws.

<Callout type="warn" title="Never assign state directly">
`count = count + 1` does nothing useful, React won't know and won't
re-render. Always go through the setter: `setCount(count + 1)`.
</Callout>

## Updater functions

When the next value depends on the previous one, and especially when
updates might batch together, pass a **function** to the setter. React
calls it with the latest value:

```tsx
setCount((prev) => prev + 1); // safest way to increment
```

## Updating objects and arrays without mutating

State should be treated as **immutable**: create a *new* value rather
than editing the old one, so React can detect the change. Use the
spread syntax:

```tsx
const [user, setUser] = useState({ name: "Ada", age: 36 });
setUser({ ...user, age: 37 });          // new object, one field changed

const [items, setItems] = useState<string[]>([]);
setItems([...items, "new item"]);        // new array with one more item
```

State can hold anything, and the UI just reflects it. Below, a single
`color` string drives the preview swatch: clicking a chip sets the
state, and everything that reads `color` updates at once:

<ReactPreview
  code={`function ColorPicker() {
  const [color, setColor] = useState("#4f46e5");
  const swatches = ["#4f46e5", "#0891b2", "#db2777", "#ea580c", "#16a34a"];

  return (
    <div>
      <div className="preview" style={{ background: color }}>{color}</div>
      {swatches.map((c) => (
        <button key={c} style={{ background: c }} onClick={() => setColor(c)} />
      ))}
    </div>
  );
}`}
>
  <ColorPickerDemo />
</ReactPreview>
