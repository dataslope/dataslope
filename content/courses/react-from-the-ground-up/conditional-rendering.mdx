A component often needs to show **different things** depending on its
state: logged in or out, loading or loaded, empty or full. Because JSX
is just JavaScript, you render conditionally with the same tools you
already use to choose values, `if`, the ternary `?:`, and `&&`.

## Choosing between two things: the ternary

Inside JSX you can't write an `if` statement (statements aren't
expressions), but you *can* use the ternary operator, which **is** an
expression. This is the workhorse for "show A or B":

<ReactPreview
  code={`function Account() {
  const [user, setUser] = useState<string | null>(null);

  return (
    <div>
      {user ? (
        <>
          <strong>Welcome back, {user} 👋</strong>
          <button onClick={() => setUser(null)}>Log out</button>
        </>
      ) : (
        <>
          <span>You are signed out.</span>
          <button onClick={() => setUser("Ada")}>Log in</button>
        </>
      )}
    </div>
  );
}`}
>
  <AuthToggleDemo />
</ReactPreview>

The whole `{user ? (...) : (...)}` is one expression that evaluates to
one of two JSX trees. Click the button and the state flips, so the
branch flips.

## Showing something or nothing: `&&`

When you want to render something **only when a condition is true** (and
nothing otherwise), reach for `&&`. In JavaScript, `cond && value`
evaluates to `value` when `cond` is truthy and to `cond` (a falsy value
React skips) otherwise:

<ReactPreview
  code={`function Cart() {
  const [count, setCount] = useState(0);

  return (
    <div>
      <span className="cart">
        🛒
        {count > 0 && <span className="badge">{count}</span>}
      </span>
      <button onClick={() => setCount((c) => Math.max(0, c - 1))}>−</button>
      <button onClick={() => setCount((c) => c + 1)}>Add to cart</button>
    </div>
  );
}`}
>
  <CartBadgeDemo />
</ReactPreview>

The badge appears only once `count > 0`. Add items and it shows; remove
them all and it vanishes.

<Figure
  slug="rx-conditional-rendering-inline-cutout"
  alt="A switch on a panel with two prepared blocks beside it, only the block matching the switch's position mounted in the frame"
  caption="Only the matching branch is mounted; the other is never put on the page."
/>

<Callout type="warn" title="The && number gotcha">
`&&` returns the *left* value when it's falsy, and React renders some
falsy values. `{count && <Badge />}` renders a literal **`0`** when
`count` is `0`, because `0` is falsy but still a renderable number. Guard
with a real boolean instead: `{count > 0 && <Badge />}`. The same trap
bites empty strings. Ternaries (`cond ? <X/> : null`) sidestep it
entirely.
</Callout>

## Pulling logic out with variables and early returns

For anything beyond a simple choice, compute the JSX in a variable
before the `return`, or **return early** for an edge case. Both keep the
returned markup readable:

<CodeBlock
  adapter="react"
  files={[
    {
      filename: "main.tsx",
      starterCode: `import { useState } from "react";
import { createRoot } from "react-dom/client";

type Status = "loading" | "error" | "ready";

function Panel({ status }: { status: Status }) {
  // Early return handles the edge cases first…
  if (status === "loading") return <p>⏳ Loading…</p>;
  if (status === "error") return <p>⚠️ Something went wrong.</p>;

  // …so the main path stays clean.
  return <p>✅ Everything is ready.</p>;
}

function App() {
  const [status, setStatus] = useState<Status>("loading");
  return (
    <main style={{ fontFamily: "system-ui", margin: 24 }}>
      <Panel status={status} />
      <button onClick={() => setStatus("loading")}>Loading</button>{" "}
      <button onClick={() => setStatus("error")}>Error</button>{" "}
      <button onClick={() => setStatus("ready")}>Ready</button>
    </main>
  );
}

createRoot(document.getElementById("root")!).render(<App />);
`,
    },
  ]}
/>

That "guard the edge cases, then render the happy path" shape is
everywhere in React, especially in data fetching, where `loading` and
`error` states return early before the data renders.
