Almost everything in React flows through state and props. But sometimes
you need to step outside that flow, to **focus an input**, measure an
element, or hold a value that changes without redrawing the screen.
That's what **`useRef`** is for.

## A ref is a box that survives renders

`useRef(initial)` returns an object with a single mutable property,
`.current`. React keeps the same box across every render, and, crucially,
**changing `.current` does not trigger a re-render**. That's the opposite
of state, and exactly why refs suit values the UI doesn't directly
display.

```tsx
const ref = useRef(0);
ref.current += 1;   // mutate freely; no re-render happens
```

Click the first button below many times, nothing on screen changes,
because it only bumps a ref. Then "Reveal" reads that ref into state and
shows the accumulated total:

<ReactPreview
  code={`function SilentCounter() {
  const clicksRef = useRef(0);              // persists, never re-renders
  const [shown, setShown] = useState<number | null>(null);

  return (
    <div>
      <button onClick={() => { clicksRef.current += 1; }}>
        Click me (updates a ref silently)
      </button>
      <button onClick={() => setShown(clicksRef.current)}>
        Reveal the count
      </button>
      {shown !== null && <span>The ref counted {shown} clicks.</span>}
    </div>
  );
}`}
>
  <SilentCounterDemo />
</ReactPreview>

## Refs to DOM nodes

The most common use: get a handle on a real DOM element. Put the ref on
an element with the `ref` attribute, and after render `ref.current` is
that DOM node, so you can call imperative methods like `.focus()`,
`.scrollIntoView()`, or read `.value`:

<ReactPreview
  code={`function FocusField() {
  const inputRef = useRef<HTMLInputElement>(null);

  return (
    <div>
      <input ref={inputRef} placeholder="Click the button →" />
      <button onClick={() => inputRef.current?.focus()}>
        Focus the input
      </button>
    </div>
  );
}`}
>
  <FocusInputDemo />
</ReactPreview>

The `?.` matters: `inputRef.current` is `null` on the first render (the
element doesn't exist yet) and becomes the node once React mounts it. By
the time a click handler runs, it's set.

<Callout type="warn" title="Don't reach for a ref to do what state does">
Refs are an escape hatch. If a value should be *shown* in the UI, it
belongs in **state**, not a ref, because a ref won't re-render when it
changes. Use refs for imperative DOM calls and for bookkeeping the render
doesn't depend on (timer ids, previous values, instance counters). When
in doubt, start with state.
</Callout>

## Refs vs. state, at a glance

| | State | Ref |
| --- | --- | --- |
| Triggers re-render on change | Yes | No |
| Value is preserved across renders | Yes | Yes |
| Read/written during render | Read yes, write no | Avoid both |
| Good for | Anything the UI shows | DOM nodes, timers, "last value" |
