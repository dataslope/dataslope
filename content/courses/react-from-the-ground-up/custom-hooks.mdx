Composition reuses *markup*. **Custom hooks** reuse *logic*, the
`useState` and `useEffect` wiring that would otherwise be copy-pasted
between components. A custom hook is just a function whose name starts
with `use` and that calls other hooks.

## From duplicated logic to a hook

Say two components both track a boolean that flips, a menu, a modal,
an accordion. Instead of repeating the `useState` + toggle in each,
extract it:

<CodeBlock
  adapter="react"
  files={[
    {
      filename: "main.tsx",
      starterCode: `import { useState } from "react";
import { createRoot } from "react-dom/client";

// A custom hook: reusable state + behavior, no markup.
function useToggle(initial: boolean) {
  const [on, setOn] = useState(initial);
  const toggle = () => setOn((prev) => !prev);
  return { on, toggle };
}

function App() {
  const menu = useToggle(false);
  const details = useToggle(true);

  return (
    <main style={{ fontFamily: "system-ui", margin: 24 }}>
      <button onClick={menu.toggle}>
        Menu is {menu.on ? "open" : "closed"}
      </button>
      {menu.on && <p>🍔 Menu contents</p>}
      <hr />
      <button onClick={details.toggle}>
        Details are {details.on ? "shown" : "hidden"}
      </button>
      {details.on && <p>📋 Extra details</p>}
    </main>
  );
}

createRoot(document.getElementById("root")!).render(<App />);
`,
    },
  ]}
/>

Two independent toggles, one shared implementation. Each call to
`useToggle` gets its *own* state, hooks are functions, not globals.
The rules that make this work:

- **Only call hooks at the top level** of a component or another hook,
  never inside loops, conditions, or nested functions.
- **Only call hooks from React functions**, components or custom
  hooks, not plain helpers.
- **Name them `useSomething`**, the `use` prefix is how React (and its
  linter) recognizes a hook.

The card below calls `useToggle` *twice*, once for dark mode, once for
bold, and each call keeps its own independent state. That independence
is the whole point: a hook is a function, not a shared global:

<ReactPreview
  code={`function useToggle(initial = false) {
  const [on, setOn] = useState(initial);
  const toggle = () => setOn((v) => !v);
  return [on, toggle] as const;
}

function ThemeCard() {
  const [dark, toggleDark] = useToggle(false);
  const [bold, toggleBold] = useToggle(true);

  return (
    <div className={dark ? "dark" : "light"}>
      <p style={{ fontWeight: bold ? 700 : 400 }}>One hook, reused twice.</p>
      <button onClick={toggleDark}>{dark ? "Light" : "Dark"} mode</button>
      <button onClick={toggleBold}>{bold ? "Un-bold" : "Bold"}</button>
    </div>
  );
}`}

## Hooks can use effects too

A custom hook can bundle `useEffect` as well, which is how the
ecosystem ships things like `useLocalStorage`, `useFetch`, or
`useWindowSize`. The component that uses them stays clean:

```tsx
function useNow(): Date {
  const [now, setNow] = useState(() => new Date());
  useEffect(() => {
    const id = setInterval(() => setNow(new Date()), 1000);
    return () => clearInterval(id);
  }, []);
  return now;
}
// In a component: const now = useNow();
```

Here's a `useInterval` hook powering a live stopwatch. The hook hides
the interval bookkeeping (and the ref trick that keeps the callback
fresh); the component just says "tick every 100ms while running":

<ReactPreview
  code={`function useInterval(callback: () => void, delay: number | null) {
  const saved = useRef(callback);
  useEffect(() => { saved.current = callback; }, [callback]);
  useEffect(() => {
    if (delay === null) return;                 // null pauses the timer
    const id = setInterval(() => saved.current(), delay);
    return () => clearInterval(id);
  }, [delay]);
}

function Stopwatch() {
  const [ms, setMs] = useState(0);
  const [running, setRunning] = useState(false);
  useInterval(() => setMs((t) => t + 100), running ? 100 : null);

  return (
    <div>
      <span>{(ms / 1000).toFixed(1)}s</span>
      <button onClick={() => setRunning((r) => !r)}>{running ? "Pause" : "Start"}</button>
      <button onClick={() => { setRunning(false); setMs(0); }}>Reset</button>
    </div>
  );
}`}
>
  <StopwatchDemo />
</ReactPreview>

Custom hooks really shine when they bundle a browser API. This
`useLocalStorageState` behaves like `useState` but *persists*, type
your name, reload the page, and it's still there:

<ReactPreview
  code={`function useLocalStorageState(key: string, initial: string) {
  const [value, setValue] = useState(initial);
  useEffect(() => {
    const stored = window.localStorage.getItem(key);
    if (stored !== null) setValue(stored);
  }, [key]);
  useEffect(() => {
    window.localStorage.setItem(key, value);    // sync to storage on change
  }, [key, value]);
  return [value, setValue] as const;
}

function NameField() {
  const [name, setName] = useLocalStorageState("demo-name", "");
  return (
    <div>
      <input value={name} onChange={(e) => setName(e.target.value)} placeholder="Type your name…" />
      <p>{name ? "Hi " + name + "! " : ""}Reload, this input remembers itself.</p>
    </div>
  );
}`}
>
  <UseLocalStorageDemo />
</ReactPreview>
