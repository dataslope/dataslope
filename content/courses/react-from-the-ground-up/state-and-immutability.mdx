State often holds an **array** (a todo list, search results) or an
**object** (a form, a settings panel). React only re-renders when it
sees that the state *value changed*, and it checks by identity: is this
a **different** object than last time? So the rule is simple and
absolute: **never mutate state, replace it.**

## Why mutation doesn't work

`items.push("new")` changes the existing array in place. Its identity is
unchanged, so React compares "same array === same array", sees no
difference, and skips the re-render. Your data changed but the screen
didn't. The fix is to build a **new** value and pass it to the setter.

<Figure
  slug="rx-state-and-immutability-inline-cutout"

## Arrays: add, remove, update by copying

Three patterns cover almost everything, all of them produce a new array:

```tsx
setItems([...items, newItem]);                       // add to the end
setItems(items.filter((it) => it.id !== id));        // remove by id
setItems(items.map((it) =>                            // update one item
  it.id === id ? { ...it, done: true } : it));
```

Add and remove items in the live list below. "Add" spreads a new array;
the **×** removes with `filter`, again a new array. The old one is never
touched:

<ReactPreview
  code={`function ShoppingList() {
  const [items, setItems] = useState(["Milk", "Eggs"]);
  const [draft, setDraft] = useState("");

  const add = () => {
    if (!draft.trim()) return;
    setItems((prev) => [...prev, draft.trim()]);       // new array
    setDraft("");
  };
  const remove = (index: number) =>
    setItems((prev) => prev.filter((_, i) => i !== index)); // new array

  return (
    <div>
      <input value={draft} onChange={(e) => setDraft(e.target.value)}
        onKeyDown={(e) => e.key === "Enter" && add()} placeholder="Add an item…" />
      <button onClick={add}>Add</button>
      <ul>
        {items.map((it, i) => (
          <li key={i}>{it} <button onClick={() => remove(i)}>×</button></li>
        ))}
      </ul>
    </div>
  );
}`}
>
  <ImmutableListDemo />
</ReactPreview>

<Callout type="info" title="Prefer the updater form for these">
When the next value is built from the previous one, pass a function:
`setItems((prev) => [...prev, item])`. React always calls it with the
latest state, so rapid or batched updates never work from a stale copy.
</Callout>

## Objects: copy, then override

For objects, spread the old one and override the field you're changing.
The `[key]: value` computed-key syntax lets one handler update any field:

<ReactPreview
  code={`function Settings() {
  const [settings, setSettings] = useState({
    wifi: true, bluetooth: false, dnd: false,
  });

  const toggle = (key: keyof typeof settings) =>
    setSettings((prev) => ({ ...prev, [key]: !prev[key] })); // new object

  return (
    <div>
      {Object.keys(settings).map((key) => (
        <label key={key}>
          {key}
          <input type="checkbox"
            checked={settings[key]}
            onChange={() => toggle(key)} />
        </label>
      ))}
      <pre>{JSON.stringify(settings)}</pre>
    </div>
  );
}`}
>
  <SettingsObjectDemo />
</ReactPreview>

Each toggle builds a brand-new object with one field flipped. The JSON
readout proves the state updates, and because it's a *new* object every
time, React re-renders reliably.

<Callout type="warn" title="Nested updates copy at each level">
Spread is shallow. To change `user.address.city`, you must copy every
level down to the change:
`setUser({ ...user, address: { ...user.address, city } })`. Deeply
nested state is a smell, keep state flat where you can, or reach for a
reducer (a later topic) when it gets hairy.
</Callout>
