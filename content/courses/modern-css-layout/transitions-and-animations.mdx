Motion, used sparingly, makes an interface feel responsive and
polished: buttons that ease on hover, panels that slide in, a badge
that gently pulses. CSS gives you two tools, **transitions** for
state changes and **animations** for scripted sequences.

## Transitions: animate a change

A `transition` tells the browser to *interpolate* a property instead of
snapping to the new value. Put the transition on the element's normal
state; it applies whenever the property changes (on `:hover`, on a
class toggle, anything):

```css
.button {
  background: #6366f1;
  transition: background 0.2s ease, transform 0.2s ease;
}
.button:hover {
  background: #4f46e5;
  transform: translateY(-2px);
}
```

The shorthand is `transition: <property> <duration> <timing> <delay>`.

## `transform`: move without disturbing layout

`transform` (translate, scale, rotate, skew) is the property to
animate for performance, it doesn't trigger layout, so it stays smooth:

```css
transform: translateX(20px);   /* move right */
transform: scale(1.1);         /* grow to 110% */
transform: rotate(15deg);      /* tilt */
```

## Animations: scripted, repeatable motion

For motion that isn't tied to a state change, define keyframes and
attach them with `animation`:

```css
@keyframes fade-in {
  from { opacity: 0; transform: translateY(8px); }
  to   { opacity: 1; transform: translateY(0); }
}
.panel { animation: fade-in 0.4s ease-out; }
```

The `animation` shorthand is
`<name> <duration> <timing> <delay> <iteration-count>`, e.g.
`pulse 1s ease-in-out infinite`.

<Callout type="warn" title="Respect reduced motion">
Some people get motion sickness from animation. Honor their OS setting:

```css
@media (prefers-reduced-motion: reduce) {
  * { animation: none !important; transition: none !important; }
}
```

It's a small block that makes your site usable for more people.
</Callout>
