Most elements sit in the **normal flow**, one after another. The
`position` property lets you lift an element out of that flow, or nudge
it within it, for overlays, badges, sticky headers, and tooltips.

<Figure
  slug="css-positioning-cutout"
  alt="A base panel with a small badge lifted off its corner on a thin post, a third panel floating above both at a higher level"
/>

## The five positioning modes

| Value | In flow? | Positioned relative to | Typical use |
| --- | --- | --- | --- |
| `static` | yes | nothing (default) | ordinary elements |
| `relative` | yes | its own normal spot | nudging; anchoring children |
| `absolute` | no | nearest *positioned* ancestor | badges, dropdowns |
| `fixed` | no | the viewport | sticky nav, back-to-top |
| `sticky` | yes, then pins | scroll container | section headers |

## relative + absolute: the anchor pattern

The workhorse combination: a parent set to `position: relative` becomes
the **positioning context**, and an `absolute` child is placed inside
it with `top`/`right`/`bottom`/`left`.

<Figure
  slug="css-positioning-and-stacking-relative-absolute-anchor-pattern-inline-cutout"
  alt="A small marker pinned to the corner of a card, and the same marker flying to the corner of the whole sheet once the card's pin is pulled"
  caption="An absolute child is placed against its nearest positioned ancestor, so give it one."
/>

Here the green "online" dot is an absolutely-positioned child pinned to
the bottom-right corner of its `relative` avatar. The dot doesn't take
up space in the flow, it floats over the corner:

Remove `position: relative` from `.avatar` and the dot flies to the
corner of the *page*, because the nearest positioned ancestor becomes
the viewport. That anchor relationship is the entire trick.

## `sticky`: in-flow until it isn't

`position: sticky` is a hybrid: the element scrolls normally until it
reaches a threshold (say `top: 0`), then it "sticks" there while the
rest of the content scrolls past. It's how section headers and table
headers stay visible with a single line of CSS, no JavaScript.

```css
.section-header { position: sticky; top: 0; background: white; }
```

## `z-index` and stacking

When positioned elements overlap, **`z-index`** decides who's on top,
higher numbers sit in front. Two things trip people up:

- `z-index` only affects **positioned** elements (not `static` ones).
- A positioned element with a `z-index` creates a **stacking context**:
  its children's `z-index` values are compared only *within* it, not
  against the rest of the page. A child's `z-index: 9999` can't escape
  a parent that sits behind something else.

<Figure
  slug="css-positioning-and-stacking-inline-cutout"
  alt="Three overlapping panels raised on pins of different heights, the highest pin's panel clearly on top"
  caption="`z-index` only compares elements inside the same stacking context."
/>

Three overlapping cards, each positioned with a different `z-index`.
The one with the highest value sits in front regardless of source
order, the middle card is declared last in the HTML but still loses to
the higher `z-index`:

<LivePreview
  title="z-index decides who's on top"
  background="#ffffff"
  html={`<div class="stack">
  <div class="card a">z-index: 1</div>
  <div class="card b">z-index: 3</div>
  <div class="card c">z-index: 2</div>
</div>`}
  css={`.stack { position: relative; height: 150px; font-family: system-ui, sans-serif; }
.card {
  position: absolute;
  width: 130px;
  height: 90px;
  border-radius: 12px;
  color: white;
  font-weight: 700;
  display: grid;
  place-items: center;
  box-shadow: 0 8px 20px rgba(0,0,0,0.2);
}
.a { left: 0;    top: 0;   background: #ef4444; z-index: 1; }
.b { left: 45px; top: 25px; background: #3b82f6; z-index: 3; }
.c { left: 90px; top: 50px; background: #22c55e; z-index: 2; }`}
/>

<Callout type="info" title="When z-index 'doesn't work'">
Nine times out of ten it's one of the two rules above: the element
isn't positioned (add `position: relative`), or it's trapped in a
parent stacking context. Check the ancestor chain before inflating the
number.
</Callout>
