The `transform` property lets you move, resize, rotate, and slant an
element visually, without touching the document flow. A transformed
element paints in its new position, but its neighbors act as if it never
moved. That makes transforms both flexible and fast: the browser can
hand them to the GPU, so they stay smooth even during animation.

## The 2D transform functions

Four functions cover most day-to-day needs:

```css
transform: translate(20px, 8px);  /* move right 20, down 8 */
transform: translateX(20px);      /* just the X axis */
transform: scale(1.25);           /* grow to 125% */
transform: rotate(15deg);         /* tilt clockwise */
transform: skew(-12deg);          /* slant */
```

Each box below carries a different transform. Notice the spacing: even
the scaled box overlaps its footprint without shoving its siblings,
because transforms never disturb layout:

## Combining transforms and transform-origin

You can list several functions in one `transform`, separated by spaces.
**Order matters** — the browser applies them right to left, so
`rotate(45deg) translateX(40px)` rotates first and then moves along the
already-tilted axis, which is not the same as translating and then
rotating.

By default every transform pivots around the element's center. The
`transform-origin` property moves that pivot. The three squares below
all rotate `40deg`; only their origin differs. The dashed outline marks
where each box sat before rotating:

## A hover interaction

Transforms shine on hover, because moving a card with `translate` and
`scale` never nudges the layout around it. Pair the transform with a
`transition` and the change eases instead of snapping. Hover the card
below (it's live) to watch it lift and grow:

<LivePreview
  title="Hover to lift and scale — combined transform + transition"
  background="#ffffff"
  html={`<div class="card">
  <strong>Pro plan</strong>
  <span>Hover me</span>
</div>`}
  css={`.card {
  width: 200px;
  padding: 20px;
  background: white;
  border: 1px solid #e2e8f0;
  border-radius: 14px;
  box-shadow: 0 4px 10px rgba(0,0,0,0.08);
  display: grid;
  gap: 6px;
  font-family: system-ui, sans-serif;
  cursor: pointer;
  transition: transform 0.2s ease, box-shadow 0.2s ease;
}
.card span { color: #64748b; font-size: 14px; }
.card:hover {
  transform: translateY(-8px) scale(1.03);
  box-shadow: 0 18px 34px rgba(0,0,0,0.16);
}`}
/>

The `transition` here just smooths the transform; animating transforms
in depth (timing curves, keyframes, reduced motion) is the subject of
the transitions lesson.

<Callout type="info" title="Why transforms feel smooth">
Changing `top` or `margin` forces the browser to recompute layout for
the page. A `transform` does not — it only repaints the one element,
and the compositor can offload it to the GPU. That is why transform and
opacity are the two properties to lean on for silky hover and animation
effects.
</Callout>

Reaching into the third dimension is a small step further: `rotateX`,
`rotateY`, `translateZ`, and a `perspective` on the parent turn flat
boxes into cards you can flip. It's the same idea with a depth axis
added, and worth exploring once the 2D functions feel natural.
