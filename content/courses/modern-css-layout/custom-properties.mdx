**Custom properties** (CSS variables) let you name a value once and
reuse it everywhere. Change the definition and every use updates, which
is what makes design systems, theming, and dark mode practical in plain
CSS.

## Defining and using

A custom property starts with `--` and is read with `var()`:

```css
:root {
  --brand: #6366f1;
  --space: 1rem;
}

.button {
  background: var(--brand);
  padding: var(--space);
}
```

Defining them on **`:root`** (the `<html>` element) makes them
available to the whole page, because custom properties **inherit**.

One `--brand` value drives every button below, background, border, and
text color all read from it. Because variables inherit and can be
**redefined in a scope**, the second card overrides `--brand` locally
and re-themes itself to green with a single line:

## Scope and fallbacks

Custom properties follow normal inheritance, so you can **redefine**
one on a subtree to re-theme just that part:

```css
.card { --brand: #16a34a; }  /* everything inside .card now uses green */
```

`var()` also takes a **fallback** for when a variable isn't set:
`color: var(--accent, #333)` uses `#333` if `--accent` is undefined.

## Theming and dark mode

Because a variable can be redefined in a scope, theming is just
swapping values. Toggle a class or attribute on the root, or respond to
the OS setting with `prefers-color-scheme`, and the whole page
re-themes:

```css
:root {
  --bg: white;
  --fg: #1e293b;
}
@media (prefers-color-scheme: dark) {
  :root {
    --bg: #0f172a;
    --fg: #e2e8f0;
  }
}
body { background: var(--bg); color: var(--fg); }
```

<Callout type="info" title="Variables can be updated by JavaScript">
`element.style.setProperty('--brand', '#ec4899')` changes a custom
property at runtime, and every rule using it updates instantly. It's
how theme pickers and "accent color" settings are built.
</Callout>
