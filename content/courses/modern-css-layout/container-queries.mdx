title: Container Queries
description: Style a component by the width of its own container, so the same card adapts whether it sits in a wide column or a narrow sidebar.
---

A media query asks about the *viewport*. A **container query** asks about
the *element a component lives in*. That difference is the whole point:
a card shouldn't care how wide the window is, it should care how much
room it was actually given.

## The idea: style by container width

Two steps. First, mark an ancestor as a **query container** with
`container-type: inline-size` (the browser will now track that element's
inline width). Then write `@container` rules that respond to it:

```css
.column {
  container-type: inline-size;   /* this element is a query container */
}

@container (min-width: 380px) {
  .card { display: flex; }        /* applies when the CONTAINER is >= 380px */
}
```

`inline-size` means "watch the width" (the inline axis in horizontal
writing). The `@container` block then styles the container's
*descendants*, exactly like a media query, but keyed to local space
instead of the screen.

## One component, two contexts

Here is why this matters. Below is the **same card markup and the same
CSS**, dropped into two wrapper columns, one `260px` wide, one `460px`
wide. Each wrapper is a container. The card stacks in the narrow column
and becomes a row in the wide one, at the same time, on the same page:

<LivePreview

  align-items: flex-start;
  font-family: system-ui, sans-serif;
}
.col {
  flex: 0 0 auto;             /* keep each wrapper's width fixed */
  container-type: inline-size; /* each wrapper is a query container */
}
.card {
  border: 1px solid #e2e8f0;
  border-radius: 12px;
  overflow: hidden;
  background: white;

  .body { flex: 1; }
}`}
/>

With a media query this is impossible: both cards live on the same
screen, so any viewport rule fires for both. The container query lets a
single, reusable component respond to *where it was placed*. Build the
card once, and it does the right thing in a main column, a sidebar, or a
tight grid cell.

## Naming containers

When containers nest, name them so a query targets the right one.
`container-name` labels a container, and you query it by name:

```css
.sidebar { container-type: inline-size; container-name: rail; }

@container rail (min-width: 300px) {
  .widget { font-size: 1.1rem; }
}
```

The shorthand `container: rail / inline-size` sets both at once. Without
a name, `@container` matches the *nearest* ancestor container, which is
usually what you want anyway.

## Container query units

Container queries bring their own relative units, sized against the
query container instead of the viewport:

- **`cqi`** is 1% of the container's inline size (its width, usually).
- **`cqw`** is 1% of the container's width specifically.

So `font-size: 10cqi` is "one tenth of my container's width." Same rule,
two containers, two sizes:

<LivePreview
  title="cqi units scale text to the container, not the window"
  background="#f8fafc"
  html={`<div class="wrap">
  <div class="box" style="width: 220px">
    <div class="banner"><h2>220px</h2></div>
  </div>
  <div class="box" style="width: 420px">
    <div class="banner"><h2>420px</h2></div>
  </div>
</div>`}
  css={`.wrap {
  display: flex;
  flex-wrap: wrap;
  gap: 16px;
  align-items: flex-start;
  font-family: system-ui, sans-serif;
}
.box { flex: 0 0 auto; container-type: inline-size; }
.banner {
  background: #0f172a;
  color: white;
  padding: 16px;
  border-radius: 10px;
}
.banner h2 {
  margin: 0;
  font-size: 10cqi;   /* 10% of this container's width */
}`}
/>

The `220px` container renders `22px` text; the `420px` one renders
`42px`, from one declaration. It is `clamp()`'s viewport trick, scoped
to a component.

<Callout type="info" title="You query the descendants, not the container itself">
An `@container` rule styles elements *inside* the query container, never
the container element you set `container-type` on. So wrap your
component in a container element, then style the component. Setting
`container-type` also establishes size and layout containment on that
element, which is why the container needs a definite width to measure.
</Callout>
