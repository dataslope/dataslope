description: The contract between a function and its callers, what goes in, what comes out, and the small details that matter.
---

A function is a contract: *"if you give me these inputs, I will
give you this output"*. The vocabulary around that contract is
worth getting right.

<Figure
  slug="js-parameters-and-returns-cutout"
  alt="Parameters and return values, an isometric illustration"
/>

- **Parameters** are the names in the function declaration. They
  are the *placeholders*.
- **Arguments** are the actual values passed in when the function
  is called.

<Figure
  slug="js-parameters-and-returns-inline-cutout"
  alt="A machine with two labelled input slots on top and one chute below, two blocks going in and one coming out"
  caption="Parameters name what goes in; the return value is the one thing that comes out."
/>

```javascript
function greet(name, age) {    // 'name' and 'age' are parameters
  return `Hi ${name}, ${age}`;
}

greet("Ada", 28);              // "Ada" and 28 are arguments
```

In casual conversation, people use the two words interchangeably.
In writing about JavaScript precisely, this distinction is useful.

## Arguments are matched by position

When you call a function, JavaScript binds each argument to the
parameter in the same position, first to first, second to second.

<CodeBlock
  adapter="javascript"
  files={[
    {
      filename: "main.js",
      starterCode: `function divide(numerator, denominator) {
  return numerator / denominator;
}

console.log(divide(10, 2)); // 5
console.log(divide(2, 10)); // 0.2, order matters!
`,
    },
  ]}
/>

This makes long parameter lists fragile. If a function takes five
booleans, callers have to remember the exact order. We will see a
much nicer pattern (options objects) in a moment.

## Missing and extra arguments

JavaScript will not complain if you pass too few or too many
arguments. Both are legal.

- A **missing** argument becomes `undefined`.
- An **extra** argument is just ignored (though it is still
  available via `arguments` or rest parameters).

<CodeBlock
  adapter="javascript"
  files={[
    {
      filename: "main.js",
      starterCode: `function describe(name, age, city) {
  console.log("name:", name);
  console.log("age: ", age);
  console.log("city:", city);
}

describe("Ada", 28, "London");
console.log("---");
describe("Linus"); // age and city are undefined
console.log("---");
describe("Grace", 80, "NYC", "extra"); // the "extra" is silently dropped
`,
    },
  ]}
/>

This forgiveness is a double-edged sword. It makes JavaScript
beginner-friendly, but it also means typos like forgetting an
argument fail silently rather than loudly. We will see in the
debugging chapter how to defend against this.

## Default parameter values

You can give a parameter a default value, used when the caller does
not pass anything for it (or passes `undefined`).

<CodeBlock
  adapter="javascript"
  files={[
    {
      filename: "main.js",
      starterCode: `function greet(name, greeting = "Hello") {
  return greeting + ", " + name + "!";
}

console.log(greet("Ada")); // "Hello, Ada!"
console.log(greet("Ada", "Welcome")); // "Welcome, Ada!"
console.log(greet("Ada", undefined)); // "Hello, Ada!", undefined triggers the default
console.log(greet("Ada", null)); // "null, Ada!", null does NOT trigger the default
`,
    },
  ]}
/>

Defaults are a great way to make a function easier to use without
sacrificing flexibility.

## Rest parameters: gathering many arguments

If you don't know how many arguments a function will be called
with, gather them with a **rest parameter** (`...name`):

<CodeBlock
  adapter="javascript"
  files={[
    {
      filename: "main.js",
      starterCode: `function sum(...numbers) {
  let total = 0;
  for (const n of numbers) total += n;
  return total;
}

console.log(sum()); // 0
console.log(sum(1)); // 1
console.log(sum(1, 2, 3)); // 6
console.log(sum(10, 20, 30, 40)); // 100
`,
    },
  ]}
/>

`numbers` is a real array containing all the arguments. The rest
parameter must come **last** in the parameter list. You can have
ordinary parameters before it:

```javascript
function first(label, ...values) {
  console.log(label, ":", values);
}
first("scores", 90, 85, 70);   // "scores : [90, 85, 70]"
```

## The spread operator: unpacking an array into arguments

The opposite of gathering is **spreading**. If you have an array and
want to pass each element as a separate argument, use `...` at the
call site:

<CodeBlock
  adapter="javascript"
  files={[
    {
      filename: "main.js",
      starterCode: `function add(a, b, c) {
  return a + b + c;
}

const triple = [10, 20, 30];

// Without spread:
console.log(add(triple[0], triple[1], triple[2])); // 60

// With spread:
console.log(add(...triple)); // 60
`,
    },
  ]}
/>

The same `...` syntax means **rest** in a parameter list and
**spread** at a call site. The context tells you which.

## Returning values

A function communicates its result through `return`. A few useful
things to know:

- `return` immediately exits the function.
- `return;` without a value, or no `return` at all, gives the
  caller `undefined`.
- A function can have many `return` statements.
- Anywhere in the body, including from inside a loop, an `if`, or
  a nested block.

<CodeBlock
  adapter="javascript"
  files={[
    {
      filename: "main.js",
      starterCode: `function findFirstNegative(numbers) {
  for (const n of numbers) {
    if (n < 0) return n; // exit the function the moment we find one
  }
  return null; // ran out of numbers, return null
}

console.log(findFirstNegative([1, 2, -3, 4])); // -3
console.log(findFirstNegative([1, 2, 3, 4])); // null
`,
    },
  ]}
/>

The early `return` inside the `for` loop is idiomatic. There's no
need to set a flag and break, `return` does both at once.

## Returning more than one value: object destructuring

JavaScript functions return *one* value. But that value can be an
**object** with multiple named pieces, which is the standard way to
return several related results.

<CodeBlock
  adapter="javascript"
  files={[
    {
      filename: "main.js",
      starterCode: `function summarize(numbers) {
  let min = numbers[0],
    max = numbers[0],
    total = 0;
  for (const n of numbers) {
    if (n < min) min = n;
    if (n > max) max = n;
    total += n;
  }
  return { min, max, total, average: total / numbers.length };
}

const { min, max, average, total } = summarize([4, 9, 1, 7, 3]);
console.log("min:", min);
console.log("max:", max);
console.log("total:", total);
console.log("average:", average);
`,
    },
  ]}
/>

The `const { min, max, ... } = ...` syntax is called
**destructuring**. It pulls named properties out of the returned
object into separate variables in one line. We will use this all
the time.

## Options objects (the named-arguments pattern)

For functions with many parameters, especially booleans or
configuration values, passing an **object of options** is far
more readable than passing many separate positional arguments.

<Figure
  slug="js-parameters-and-returns-arguments-are-matched-inline-cutout"
  alt="Two blocks dropping into two labelled slots on a machine in the order they arrive, a third block held back with no slot to take it"
  caption="Arguments fill parameters by position, and a spare argument has nowhere to go."
/>

<CodeBlock
  adapter="javascript"
  files={[
    {
      filename: "main.js",
      starterCode: `// Hard to read: which argument is which?
function format1(text, upper, trim, prefix, suffix) {
  let s = text;
  if (trim) s = s.trim();
  if (upper) s = s.toUpperCase();
  return prefix + s + suffix;
}
console.log(format1("  hello  ", true, true, "<", ">"));

// Easier to read: each option is named at the call site.
function format2(
  text,
  { upper = false, trim = false, prefix = "", suffix = "" } = {},
) {
  let s = text;
  if (trim) s = s.trim();
  if (upper) s = s.toUpperCase();
  return prefix + s + suffix;
}
console.log(
  format2("  hello  ", { trim: true, upper: true, prefix: "<", suffix: ">" }),
);
`,
    },
  ]}
/>

Both calls produce the same string. The second is dramatically
easier to read and to extend (a new option is one new property,
not a new positional slot to remember).

The `= {}` at the end of the parameter list is a default for the
options object itself, so callers who don't need any options can
call the function with no second argument.

## Functions are objects too

A small but important fact: in JavaScript, functions are a kind of
**object**. They can have properties attached to them. They are
compared by reference, like other objects. They are stored on the
heap.

You don't need to use this fact often, but it explains a few
behaviours:

<CodeBlock
  adapter="javascript"
  files={[
    {
      filename: "main.js",
      starterCode: `function f() {}
f.label = "my function";
console.log(f.label); // "my function"
console.log(typeof f); // "function"
console.log(typeof f === "function"); // true

// Functions compare by reference:
const g = () => 1;
const h = () => 1;
console.log(g === h); // false, two different function values, even with same body
console.log(g === g); // true
`,
    },
  ]}
/>

## Documenting parameters with JSDoc

A common, lightweight way to describe what a function expects is
to add a **JSDoc** comment block above it:

<CodeBlock
  adapter="javascript"
  files={[
    {
      filename: "main.js",
      starterCode: `/**
 * Convert a temperature from Celsius to Fahrenheit.
 *
 * @param {number} celsius - The temperature in degrees Celsius.
 * @returns {number} The temperature in degrees Fahrenheit.
 */
function toFahrenheit(celsius) {
  return (celsius * 9) / 5 + 32;
}

console.log(toFahrenheit(100)); // 212
console.log(toFahrenheit(0)); // 32
`,
    },
  ]}
/>

Editors (like VS Code) pick up JSDoc comments and use them for
autocomplete and hover help. They are an easy, low-cost way to
make a codebase friendlier.
