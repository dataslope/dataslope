An aggregation takes a column and returns one value. In `select()` it
produces a one-row frame; in `agg()` it produces one value per group;
in `with_columns()` it broadcasts back across every row. Same
expressions, three uses.

## The catalogue

<CodeBlock
  adapter="python"
  datasets={[{ path: "palmer-penguins.csv", stageAs: "penguins.csv" }]}
  files={[
    {
      filename: "main.py",
      initCode: `import polars as pl
penguins = pl.read_csv("penguins.csv", null_values=["NA"])`,
      starterCode: `mass = pl.col("body_mass_g")

print(
    penguins.select(
        n=pl.len(),
        count=mass.count(),          # non-null values only
        sum=mass.sum(),
        mean=mass.mean().round(1),
        median=mass.median(),
        std=mass.std().round(1),
        var=mass.var().round(1),
        min=mass.min(),
        max=mass.max(),
        n_unique=mass.n_unique(),
        null_count=mass.null_count(),
    )
)
`,
    },
  ]}
/>

`pl.len()` counts *rows*; `.count()` counts *non-null values in that
column*. The gap between them is the missing data, and confusing the
two is a common source of quietly wrong averages.

## Nulls are skipped, not treated as zero

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      starterCode: `import polars as pl

df = pl.DataFrame({"x": [10, None, 20]})

print("sum   :", df["x"].sum())      # 30, the null contributes nothing
print("mean  :", df["x"].mean())     # 15, divided by 2 not 3
print("count :", df["x"].count())    # 2
print("len   :", df.height)          # 3

# Treating a null as zero is a decision you make explicitly
print("mean if null means 0:", df["x"].fill_null(0).mean())
`,
    },
  ]}
/>

Both answers are defensible. The point is that 15 and 10 mean
different things, and the library will not choose for you.

  slug="pl-aggregations-nulls-are-skipped-inline-cutout"

  caption="Nulls are set aside by an aggregation, not counted as zero."

## Quantiles and spread

<CodeBlock
  adapter="python"
  datasets={[{ path: "diamonds.csv", stageAs: "diamonds.csv" }]}
  files={[
    {
      filename: "main.py",
      initCode: `import polars as pl
diamonds = pl.read_csv("diamonds.csv")`,
      starterCode: `price = pl.col("price")

print(
    diamonds.select(
        p10=price.quantile(0.10),
        q1=price.quantile(0.25),
        median=price.median(),
        q3=price.quantile(0.75),
        p90=price.quantile(0.90),
        iqr=price.quantile(0.75) - price.quantile(0.25),
        mean=price.mean().round(0),
    )
)
`,
    },
  ]}
/>

The mean sits well above the median, which is the signature of a
right-skewed distribution: a few very expensive diamonds pull the
average up while leaving the middle alone.

## Boolean aggregations

A Boolean column aggregates in ways that read naturally.

<CodeBlock
  adapter="python"
  datasets={[{ path: "palmer-penguins.csv", stageAs: "penguins.csv" }]}
  files={[
    {
      filename: "main.py",
      initCode: `import polars as pl
penguins = pl.read_csv("penguins.csv", null_values=["NA"])`,
      starterCode: `heavy = pl.col("body_mass_g") > 5000

print(
    penguins.select(
        any_heavy=heavy.any(),
        all_heavy=heavy.all(),
        n_heavy=heavy.sum(),                    # True counts as 1
        pct_heavy=(heavy.mean() * 100).round(1),  # mean of a Boolean is a share
    )
)
`,
    },
  ]}
/>

`heavy.mean()` being the *proportion* is worth remembering. It turns
"what fraction of rows satisfy this?" into one short expression.

## Positional and conditional aggregations

<CodeBlock
  adapter="python"
  datasets={[{ path: "palmer-penguins.csv", stageAs: "penguins.csv" }]}
  files={[
    {
      filename: "main.py",
      initCode: `import polars as pl
penguins = pl.read_csv("penguins.csv", null_values=["NA"])`,
      starterCode: `print(
    penguins.select(
        first=pl.col("species").first(),
        last=pl.col("species").last(),
        mode=pl.col("island").mode().first(),
        # The species of the heaviest penguin
        heaviest_species=pl.col("species")
        .sort_by("body_mass_g", descending=True, nulls_last=True)
        .first(),
        # Mean mass of Gentoos only, computed in one pass
        gentoo_mean=pl.col("body_mass_g")
        .filter(pl.col("species") == "Gentoo")
        .mean()
        .round(0),
    )
)
`,
    },
  ]}
/>

That last one is the pattern worth stealing: `.filter()` *inside* an
expression narrows the rows that one aggregation sees, without
filtering the frame. It lets you compute several differently-filtered
summaries in a single pass over the data.

<CodeBlock
  adapter="python"
  datasets={[{ path: "diamonds.csv", stageAs: "diamonds.csv" }]}
  files={[
    {
      filename: "main.py",
      initCode: `import polars as pl
diamonds = pl.read_csv("diamonds.csv")`,
      starterCode: `price = pl.col("price")

print(
    diamonds.select(
        ideal_mean=price.filter(pl.col("cut") == "Ideal").mean().round(0),
        fair_mean=price.filter(pl.col("cut") == "Fair").mean().round(0),
        big_mean=price.filter(pl.col("carat") > 1.5).mean().round(0),
        overall=price.mean().round(0),
    )
)
`,
    },
  ]}
/>

Four differently-scoped averages, one scan. Doing this with four
separate `filter()` calls would read the frame four times.

## Check your understanding

<MultipleChoice
  markdown={`A column has 100 rows, 10 of them null. What do \`pl.len()\` and \`pl.col("x").count()\` return?

- 100 and 100, since both count rows regardless of content
  > \`count()\` is column-aware and deliberately excludes nulls; that is the whole difference between the two.
- 90 and 90, since nulls are excluded from both
  > \`pl.len()\` counts the frame's rows and knows nothing about any particular column's nulls.
- [o] 100 and 90
  > The gap between them is the missing data, which makes their difference a quick null count.
- 100 and 10, because \`count()\` returns the number of nulls
  > Counting nulls is \`null_count()\`; \`count()\` reports the values that are present.

Using \`len()\` where you meant \`count()\` produces a mean divided by the wrong denominator.`}
/>

<MultipleChoice
  markdown={`What is \`(pl.col("mass") > 5000).mean()\`?

- The mean mass of the rows heavier than 5000
  > That would be \`pl.col("mass").filter(pl.col("mass") > 5000).mean()\`; here the mean is taken of the Boolean itself.
- Always either 0.0 or 1.0, since the input is Boolean
  > Averaging a mix of trues and falses lands between the two, which is exactly what makes it useful.
- [o] The proportion of rows where the condition holds
  > True counts as 1 and false as 0, so their mean is the share. Multiply by 100 for a percentage.
- An error, because \`mean()\` is not defined on a Boolean column
  > Boolean columns support \`mean()\`, \`sum()\`, \`any\`, and \`all\`, and each has a natural reading.

"What fraction of rows satisfy this?" becomes one short expression.`}
/>

<MultipleChoice
  markdown={`Why compute four differently-filtered averages inside one \`select()\` rather than with four \`filter()\` calls?

- \`filter()\` cannot be applied to the same frame more than once
  > A frame can be filtered any number of times; the argument is about how many passes the data takes.
- The results would otherwise have different column names
  > Naming is under your control either way, through \`alias()\` or keyword arguments.
- [o] Expression-level filters let all four be computed in one pass over the data
  > Four separate \`filter()\` calls scan the frame four times and produce four frames to stitch together.
- Frame-level filters silently drop rows containing nulls in other columns
  > \`filter()\` only considers the condition you give it; other columns' nulls do not affect which rows survive.

An expression-level \`filter()\` narrows one aggregation's view without narrowing the frame.`}
/>
