Real work starts with a file. Polars reads the usual formats, and for
most of them it offers two functions that look nearly identical and
behave very differently.

## read versus scan

| Function | What it does |
| --- | --- |
| `pl.read_csv(path)` | Reads the file now, returns a `DataFrame` |
| `pl.scan_csv(path)` | Returns a `LazyFrame`, reads nothing yet |

`read_*` is eager: the bytes are parsed immediately and you hold a
table. `scan_*` is lazy: you get a query plan whose first step is
"read this file", and no I/O happens until you call `.collect()`.

That distinction matters because a lazy plan can be *rewritten*
before it runs. If your query only touches three columns and only
keeps rows from 2009, Polars can push both facts down into the
reader and never parse the rest.

```python
import polars as pl

eager = pl.read_csv("penguins.csv", null_values=["NA"])
print(type(eager).__name__, eager.shape)

lazy = pl.scan_csv("penguins.csv", null_values=["NA"])
print(type(lazy).__name__)

# Nothing has been read yet. collect() is what runs it.
print(lazy.select("species", "body_mass_g").head(3).collect())
```

<Callout type="info" title="Not runnable in the browser">
The Polars build that ships with Pyodide is compiled without the streaming
engine, so `engine="streaming"` raises here.
The code is correct and works on a normal Polars install; it is shown
here rather than run.
</Callout>


The rule of thumb: **use `scan_*` unless you have a reason not to.**
The eager/lazy chapter later explains why in detail; for now, know
that the lazy version is rarely slower and frequently much faster.

## CSV, and the arguments worth knowing

CSV is a bad format that everyone uses. It has no types, no schema,
and no agreement on how to spell "missing". Polars gives you the
knobs to cope.

The arguments you will actually reach for:

| Argument | Use |
| --- | --- |
| `null_values` | The strings that mean missing (`"NA"`, `"N/A"`, `"-"`) |
| `columns` | Read a subset, by name or by index |
| `separator` | `";"` for European CSV, `"\t"` for TSV |
| `has_header` | `False` when the file starts with data |
| `schema_overrides` | Force one column's dtype without declaring them all |
| `try_parse_dates` | Turn date-shaped strings into real dates |
| `n_rows` | Read the first N rows, for a quick look at a huge file |
| `infer_schema_length` | How many rows to sample before deciding types |

<Callout type="warn" title="infer_schema_length is a common trap">
Polars samples the first 100 rows to guess each column's type. A
column that is integers for 40,000 rows and then contains `"unknown"`
will fail to parse when it gets there. Either pass
`schema_overrides={"col": pl.String}`, or `infer_schema_length=None`
to scan the whole file (slower, always right).
</Callout>

## Writing files back out

```python
import polars as pl

df = pl.DataFrame(
    {
        "city": ["Oslo", "Lisbon", "Reykjavik"],
        "temp_c": [-3.0, 17.5, 1.5],
    }
)

df.write_csv("out.csv")
df.write_parquet("out.parquet")
df.write_ndjson("out.ndjson")

print(open("out.csv").read())
print(pl.read_parquet("out.parquet"))

# CSV forgot the types; Parquet did not.
print("from csv    :", pl.read_csv("out.csv").dtypes)
print("from parquet:", pl.read_parquet("out.parquet").dtypes)
```

<Callout type="info" title="Not runnable in the browser">
`sink_parquet` belongs to the streaming engine, which the Polars build that
ships with Pyodide is compiled without.
The code is correct and works on a normal Polars install; it is shown
here rather than run.
</Callout>


That last pair of lines is the argument for Parquet in miniature.
CSV stores text, so every read re-guesses your types. Parquet stores
the schema, the values in columnar form, per-column compression, and
per-chunk statistics. It is smaller, faster, and does not lose
information.

## JSON, and its two shapes

```python
import polars as pl

# One JSON array of objects
open("array.json", "w").write(
    '[{"city": "Oslo", "temp_c": -3.0}, {"city": "Lisbon", "temp_c": 17.5}]'
)

# Newline-delimited JSON: one object per line, the streaming-friendly shape
open("lines.ndjson", "w").write(
    '{"city": "Oslo", "temp_c": -3.0}\n{"city": "Lisbon", "temp_c": 17.5}\n'
)

print(pl.read_json("array.json"))
print(pl.read_ndjson("lines.ndjson"))
```

<Callout type="info" title="Not runnable in the browser">
The Polars build that ships with Pyodide is compiled without JSON support, so
`read_json` is missing from it.
The code is correct and works on a normal Polars install; it is shown
here rather than run.
</Callout>


Use NDJSON where you can: it can be read in chunks and appended to,
neither of which is true of one enormous JSON array.

## Reading straight from a URL

Polars can read a remote file directly, which is handy for public
datasets.

<Figure
  slug="pl-reading-and-writing-data-read-versus-scan-inline-cutout"
  alt="One carton tipped fully onto a bench beside another carton with only a thin peephole cut in its side"
  caption="`read_*()` loads the whole file; `scan_*()` peers in and reads what it needs."

```python
url = "https://example.com/data/measurements.parquet"
df = pl.read_parquet(url)
```

<Callout type="info" title="In-browser exception">
The code blocks in this course run in WebAssembly, where network
access goes through the browser and is subject to cross-origin rules.
That is why lessons here stage a local file instead. On your own
machine the URL form works as written.
</Callout>

## Practice

Try it yourself before reading on. `penguins.csv` uses `"NA"` for missing
values. Read only the `species`, `island` and `body_mass_g` columns treating
`"NA"` as missing, write the result to `penguins.parquet`, and read that file
back. The point is that the types survive the round trip.

```python
import polars as pl

subset = pl.read_csv(
    "penguins.csv",
    null_values=["NA"],
    columns=["species", "island", "body_mass_g"],
)
subset.write_parquet("penguins.parquet")
round_trip = pl.read_parquet("penguins.parquet")

print(round_trip.head())
print(round_trip.dtypes)
# body_mass_g comes back as Int64, with its two nulls intact.
```

<Callout type="info" title="Not runnable in the browser">
The Polars build that ships with Pyodide is compiled without the streaming
engine, and `write_parquet()` is implemented on top of it, so writing Parquet
raises here. The code is correct on a normal Polars install; it is shown
rather than run.
</Callout>

<MultipleChoice

- Parquet compresses the data, and compression preserves types
  > Compression reduces size; it says nothing about types. Parquet keeps types because it stores a schema alongside the data.
- CSV files are always read with \`infer_schema_length=100\`
