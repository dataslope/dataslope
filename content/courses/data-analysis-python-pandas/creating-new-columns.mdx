Most analyses involve creating new columns: ratios, flags,
buckets, formatted strings. Pandas gives you several ways. Each
fits a different situation.

## The simplest case, arithmetic

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      starterCode: `import pandas as pd

df = pd.DataFrame(
    {
        "name": ["Aiko", "Bilal", "Chen"],
        "salary": [120, 95, 140],
        "bonus": [12, 8, 20],
    }
)

df["total_comp"] = df["salary"] + df["bonus"]
df["bonus_pct"] = (df["bonus"] / df["salary"] * 100).round(1)

display(df)
`,
    },
  ]}
/>

The whole column appears on both sides of `=`. That is the
*vectorized* style: no for-loop, just whole-column arithmetic.

## `.assign()`, chainable column creation

`.assign()` produces a *new* DataFrame with the added columns,
which makes it perfect for method chains.

<Figure
  slug="pandas-creating-new-columns-assign-chainable-column-inline-cutout"
  alt="A board passing through three machines in a row, each adding one more column and handing the board on"
  caption="Each `.assign()` hands on a new frame, so columns can be added in one chain."
/>

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      initCode: `import pandas as pd
df = pd.DataFrame({
    "name":   ["Aiko","Bilal","Chen"],
    "salary": [120, 95, 140],
    "bonus":  [12, 8, 20],
})`,
      starterCode: `new_df = df.assign(total_comp=lambda x: x["salary"] + x["bonus"]).assign(
    bonus_pct=lambda x: (x["bonus"] / x["salary"] * 100).round(1)
)
display(new_df)
print()
print("Original is unchanged:")
display(df)
`,
    },
  ]}
/>

The `lambda x: ...` lets `.assign` see the *current* state of the
DataFrame (including columns added earlier in the chain). This
matters when you want one new column to reference another.

## Mutate-in-place vs. assign

The same logical operation can be expressed two ways:

```python
# In place, modifies df
df["total_comp"] = df["salary"] + df["bonus"]

# Functional, returns a new DataFrame
df2 = df.assign(total_comp=df["salary"] + df["bonus"])
```

Both are widely used. A modern convention: use `.assign()` inside
long method chains; use direct assignment for one-off tweaks.
Either way, **immutability is the analyst's friend**, keeping
the original `df` untouched makes it easier to reason about
later cells.

<Callout type="info" title="Mutable vs immutable thinking">
*Mutable* operations change the DataFrame in place; *immutable*
operations return a new one. Pandas supports both. Beginners
tend to overuse mutable (and lose track of state); experienced
analysts often prefer immutable, even at the cost of an extra
variable.
</Callout>

## Conditional columns with `np.where()`

`np.where` is a vectorised if/else: three arrays in, one out, elementwise.

<SyntaxBreakdown
  parts={[
    { text: "np.where(" },
    { text: "df.age >= 18,", label: "the condition, elementwise" },
    { text: "\"adult\",", label: "value where it is true" },
    { text: "\"minor\"", label: "value where it is false" },
    { text: ")" },
  ]}
/>

`np.where(condition, value_if_true, value_if_false)` is a
vectorized ternary.

<Figure
  slug="pandas-creating-new-columns-inline-cutout"
  alt="Two existing columns feeding a small machine that sets a third column down beside them on the same board"
  caption="A new column is computed from the ones already on the table, row by row."
/>

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      starterCode: `import pandas as pd
import numpy as np

df = pd.DataFrame({"salary": [120, 95, 140, 80, 128]})
df["band"] = np.where(df["salary"] >= 130, "high", "standard")
display(df)
`,
    },
  ]}
/>

## Multi-condition: `np.select()`

For more than two branches, `np.select()` is cleaner than a nest of
`np.where()` calls.

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      starterCode: `import pandas as pd
import numpy as np

df = pd.DataFrame({"score": [92, 73, 58, 85, 41, 99]})

conditions = [
    df["score"] >= 90,
    df["score"] >= 80,
    df["score"] >= 70,
    df["score"] >= 60,
]
choices = ["A", "B", "C", "D"]

df["grade"] = np.select(conditions, choices, default="F")
display(df)
`,
    },
  ]}
/>

## Mapping with dictionaries: `.map`

When the new column is a lookup from old values:

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      starterCode: `import pandas as pd

df = pd.DataFrame(
    {
        "currency": ["USD", "EUR", "GBP", "USD", "JPY"],
        "amount": [100, 200, 150, 80, 12000],
    }
)

rates = {"USD": 1.00, "EUR": 1.08, "GBP": 1.27, "JPY": 0.0067}
df["amount_usd"] = (df["amount"] * df["currency"].map(rates)).round(2)
display(df)
`,
    },
  ]}
/>

`.map(dict)` is the quintessential dictionary-as-lookup pattern.
Values not in the dict become NaN.

## `.apply`, when you really need a function

When a column's value depends on more complex logic, fall back
to `.apply`. It is slower than vectorized operations, but
flexible.

"Slower" understates it at scale. What costs is entering the Python
interpreter, which a vectorized expression does a handful of times and
`.apply` does once per row:

<Chart slug="groupby-vectorized-speedup" />

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      starterCode: `import pandas as pd

def grade(score):
    if score >= 90:
        return "A"
    if score >= 80:
        return "B"
    if score >= 70:
        return "C"
    if score >= 60:
        return "D"
    return "F"

df = pd.DataFrame({"score": [92, 73, 58, 85, 41, 99]})
df["grade"] = df["score"].apply(grade)
display(df)
`,
    },
  ]}
/>

For *one column* → use `Series.apply(func)`. For *multiple
columns* per row → use `DataFrame.apply(func, axis=1)`, but
expect it to be slow on big data; prefer vectorized expressions
when you can.

## Binning continuous values

`pd.cut()` slices a continuous column into named buckets:

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      starterCode: `import pandas as pd

df = pd.DataFrame({"age": [22, 35, 47, 61, 18, 29, 71, 45]})
df["age_group"] = pd.cut(
    df["age"],
    bins=[0, 25, 40, 60, 200],
    labels=["young", "mid", "senior", "veteran"],
)
display(df)
`,
    },
  ]}
/>

For equal-frequency buckets (quartiles, quintiles) use
`pd.qcut()`:

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      starterCode: `import pandas as pd

df = pd.DataFrame({"income": [25, 35, 45, 60, 80, 110, 150, 200, 400]})
df["quartile"] = pd.qcut(df["income"], q=4, labels=["Q1", "Q2", "Q3", "Q4"])
display(df)
`,
    },
  ]}
/>

## A composite example

Put several techniques together, the penguins dataset with four
derived fields, one per technique from this chapter.

<CodeBlock
  adapter="python"
  datasets={[{ path: "palmer-penguins.csv", stageAs: "penguins.csv" }]}
  files={[
    {
      filename: "main.py",
      initCode: `import pandas as pd
import numpy as np
penguins = pd.read_csv("penguins.csv")`,
      starterCode: `# 1. Arithmetic: grams to kilograms
penguins["body_mass_kg"] = penguins["body_mass_g"] / 1000

# 2. Binning: flipper length into size bands
penguins["size_band"] = pd.cut(
    penguins["flipper_length_mm"],
    bins=[0, 190, 210, 1000],
    labels=["small", "medium", "large"],
)

# 3. Mapping: a short code per island
penguins["island_code"] = penguins["island"].map(
    {"Biscoe": "BIS", "Dream": "DRM", "Torgersen": "TOR"}
)

# 4. Conditional flag: "jumbo" = heavy AND long-flippered
penguins["jumbo"] = np.where(
    (penguins["body_mass_g"] > 5000) & (penguins["flipper_length_mm"] > 215),
    True,
    False,
)

display(
    penguins[
        ["species", "body_mass_kg", "flipper_length_mm", "size_band", "island_code", "jumbo"]
    ].head(10)
)
print()
print("Jumbo fraction:", penguins["jumbo"].mean().round(3))
`,
    },
  ]}
/>

## Check your understanding

<MultipleChoice
  markdown={`What is the difference between \`df["x"] = ...\` and \`df.assign(x=...)\`?

- [o] Direct assignment modifies \`df\` in place; \`.assign\` returns a *new* DataFrame and leaves the original untouched
  > \`.assign\` is the immutable alternative and chains nicely in pipelines.
- The first is faster
  > Performance is similar for small DataFrames; the meaningful difference is mutability, not speed.
- \`.assign\` is a method on Series
  > \`.assign\` is a DataFrame method; Series has no \`assign()\` method.
- Nothing
  > The two differ in whether the original DataFrame is mutated: direct assignment modifies \`df\` in place, while \`.assign\` returns a new DataFrame leaving the original unchanged.

Choose based on whether you want to preserve the original DataFrame.`}
/>

<MultipleChoice
  markdown={`When would you reach for \`np.select()\` instead of \`np.where()\`?

- When you want to filter
  > Filtering rows uses boolean masks and \`.loc\`; neither \`np.where()\` nor \`np.select()\` filters a DataFrame.
- When you want to sort
  > Sorting uses \`df.sort_values()\`; the choice between \`np.where()\` and \`np.select()\` is about how many conditional branches you need.
- When you want to drop columns
  > Dropping columns uses \`df.drop(columns=...)\`; this is unrelated to \`np.where()\` or \`np.select()\`.
- [o] When you need to assign one of *more than two* values depending on multiple conditions
  > \`np.where()\` is binary (if/else). \`np.select()\` extends to many branches without nesting.

For grade letters, salary bands, customer tiers, etc., \`np.select()\` keeps the logic readable.`}
/>

<MultipleChoice
  markdown={`\`df["currency"].map({"USD": 1.00, "EUR": 1.08})\` returns NaN for rows whose currency is "GBP". Why?

- The dict is read-only
  > Python dictionaries passed to \`.map\` are used for lookup only and are never modified; read-only access is not the cause of NaN results.
- [o] \`.map\` returns NaN for any value not found in the mapping dict; "GBP" is missing so the result is NaN
  > You can supply a default with \`.map(dict).fillna(...)\` or by using \`.replace\` instead.
- The map is corrupted
  > The dictionary is intact and correctly maps USD and EUR; NaN is returned specifically for values not found in the dict, which is the defined behavior.
- Pandas does not support strings in maps
  > \`.map\` works perfectly with string keys in a dictionary; the issue is that "GBP" is simply absent from the dict, not that strings are unsupported.

Always confirm your mapping is exhaustive (or explicitly handle the misses).`}
/>
