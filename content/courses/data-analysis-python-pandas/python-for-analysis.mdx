need a small, well-chosen subset of Python, enough to read the
code you write, enough to recognize errors, and enough to glue
together the Pandas calls that do the real work.

## Variables and assignment

A variable is a name that points to a value. The `=` sign
**assigns** a value to a name.

<Figure
  slug="pandas-python-for-analysis-variables-assignment-inline-cutout"
  alt="A blank tag tied to a block, then untied and tied to a different block, the first block left where it was"
  caption="A variable is a tag on a value, and rebinding it leaves the value untouched."
/>

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      starterCode: `name = "Aiko"
age = 29
is_active = True

print(name, age, is_active)
print(type(name), type(age), type(is_active))
`,
    },
  ]}
/>

In Pandas you will mostly assign DataFrames to variables:

```python
df = pd.read_csv("orders.csv")
clean = df.dropna()
```

The names are short on purpose, they appear a lot. Common
conventions:

- `df`, the current DataFrame.
- `df_a`, `df_b`, when you have multiple.
- `s`, a Series (one column).
- `g`, a GroupBy object.
- `idx`, an Index.

## The basic data types

Pandas wraps these, but you will sometimes pass them around
directly:

| Type     | Example         | Used in Pandas for                  |
| -------- | --------------- | ----------------------------------- |
| `int`    | `42`            | Counts, IDs, integer columns        |
| `float`  | `3.14`          | Continuous measurements, NaN-able   |
| `str`    | `"hello"`       | Text columns, labels, column names  |
| `bool`   | `True`/`False`  | Filters, boolean columns            |
| `None`   | `None`          | Missing values (often becomes NaN)  |
| `list`   | `[1, 2, 3]`     | Multiple column names, multi-select |
| `dict`   | `{"a": 1}`      | Column-to-value mappings, renames   |
| `tuple`  | `(1, 2)`        | Shape, fixed-size groups            |

A few examples:

## f-strings, formatted text

You will use f-strings constantly to assemble report-ready
messages.

<Figure
  slug="pandas-python-for-analysis-inline-cutout"
  alt="A hand editing cells one by one on the left, and a short instruction strip redoing the whole board on the right"
  caption="Editing cells by hand does not scale; a few lines redo the whole table."
/>

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      starterCode: `name = "Aiko"
salary = 120000
rate = 0.075

# Old way (you do not need this):
# print("Hi " + name + ", your raise is " + str(salary * rate))

# Modern way: f-strings
print(f"Hi {name}, your raise is \${salary * rate:,.2f}")
print(f"That is {rate:.1%} of your current salary of \${salary:,}")
`,
    },
  ]}
/>

The format specifiers (`:,.2f`, `:.1%`, `:,`) are worth
memorizing because they show up everywhere in analyst code.

## Comparisons and booleans

Pandas filtering is built entirely on boolean comparisons.

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      starterCode: `x = 5

print(x == 5)  # equal
print(x != 5)  # not equal
print(x > 3)
print(x >= 5)
print(x < 10)

# Logical combinations
print(x > 3 and x < 10)
print(x == 5 or x == 6)
print(not (x == 5))
`,
    },
  ]}
/>

Pandas uses *vectorized* versions of these on whole columns,
`df["age"] > 30` returns a column of booleans, one per row.
We will see this constantly.

## Lists and indexing

Lists hold an ordered sequence of items. You index them with
integers, starting at 0.

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      starterCode: `names = ["Aiko", "Bilal", "Chen", "Diego"]

print(names[0])  # first
print(names[-1])  # last
print(names[1:3])  # slice: items at index 1 and 2 (exclusive end)
print(len(names))

# Adding items
names.append("Eve")
print(names)
`,
    },
  ]}
/>

The slice syntax `start:stop` will reappear in Pandas's `iloc`
selector, with the same exclusive-end behavior.

## Dictionaries

A dictionary maps keys to values. You will use them most often
as small lookup tables and for column renames.

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      starterCode: `exchange = {"USD": 1.00, "EUR": 1.08, "GBP": 1.27}

print(exchange["EUR"])
print("JPY" in exchange)

# Iterate
for currency, rate in exchange.items():
    print(f"  1 {currency} = \${rate:.2f}")
`,
    },
  ]}
/>

In Pandas: `df["currency"].map(exchange)` looks up the rate for
every row in one shot. We will see `.map()` later.

## Functions

A function bundles up reusable logic. The classic shape:

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      starterCode: `def years_until_retirement(age, retire_at=65):
    """Return how many years until retirement."""
    return retire_at - age

print(years_until_retirement(29))
print(years_until_retirement(60, retire_at=67))
`,
    },
  ]}
/>

Two Python features that matter for Pandas:

- **Default arguments** (`retire_at=65`) make functions easier
  to call.
- **Docstrings** (the triple-quoted line) document intent. Get in
  the habit early.

You will write functions that operate on whole columns:

```python
def grade(score):
    if score >= 90:
        return "A"
    if score >= 80:
        return "B"
    return "C"

df["letter"] = df["score"].apply(grade)
```

We will see `.apply()` in detail later.

## Lambdas, small inline functions

A `lambda` is a one-line anonymous function. Useful for short
column transformations.

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      starterCode: `square = lambda x: x * x
print(square(7))

# Equivalent to:
def square2(x):
    return x * x

# Lambdas shine when passed to other functions:
nums = [1, 2, 3, 4, 5]
print(list(map(lambda n: n * 10, nums)))
`,
    },
  ]}
/>

In Pandas: `df["price"].apply(lambda p: p * 1.08)` is a common
pattern.

## What you do *not* need to know yet

It is a long list. Don't worry about:

- Classes and `self`.
- Decorators.
- Generators and `yield`.
- Context managers and `with`.
- Type hints beyond very simple ones.
- Async / `await`.

You will pick these up gradually if you need them. Pandas is
forgiving, the surface area you need to be productive is small.

<Callout type="info" title="Pandas is mostly chained calls">
A typical line of analyst code looks like:

`df.groupby("department")["salary"].mean().round(0).sort_values()`

Reading right to left through the chain, *take df, group by
department, pull out salary, average it, round, sort*, is
exactly how you should read it. Each step transforms the
result of the previous step.
</Callout>

## Check your understanding

<MultipleChoice
  markdown={`What does \`f"{rate:.1%}"\` print when \`rate = 0.075\`?

- \`75.0%\`
  > $0.075 \\times 100 = 7.5$, not 75; \`75.0%\` would result from formatting \`0.75\`, not \`0.075\`.
- \`0.075\`
  > Without a format specifier the number would print as \`0.075\`; the \`:.1%\` specifier multiplies by 100 and appends a percent sign, so the raw value is not the output.
- \`7.5\`
  > The \`%\` in \`:.1%\` adds the percent sign to the output; printing just \`7.5\` would require a format like \`:.1f\` after manually multiplying by 100.
- [o] \`7.5%\`
  > The \`.1%\` format multiplies by 100 and adds a percent sign, with one decimal place. Memorizing this format is worth the five seconds.

Format specifiers like this make report-ready output trivial.`}
/>

<MultipleChoice
  markdown={`Why are list slices like \`names[1:3]\` "exclusive at the end"?

- Slices always exclude the first item
  > Slices exclude the *last* item (the stop index), not the first; \`names[1:3]\` includes the item at index 1 and excludes the item at index 3.
- [o] By convention; \`names[1:3]\` returns items at index 1 and 2, so that \`len(names[1:3]) == 3 - 1 == 2\`, the slice length equals the difference of the indices
  > The exclusive end-index makes slice arithmetic clean: \`a[i:j]\` has length \`j - i\`. Pandas' \`iloc\` uses the same convention.
- It is a Python bug
  > The exclusive end is an intentional design decision in Python, not a bug; it makes slice length arithmetic consistent: \`len(s[i:j]) == j - i\`.
- It is a NumPy convention only
  > Exclusive-end slicing is a core Python convention, present in lists, strings, tuples, and range, not only in NumPy arrays.

Same rule as Pandas' \`iloc\`, useful to remember.`}
/>
