Numbers are abstract. Charts let humans *see* patterns. This
page introduces **Plotly Express**, a high-level interface
that turns DataFrames into interactive charts in one line.

<Figure
  slug="pandas-visualization-basics-cutout"
  alt="Visualization basics, an isometric illustration"
/>

<Callout type="info" title="Visualization is a thinking aid">
The goal of a chart during analysis is not to look pretty,
it's to surface insight. A messy scatter plot you understand is
worth more than a polished bar chart that hides the truth.
</Callout>

A separate course will dive deep into visualization. Here we
cover what's needed to *complete* exploratory analyses: bars,
histograms, scatter plots, and lines.

## Hello, Plotly Express

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      starterCode: `import pandas as pd
import plotly.express as px

df = pd.DataFrame(
    {
        "department": ["Eng", "Sales", "HR", "Eng", "Sales", "HR", "Eng", "Sales"],
        "headcount": [25, 18, 6, 30, 22, 8, 28, 20],
        "year": [2022, 2022, 2022, 2023, 2023, 2023, 2024, 2024],
    }
)

fig = px.bar(
    df, x="department", y="headcount", color="year", barmode="group",
    template="simple_white",
)
fig.show()
`,
    },
  ]}
/>

A single function call:

- Picks aesthetics (`x`, `y`, `color`).
- Chooses sensible axis ranges.
- Produces a legend.
- Returns an interactive figure.

Histograms are the single most underrated tool in exploratory analysis. Look
for:

- A long tail (skew)
- Multiple humps (mixed populations)
- Suspicious spikes (default values? censoring?)
- Gaps (missing ranges)

## Box plots, distributions across categories

A box knows only about quartiles, so three very different distributions can
produce the same one:

A box plot shows median, quartiles, and outliers in one
glance. Use it to compare a numeric column across categories.

## Scatter, relationships between two numerics

With enough points a scatter turns into a solid blob. Opacity is the first
fix, and it costs nothing:

<Chart slug="overplotting-alpha" />

<CodeBlock
  adapter="python"
  datasets={[{ path: "palmer-penguins.csv", stageAs: "penguins.csv" }]}
  files={[
    {
      filename: "main.py",
      initCode: `import pandas as pd
import plotly.express as px
penguins = pd.read_csv("penguins.csv")`,
      starterCode: `fig = px.scatter(
    penguins,
    x="flipper_length_mm",
    y="body_mass_g",
    color="species",
    opacity=0.7,
    title="Flipper length vs body mass, by species",
    template="simple_white",
)
fig.show()
`,
    },
  ]}
/>

Run it and notice how cleanly the three species separate into
three clouds, heavier penguins have longer flippers, and Gentoos
sit clearly apart in the upper-right. This penguin scatter is a
small classic of data teaching precisely because the structure
leaps out of the picture in a way no table of numbers ever could.
Opacity (`opacity=0.7`) keeps overlapping points readable.

## Line, trends over time

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      starterCode: `import pandas as pd
import plotly.express as px

dates = pd.date_range("2024-01-01", periods=60, freq="D")
df = pd.DataFrame(
    {
        "date": list(dates) * 2,
        "value": [80 + i * 0.5 for i in range(60)] + [60 + i * 0.7 for i in range(60)],
        "metric": ["visits"] * 60 + ["sign_ups"] * 60,
    }
)

fig = px.line(
    df, x="date", y="value", color="metric", title="Daily visits and sign-ups",
    template="simple_white",
)
fig.show()
`,
    },
  ]}
/>

A few line-chart rules:

- The x-axis is usually time.
- Truncating the y-axis can dramatically exaggerate small
  changes, use `range=[0, ...]` deliberately.
- One line per "thing being tracked", mapped via `color`.

A line is not just a prettier scatter. It asserts that the quantity existed
between the points and moved through those values, which is true of time and
meaningless for categories:

Faceting splits one chart into multiple small ones. It's often
clearer than overlaying many colors.

This is what faceting buys: the same series that overlap into an unreadable
tangle become legible the moment each gets its own panel.

## Choosing a chart, a quick flow

```mermaid
flowchart LR
  Q1{"What do you<br/>want to show?"}
  Q1 --> A1["Distribution of<br/>one numeric column"] --> H["Histogram or box plot"]
  Q1 --> A2["Comparison across<br/>categories"] --> B2["Bar chart"]
  Q1 --> A3["Relationship between<br/>two numerics"] --> S["Scatter plot"]
  Q1 --> A4["Change over time"] --> L["Line chart"]
  Q1 --> A5["Composition<br/>(parts of whole)"] --> ST["Stacked bar, not pie"]
```

We'll skip pie charts. Almost any pie chart can be replaced by
a clearer bar chart.

## Visualization vs summary statistics

```mermaid
flowchart TD
  D["Same dataset"] --> S["Summary stats<br/>(mean, median, std)"]
  D --> V["Visualization<br/>(histogram, scatter)"]
  S --> M["Quick numbers<br/>Hide shape"]
  V --> N["Rich shape<br/>Slower to skim"]
```

The cautionary tale: **Anscombe's quartet**, four datasets
with identical means, identical variances, identical
correlations, and identical regression lines, yet completely
different shapes that are obvious in a scatter plot. Always
*look* at your data, not just summarize it.

The same trap catches a single column, where the summary is the three numbers
`describe()` prints first:

## How visualizations can mislead

The first one on the list, drawn. Five scores within five points of each
other, from zero and then on a cropped axis:

<Chart slug="bar-truncation" />

<Chart slug="bar-truncation-cropped" />

And the second: the same data can favour one group in every subgroup and the
other overall.

<Chart slug="simpsons-paradox" />

- **Truncated y-axes** that make 5% changes look like 50%.
- **Inappropriate aggregation** that hides subgroups (Simpson's
  paradox).
- **3D charts** that distort lengths.
- **Cherry-picked time ranges**.
- **Misleading color scales** (rainbow, non-perceptually
  uniform).
- **Pie charts with too many slices**.

Cherry-picking is the one that is hardest to catch, because nothing on
the chart is false. Ten years going nowhere, and the four months
someone would show you instead:

<Chart slug="cherry-picked-window" />

<Chart slug="cherry-picked-window-zoom" />

And the last one, on five slices rather than too many. Ranking them by
angle is genuinely hard; by length it is immediate:

<Chart slug="pie-vs-bar" />

Always ask: "Would a *different* reasonable choice of chart
tell a *different* story?"

## Check your understanding

<MultipleChoice
  markdown={`Why is a histogram more revealing than just reporting the mean?

- Means are slow to compute
  > Computing a mean is fast; the chapter's argument for histograms is about informational richness, not speed.
- Histograms are always required
  > Histograms are a strong recommendation, not a requirement; the point is that they reveal distributional shape that a mean alone cannot capture.
- Histograms always look better
  > Visual appeal is subjective and irrelevant here; the argument for histograms is that they convey distributional information a mean cannot.
- [o] A histogram shows the full shape, skew, multiple modes, gaps, outliers, that a single mean entirely hides
  > Anscombe's quartet is the canonical demonstration.

You should plot your data before summarizing it.`}
/>

<MultipleChoice
  markdown={`Your chart shows a small change exaggerated dramatically. The most likely cause is:

- A bug in Plotly
  > Plotly faithfully renders the data and axis range you provide; if the range starts above zero, that is the analyst's configuration, not a library defect.
- [o] A truncated y-axis (the axis does not start at zero) makes small differences look large
  > Truncated axes are one of the most common, and abused, chart tricks.
- Wrong chart type
  > A wrong chart type can mislead, but exaggeration of a small absolute change most commonly comes from truncating the y-axis.
- Too much color
  > Color overload affects clarity and aesthetics, but it does not exaggerate the apparent magnitude of changes on an axis.

Be deliberate about axis ranges.`}
/>

<MultipleChoice
  markdown={`When comparing a numeric metric across many categories at once, which is generally clearest?

- A 3D surface plot
  > A 3D surface plot requires two continuous numeric axes defining a surface; it is suited to showing a function of two variables, not a metric compared across discrete categories.
- [o] A bar chart, or a faceted small-multiples histogram if you need the distribution
  > Bars use the strongest perceptual cue (length) and small multiples avoid clutter.
- A pie chart
  > Pie charts are hard to read when there are more than a handful of categories and rely on angle perception, which humans perform poorly; the chapter explicitly recommends against them.
- Many overlapping line charts
  > Overlapping lines for many categories become an unreadable spaghetti plot; they work for a small number of series tracked over time, not for cross-category comparison at a point in time.

Simple, well-chosen charts beat fancy ones almost every time.`}
