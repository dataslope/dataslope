If meaning is geometry, then comparing meanings is measuring distance.
There is a standard way to do it, and a reason it is not the obvious
one.

## Why not straight-line distance

Euclidean distance measures how far apart two points are. That
includes how far each is from the origin, which for embeddings is
mostly noise: vector *magnitude* tends to track things like token
frequency rather than meaning.

**Cosine similarity** measures the angle between two vectors and
ignores their lengths entirely. Two vectors pointing the same
direction score 1.0 regardless of how long either is.

$$\cos(a, b) = \frac{a \cdot b}{\lVert a \rVert \lVert b \rVert}$$

The numerator is the dot product; the denominator divides out both
magnitudes. Values run from 1.0 (identical direction) through 0.0
(unrelated) to -1.0 (opposite).

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      starterCode: `import numpy as np

def cosine(a, b):
    return float(np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b)))

short = np.array([1.0, 1.0])
long = np.array([5.0, 5.0])   # same direction, five times the length
other = np.array([1.0, -1.0]) # perpendicular

print("Euclidean distance short<->long:", round(float(np.linalg.norm(short - long)), 3))
print("Cosine similarity short<->long: ", round(cosine(short, long), 3))
print()
print("Cosine similarity short<->other:", round(cosine(short, other), 3))
print()
print("Same direction scores 1.0 no matter the magnitude,")
print("which is what we want when magnitude is not about meaning.")
`,
    },
  ]}

## A working semantic search

This is the whole of retrieval, minus a real embedding model. Note
that the query shares no words with the best match, which is the point:
the search is over meaning rather than text.

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      initCode: `import numpy as np

def cosine(a, b):
    return float(np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b)))

# Stand-in "embeddings" over four hand-chosen semantic axes:
#   [finance, weather, sport, cooking]
DOCS = {
    "Quarterly revenue rose twelve percent":      np.array([0.9, 0.0, 0.1, 0.0]),
    "Heavy rain expected across the region":      np.array([0.0, 0.9, 0.1, 0.0]),
    "The match finished two goals to one":        np.array([0.0, 0.1, 0.9, 0.0]),
    "Simmer the sauce for twenty minutes":        np.array([0.0, 0.0, 0.0, 0.9]),
    "Earnings beat analyst expectations":         np.array([0.85, 0.0, 0.0, 0.1]),
}

def search(query_vec, k=3):
    scored = [(cosine(query_vec, v), text) for text, v in DOCS.items()]
    scored.sort(reverse=True)
    return scored[:k]`,
      starterCode: `import numpy as np

# "How did the company perform financially?"
query = np.array([0.95, 0.0, 0.0, 0.05])

print("Query is about: finance")
print()
for score, text in search(query):
    print(f"  {score:.3f}  {text}")

print()
print("Note the top hit shares no words with the query.")
print("Matching happens in vector space, not on text.")

# Try a different query direction:
weather_query = np.array([0.0, 1.0, 0.0, 0.0])
print()
print("Query is about: weather")
for score, text in search(weather_query, k=2):
    print(f"  {score:.3f}  {text}")
`,
    },
  ]}

## Where this breaks

Two failure modes are worth knowing, because they explain a lot of
disappointing retrieval systems:

* **Cosine similarity has no notion of truth.** "The drug is
  effective" and "the drug is not effective" are extremely close in
  embedding space, because negation is a small perturbation to a
  sentence's overall direction. A retrieval system will happily return
  the opposite of what you asked for.
* **Similar is not relevant.** A document about your topic can be
  close in the space and still useless for the specific question. This
  is why production systems add a reranking step that reads candidates
  more carefully rather than trusting the geometry alone.

<Callout type="warn" title="The negation problem, concretely">
If you build a search over policy documents, a query for "cases where
approval is required" will surface "cases where approval is not
required" near the top. Similarity is not a proxy for entailment, and
no amount of tuning the embedding model fixes that.
</Callout>
