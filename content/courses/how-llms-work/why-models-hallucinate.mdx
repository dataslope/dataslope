## The one-sentence explanation

> The model produces plausible continuations. A plausible continuation
> of a question is an answer. Whether an answer is *available* is not
> something the mechanism can check.

Everything else follows.

## Why there is no "I do not know" signal

Consider what the model does when asked for a citation supporting a
claim.

Its training contains millions of citations. The pattern is
overwhelmingly clear: author names, a year, a plausible title, a
journal. Producing something with that shape is exactly what it is good
at, and the shape is right.

What it does not have is a mechanism that distinguishes "this specific
paper exists in my parameters" from "I am generating something with the
right shape". There is no confidence tag attached to a fact. **The
generation process is identical either way.**

## Where the risk concentrates

Hallucination is not uniformly distributed. It rises sharply where:

* **The fact is rare.** Something mentioned once has a weak trace.
  Something mentioned a million times has a strong one.
* **The fact is specific.** Numbers, dates, page references, version
  numbers, exact quotes. The shape is easy and the content is not.
* **The fact is composite.** "The paper by X about Y published in Z"
  requires three things to be simultaneously right, and each is an
  opportunity.
* **The fact is recent.** Past the training cutoff, nothing is
  attested, but the pattern of talking about recent events is.
* **You asked leadingly.** "What was the name of the study that proved
  this?" presupposes such a study, and the most plausible continuation
  is a name.

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      starterCode: `# A rough risk score, to make the pattern concrete.
def risk(rare, specific, composite, recent, leading):
    factors = {
        "rarely attested": rare, "highly specific": specific,
        "composite claim": composite, "after cutoff": recent,
        "leading question": leading,
    }
    hits = [name for name, on in factors.items() if on]
    return len(hits), hits

cases = {
    "Capital of France":              (0, 0, 0, 0, 0),
    "Population of a small town":     (1, 1, 0, 0, 0),
    "Page number of a quotation":     (1, 1, 1, 0, 0),
    "Name of the study that proved X": (1, 1, 1, 0, 1),
}

for label, flags in cases.items():
    n, hits = risk(*flags)
    print(f"{label:<32} risk {n}/5  {hits if hits else ''}")
`,
    },
  ]}

## Why "just tell me if you don't know" fails

Because it asks the model to report on a property it cannot observe.

The instruction does have a real effect: it shifts the distribution
toward hedged phrasing, so you get more sentences containing "I am not
certain". But that shift is stylistic, not diagnostic. The hedges do
not land preferentially on the wrong answers, because nothing inside
the process knows which answers are wrong.

## What actually reduces it

* **Ground it.** Supply the source text and ask for answers drawn from
  it. Retrieval works because the fact is now in the context rather
  than in the weights.
* **Ask for verifiable outputs.** A query you can run beats a number
  you must trust.
* **Constrain the shape.** Structured output with a schema removes the
  freedom to invent a field.
* **Give it an exit.** "If the document does not contain this, reply
  NOT_FOUND" works better than "do not make things up", because it
  provides a specific alternative continuation that is easy to produce.

<Callout type="warn" title="The uncomfortable implication">
Hallucination cannot be fully solved at the model level, because it is
the same capability as generalization. A model that only ever produced
strings it had seen verbatim would be useless. The industry's answer
has been to add grounding, tools, and verification *around* the model
rather than to expect the model to stop doing what it does.
</Callout>
