Here is the entire thing:

<Figure

/>

> **A language model takes a sequence of tokens and produces a
> probability distribution over which token comes next.**

That is it. Everything else, the chat interface, the tool use, the
reasoning, the refusals, is built on top of that one operation,
applied repeatedly.

## Repeated application is where the magic is

The model produces one token. That token is appended to the input. The
model runs again on the longer input and produces the next one. Repeat
until it produces a token meaning "done".

# exactly what a real system does; only \`predict_next\` is different.

def predict_next(context):
    """A toy 'model': looks up what usually follows."""
    table = {
        ("the",): "cat",
        ("the", "cat"): "sat",
        ("the", "cat", "sat"): "on",
        ("the", "cat", "sat", "on"): "the",
        ("the", "cat", "sat", "on", "the"): "mat",
    }
    return table.get(tuple(context), "<end>")

context = ["the"]
for step in range(6):
    nxt = predict_next(context)
    print(f"step {step}: context={context} -> {nxt!r}")
    if nxt == "<end>":
        break
    context.append(nxt)

print()
print("Final:", " ".join(context))
`,

/>

Notice what this loop does *not* contain: any plan, any goal, any
representation of the finished sentence. The sentence appears because
each local step was reasonable, not because anything decided in
advance what the sentence would be.

Hold onto that. It explains a great deal of behavior later.

## A distribution, not a word

The real model does not return `"cat"`. It returns a score for
**every token in its vocabulary**, typically 50,000 to 200,000 of
them. Something like:

| Token | Probability |
| --- | --- |
| ` cat` | 0.31 |
| ` dog` | 0.14 |
| ` man` | 0.09 |
| ` first` | 0.04 |
| ... | ... |

A separate step, covered in *Sampling*, picks one. That separation
matters: the model's job ends at the distribution, and the choice of
how to draw from it is a knob you control.

## Where the knowledge lives

The model has no database. There is no lookup table of facts, and no
retrieval step unless one was explicitly added by the surrounding
system.

What it has is a large number of parameters, adjusted during training
so that its predictions matched real text. Facts that appeared often
and consistently in training are encoded in those parameters strongly
enough to be reproduced reliably. Facts that appeared once are not.

This is why a model can tell you the capital of France with complete
reliability and invent a plausible-sounding citation with equal
fluency. Both come out of the same mechanism, and the mechanism does
not distinguish "I have this stored well" from "I am producing
something shaped like an answer".

<MultipleChoice
  markdown={`In the generation loop, what happens to each token after it is produced?

- It is discarded once written to the screen.
  > Discarding it would make each token independent of the last.
- [o] It is appended to the input, and the model runs again on the longer sequence.
  > This is what makes the output coherent: every prediction conditions on everything generated so far.
- It is stored in a separate output buffer and not reused.
  > It must re-enter the input, or the next prediction would have no knowledge of it.
- It is compared against the expected token to compute an error.
  > Error computation happens during training, not during generation.

Generation is the same operation applied repeatedly to a growing
input.`}
/>
