The vocabulary in the previous chapter was hand-written. Real ones are
*learned*, by an algorithm called **byte-pair encoding** (BPE) that is
simple enough to build here in full.

<Figure
  slug="llm-building-tokenizer-cutout"

## The algorithm

Start with every word split into individual characters. Then repeat:

1. Count every adjacent pair of symbols across the whole corpus.
2. Find the most frequent pair.
3. Merge it into a single new symbol everywhere it appears.
4. Record the merge.

Stop when you have as many merges as you want vocabulary entries. The
list of merges *is* the tokenizer: to tokenize new text, split it into
characters and replay the merges in order.

<Figure
  slug="llm-building-a-tokenizer-counting-pairs-inline-cutout"
  alt="A ribbon of chips with a tally rack beside it counting how often each neighbouring pair appears"
  caption="The commonest neighbouring pair is merged, and then the count is taken again."
/>

<Figure

The elegance is that frequency does all the work. Common sequences get
merged early and become single tokens; rare ones never merge and stay
fragmented. That is exactly the behavior we observed in the previous
chapter, and nobody designed it.

## Counting the pairs

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      starterCode: `from collections import Counter

corpus = "low low low low low lower lower newest newest newest widest widest"

# Step 0: word frequencies, and each word split into characters.
# "</w>" marks a word boundary, so "low" at the end of a word can
# merge differently from "low" inside "lower".
freqs = Counter(corpus.split())
splits = {word: list(word) + ["</w>"] for word in freqs}

for word, syms in splits.items():
    print(f"{word:>8} (x{freqs[word]}) -> {syms}")

# Step 1: count adjacent pairs, weighted by word frequency.
pairs = Counter()
for word, syms in splits.items():
    for i in range(len(syms) - 1):
        pairs[(syms[i], syms[i + 1])] += freqs[word]

print()
print("Most common adjacent pairs:")
for pair, n in pairs.most_common(5):
    print(f"  {pair} seen {n}x")
`,
    },
  ]}

## The full training loop

Now the merges. Watch the order they come out in.

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      starterCode: `from collections import Counter

corpus = "low low low low low lower lower newest newest newest widest widest"

def pair_counts(splits, freqs):
    pairs = Counter()
    for word, syms in splits.items():
        for i in range(len(syms) - 1):
            pairs[(syms[i], syms[i + 1])] += freqs[word]
    return pairs

def merge_pair(pair, splits):
    a, b = pair
    out = {}
    for word, syms in splits.items():
        new, i = [], 0
        while i < len(syms):
            if i < len(syms) - 1 and syms[i] == a and syms[i + 1] == b:
                new.append(a + b)
                i += 2
            else:
                new.append(syms[i])
                i += 1
        out[word] = new
    return out

freqs = Counter(corpus.split())
splits = {w: list(w) + ["</w>"] for w in freqs}
merges = []

for step in range(10):
    pairs = pair_counts(splits, freqs)
    if not pairs:
        break
    best, count = pairs.most_common(1)[0]
    if count < 2:
        break
    splits = merge_pair(best, splits)
    merges.append(best)
    print(f"merge {step + 1}: {best} seen {count}x -> {best[0] + best[1]!r}")

print()
print("Final tokenization:")
for word, syms in splits.items():
    print(f"  {word:>8} -> {syms}")
`,
    },
  ]}
/>

Read the output carefully, because it demonstrates the whole point:

* `low` appears seven times, so `l`+`o`+`w` merges almost immediately
  and becomes **one token**.
* `est</w>` merges early too, because it ends both `newest` and
  `widest`. The algorithm discovered a suffix without being told
  suffixes exist.
* `widest` ends up as `w`, `i`, `d`, `est</w>`: four tokens, because
  `wid` was not frequent enough to earn a merge.

That last line is the mechanism behind everything in the previous
chapter. Frequent text is cheap and atomic. Rare text is expensive and
fragmented.

<Callout type="info" title="Why the word-boundary marker matters">
Without `</w>`, the tokenizer could not tell `low` at the end of a word
from `low` inside `lower`, and merges would leak across boundaries.
Real implementations use a similar device, often by attaching the
leading space to the token instead, which is why `" the"` is its own
entry.
</Callout>

## Train it on your own text

Change the corpus and watch the vocabulary change with it. Try a
paragraph of English, then the same volume of Python code.

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      initCode: `from collections import Counter

def pair_counts(splits, freqs):
    pairs = Counter()
    for word, syms in splits.items():
        for i in range(len(syms) - 1):
            pairs[(syms[i], syms[i + 1])] += freqs[word]
    return pairs

def merge_pair(pair, splits):
    a, b = pair
    out = {}
    for word, syms in splits.items():
        new, i = [], 0
        while i < len(syms):
            if i < len(syms) - 1 and syms[i] == a and syms[i + 1] == b:
                new.append(a + b); i += 2
            else:
                new.append(syms[i]); i += 1
        out[word] = new
    return out

def train_bpe(corpus, n_merges):
    freqs = Counter(corpus.split())
    splits = {w: list(w) + ["</w>"] for w in freqs}
    merges = []
    for _ in range(n_merges):
        pairs = pair_counts(splits, freqs)
        if not pairs: break
        best, count = pairs.most_common(1)[0]
        if count < 2: break
        splits = merge_pair(best, splits)
        merges.append(best)
    return merges, splits`,
      starterCode: `# 'train_bpe' is defined in the initialization code above.
text = """
the model reads the text and the model predicts the next token
the text is split into tokens and the tokens become numbers
"""

merges, splits = train_bpe(text, n_merges=15)

print("Merges learned, in order:")
for i, m in enumerate(merges, 1):
    print(f"  {i:2d}. {m[0]!r} + {m[1]!r} -> {m[0] + m[1]!r}")

print()
print("Resulting token counts per word:")
for word, syms in sorted(splits.items(), key=lambda kv: len(kv[1])):
    print(f"  {word:>10} -> {len(syms)} token(s): {syms}")
`,
    },
  ]}
/>

Words you repeated became single tokens. Words you used once did not.
Now try adding a long rare word to the text and see where it lands.
