The model hands you a distribution. Something has to pick a token from
it, and that something is not the model. It is a small piece of code
with a few settings, and understanding it explains why the same prompt
gives different answers.

## Softmax turns scores into probabilities

The raw output is a list of unbounded scores called **logits**. They
can be negative, they do not sum to anything in particular. Softmax
converts them:

$$p_i = \frac{e^{z_i}}{\sum_j e^{z_j}}$$

Exponentiate every score, then divide by the total. The exponential is
what makes the result *peaked*: a small lead in logits becomes a large
lead in probability.

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      starterCode: `import numpy as np

tokens = [" cat", " dog", " bird", " rock"]
logits = np.array([3.2, 2.1, 1.5, -0.4])

def softmax(x):
    e = np.exp(x - np.max(x))   # subtract max for numerical stability
    return e / e.sum()

probs = softmax(logits)

print(f"{'token':>7} {'logit':>7} {'prob':>7}")
for t, l, p in zip(tokens, logits, probs):
    print(f"{t:>7} {l:>7.1f} {p:>7.3f}  {'#' * int(p * 40)}")

print()
print("A 1.1 logit gap became a", round(float(probs[0] / probs[1]), 1),
      "x probability ratio.")
`,
    },
  ]}
/>

The `- np.max(x)` is not cosmetic. Exponentiating a large logit
directly overflows to infinity; subtracting the maximum first shifts
everything into a safe range and leaves the result unchanged.

## Temperature reshapes the distribution

Temperature divides the logits before the softmax.

* **Low temperature** (below 1) spreads the logits apart, making the
  distribution peakier and the output more deterministic.
* **High temperature** (above 1) compresses them, flattening the
  distribution and making unlikely tokens more reachable.
* **Temperature 0** means "always take the maximum", which removes
  randomness entirely.

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      initCode: `import numpy as np

def softmax(x):
    e = np.exp(x - np.max(x))
    return e / e.sum()`,
      starterCode: `import numpy as np

tokens = [" cat", " dog", " bird", " rock"]
logits = np.array([3.2, 2.1, 1.5, -0.4])

for temp in [0.2, 0.7, 1.0, 2.0]:
    probs = softmax(logits / temp)
    row = "  ".join(f"{t.strip()}={p:.3f}" for t, p in zip(tokens, probs))
    print(f"T={temp:<4} {row}")

print()
print("Low T concentrates probability on the leader.")
print("High T gives the long tail a real chance.")
`,
    },
  ]}
/>

## Top-p (nucleus) sampling

Temperature alone has a problem: at high temperature, genuinely absurd
tokens become reachable. Top-p fixes this by truncating the tail first.

Sort tokens by probability, accumulate until the total reaches *p*
(commonly 0.9), discard everything else, renormalize, then sample.

The nucleus is **adaptive**: where the model is confident it might
contain two tokens, and where the model is genuinely uncertain it might
contain fifty. That is why it works better than a fixed top-k.

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      initCode: `import numpy as np

def softmax(x):
    e = np.exp(x - np.max(x))
    return e / e.sum()`,
      starterCode: `import numpy as np

def top_p(probs, tokens, p=0.9):
    order = np.argsort(probs)[::-1]
    cumulative = 0.0
    kept = []
    for i in order:
        kept.append(i)
        cumulative += probs[i]
        if cumulative >= p:
            break
    mask = np.zeros_like(probs)
    mask[kept] = probs[kept]
    return mask / mask.sum(), [tokens[i] for i in kept]

tokens = [" cat", " dog", " bird", " rock", " idea", " seven"]

print("CONFIDENT context (one strong candidate):")
probs = softmax(np.array([5.0, 1.0, 0.5, 0.1, 0.0, -1.0]))
_, kept = top_p(probs, tokens, p=0.9)
print(f"  nucleus holds {len(kept)} token(s): {kept}")

print()
print("UNCERTAIN context (many similar candidates):")
probs = softmax(np.array([1.2, 1.1, 1.0, 0.9, 0.8, 0.7]))
_, kept = top_p(probs, tokens, p=0.9)
print(f"  nucleus holds {len(kept)} token(s): {kept}")
`,
    },
  ]}
/>

## Watch randomness accumulate

One sampled token changes the context for the next prediction, so
small divergences compound. This is why two runs of the same prompt
can agree for a sentence and then separate completely.

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      initCode: `import numpy as np

def softmax(x):
    e = np.exp(x - np.max(x))
    return e / e.sum()`,
      starterCode: `import numpy as np

rng = np.random.default_rng(0)
tokens = ["a", "b", "c"]
logits = np.array([1.0, 0.9, 0.8])   # deliberately close together

for run in range(5):
    probs = softmax(logits / 1.0)
    seq = [tokens[rng.choice(len(tokens), p=probs)] for _ in range(8)]
    print(f"run {run + 1}: {''.join(seq)}")

print()
print("Same distribution every step, five different outputs.")
print("Set temperature to 0 (take the argmax) and all five would match.")
`,
    },
  ]}
/>

<Callout type="info" title="Choosing settings">
For analysis, extraction, and code, use low temperature: you want the
most likely continuation, not a creative one. For brainstorming and
drafting, higher temperature genuinely helps. Most APIs default around
1.0, which is tuned for conversation rather than for precision work.
</Callout>
