Every major provider prices the same way. Learn the structure and you
can read any price list, including ones published after this course
was written.

## The five numbers

Per **million tokens** (MTok), the standard unit:

| Number | What it is | Typical relationship |
| --- | --- | --- |
| **Input** | Tokens you send | The baseline |
| **Output** | Tokens generated | **5 times input, sometimes more** |
| **Cached input** | Repeated prefix, already processed | **10% of input or less** |
| **Cache write** | Storing a prefix for reuse | Slightly above input |
| **Batch** | Asynchronous, hours not seconds | **About 50% off** |

Those relationships are remarkably stable across vendors and across
years, even as the absolute prices fall. The one that has moved, the
cache discount, has only moved in your favor.

## Why output costs more than input

This is not a pricing policy, it reflects the computation.

<Figure
  slug="llm-pricing-structure-inline-cutout"
  alt="A set of scales with input chips on one pan and output chips on the other, the output pan weighted heavier"
  caption="Output costs more than input because it is generated one token at a time."
/>

**Input** is processed in parallel. All your tokens go through the
model together in one pass, and the hardware is fully occupied.

**Output** is generated one token at a time. Each token requires its
own forward pass through the entire model, and each pass depends on the
previous token, so none of it can be parallelized within a single
response. The hardware spends most of its time moving weights around
rather than computing.

A price difference of five times or more is the market's reflection of
a real efficiency gap.

## Why cached input is so cheap

If you send the same 50,000-token prefix on every turn, the provider
can store its processed internal state and skip recomputing it. What
you pay for is retrieving that state rather than producing it, which
is roughly a tenth of the work.

A tenth of the input price was the standard rate for years, and some
providers have gone further: a twentieth of the input price for a cache
hit on some models, and a fortieth on others.

<Figure
  slug="llm-pricing-structure-cached-input-so-inline-cutout"
  alt="Two scales side by side, one weighing a fresh ribbon and one weighing a ribbon already under a cover, the second barely tipping"
  caption="A cached prefix is retrieved rather than recomputed, which is far cheaper."
/>

Caches expire quickly (minutes, by default, on most providers) and
match on an **exact prefix**. A single changed byte anywhere in the
prefix invalidates everything after it, which is why putting a
timestamp at the top of a system prompt quietly costs a fortune.

## A typical price sheet

Providers sell several tiers, from a flagship model down to a small
one. The rates below are example prices, USD per million tokens, for
prompts below any long-prompt threshold (next section). They show the
typical *shape* of a price sheet rather than any provider's figures;
for real numbers, check the provider's current price page.

| Tier | Input | Output | Ratio |
| --- | --- | --- | --- |
| Flagship model | $10.00 | $50.00 | 5x |
| Large model | $4.00 | $20.00 | 5x |
| Mid-size model | $2.00 | $10.00 | 5x |
| Small model | $0.10 | $0.50 | 5x |

Three things to notice. The output-to-input ratio is 5x on every tier,
and real price sheets put it at 5x or higher, sometimes 6x or 8x. The
spread from cheapest to most expensive is a factor of 100, which means
**model selection is usually a bigger cost lever than prompt
optimization**. And a price can carry an expiry date: a promotional
rate can end and double overnight, so read the terms before you build a
budget on one.

A per-token price is also only half a comparison, because the same text
is a different number of tokens on different models. *Token Counts in
Practice* shows by how much.

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      starterCode: `# Example rates, USD per million tokens, in the shape of a typical price sheet.
MODELS = {
    "flagship":      {"in": 10.00, "out": 50.00},
    "large":         {"in": 4.00, "out": 20.00},
    "mid":           {"in": 2.00, "out": 10.00},
    "small":         {"in": 0.10, "out": 0.50},
}

# A typical request: long prompt, short answer.
in_tok, out_tok = 8_000, 500

print(f"{'model':<15} {'input':>8} {'output':>8} {'total':>9}  ratio")
for name, p in MODELS.items():
    ci = in_tok / 1e6 * p["in"]
    co = out_tok / 1e6 * p["out"]
    print(f"{name:<15} {ci:>8.5f} {co:>8.5f} {ci + co:>9.5f}  {p['out']/p['in']:.0f}x")

cheapest = min(MODELS.values(), key=lambda p: p["in"] * 8 + p["out"] * 0.5)
dearest = max(MODELS.values(), key=lambda p: p["in"] * 8 + p["out"] * 0.5)
spread = (dearest["in"] * 8 + dearest["out"] * 0.5) / (cheapest["in"] * 8 + cheapest["out"] * 0.5)
print()
print(f"Spread across tiers: {spread:.0f}x for the same request.")
`,
    },
  ]}
/>

## Watch for a length threshold

Many price sheets are flat: a 900,000-token prompt pays the same
per-token rate as a 9,000-token one. Others are not. Once a prompt
passes a threshold, the whole request is billed at a higher rate. Two
example shapes:

| Example threshold | Input rate above it | Output rate above it |
| --- | --- | --- |
| 200,000 tokens | 2x | 1.5x |
| 100,000 tokens | 5x | 5x |

The first is the common pattern: past 200,000 tokens, some providers
double the input price for the whole request. The second is rarer and
steeper, and it is why the threshold deserves as much attention as the
headline rate.

The threshold is part of the price. A workload that sends the occasional
huge document can cost several times what the headline rate suggests,
and splitting or trimming that one request below the line can be worth
more than any other optimization on it.

<Callout type="info" title="Prices fall, structure does not">
Per-token prices have fallen steeply and repeatedly, by most of their
value within a single year, and a small tier can drop tenfold from one
price sheet to the next. What did not move: the output multiple and the
batch discount. The caching discount moved in one direction only, from
a tenth toward a twentieth or a fortieth. Build your cost model on the
structure and it will survive the next price cut.
</Callout>
