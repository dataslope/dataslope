Embeddings give every token a meaning. Attention is what lets those
meanings **interact**, and it is the component that made modern
language models work.

/>

## The problem it solves

Consider:

> The trophy did not fit in the suitcase because **it** was too big.

What does "it" refer to? The trophy. Change one word:

> The trophy did not fit in the suitcase because **it** was too small.

Now "it" is the suitcase. Nothing about the token "it" changed. The
resolution depends on a relationship between "it", "big"/"small",
"trophy", and "suitcase" all at once.

<Figure
  slug="llm-attention-intuition-inline-cutout"
  alt="A row of chips along a rail, with cords of different thicknesses running from one chip back to three earlier ones, the thickest cord clearly heaviest"
/>

A model that processed tokens independently could never do this. It
needs a way for each token's representation to be **updated using
information from the other tokens**, weighted by how relevant each one
is. That is attention.

## Query, key, value

Each token produces three vectors from its embedding:

* A **query**: what am I looking for?
* A **key**: what do I offer to others looking?
* A **value**: what I actually contribute when attended to.

For each token, the model compares its query against every key,
producing a relevance score per token. Those scores are turned into
weights that sum to 1, and the token's new representation becomes a
weighted sum of all the values.

<Figure
  slug="llm-attention-intuition-query-key-value-inline-cutout"
  alt="One plain chip on a rail holding up a shaped template, a row of other plain chips each carrying a notch of a different shape, and the chip whose notch matches the template passing its block back along the rail"
/>

The mental image: every token asks a question, every token advertises
what it knows, and each token builds an updated version of itself out
of whatever answered its question best.

print('Attention from "it" to each token:')

    bar = "#" * int(w * 50)
    print(f"  {tok:>8}  {w:.3f}  {bar}")

print()
print("Weights sum to:", round(float(weights.sum()), 6))
print('Most attention goes to "trophy", which is what "it" refers to.')

## Doing it properly, with real vectors

Here is the actual computation, on toy vectors, with nothing hidden.

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      initCode: `import numpy as np

def softmax(x):
    e = np.exp(x - np.max(x))
    return e / e.sum()`,
      starterCode: `import numpy as np

tokens = ["trophy", "suitcase", "it"]

# Each token's key and value vectors (2-dimensional, for readability).
keys = np.array([[1.0, 0.2],    # trophy
                 [0.3, 1.0],    # suitcase
                 [0.1, 0.1]])   # it
values = np.array([[10.0, 0.0], # trophy contributes this
                   [0.0, 10.0], # suitcase contributes this
                   [1.0, 1.0]]) # it contributes this

# The query from "it". Pointing toward 'trophy'-like keys.
query = np.array([1.0, 0.1])

scores = keys @ query               # relevance of each token to the query
scores = scores / np.sqrt(keys.shape[1])   # scale, keeps softmax stable
weights = softmax(scores)
output = weights @ values           # weighted blend of the values

print("raw scores:  ", scores.round(3))
print("weights:     ", weights.round(3))
print()
for tok, w in zip(tokens, weights):
    print(f"  {tok:>9}: {w:.3f}")
print()
print("new representation for 'it':", output.round(3))
print("(dominated by trophy's value vector)")
`,
    },
  ]}
/>

Change `query` to `[0.2, 1.0]` and the weights shift toward
`suitcase`, and so does the output. That is the whole mechanism: a
different question retrieves a different blend.

## Many heads, many layers

Two multipliers turn this into something powerful:

* **Multiple heads.** The same operation runs many times in parallel
  with different learned query/key/value projections. One head might
  track syntactic agreement, another long-range references, another
  something with no human name. Their outputs are concatenated.
* **Multiple layers.** The output of one attention block feeds the
  next. Early layers resolve local structure, later layers assemble
  meaning across the whole input. A large model stacks dozens of these.

<Callout type="info" title="Why this was the breakthrough">
Earlier architectures processed text sequentially, so information from
token 1 reached token 500 only by passing through 499 intermediate
steps, degrading along the way. Attention connects every token to
every other token directly, in one step. That is both why long-range
dependencies work and why training could be parallelized across a
whole sequence at once, which is what made models this large trainable.
</Callout>

## The cost

Every token attends to every other token, so an input of *n* tokens
requires roughly *n²* comparisons. Doubling the input quadruples the
attention work. This is the fundamental reason long context windows
were hard to build and remain expensive to use, and why a great deal of
research goes into approximations that avoid the full quadratic cost.
