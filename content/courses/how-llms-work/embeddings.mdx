title: Embeddings
description: Every token becomes a vector, and meaning becomes geometry. This is the idea that makes everything else possible.

A token id is a number, but it is a meaningless one. Token 11241
(`" token"`) is not 11 times more of anything than token 1001. Ids are
labels, and labels support no arithmetic.

<Figure
  slug="llm-embeddings-cutout"
  alt="A three-dimensional lattice of floating labelled spheres where similar spheres cluster tightly together and one unrelated sphere sits far away across the grid"
/>

So the first thing the model does is replace each id with a **vector**:
a list of a few thousand numbers. This is the **embedding**, and it is
looked up from a table that was learned during training.

## Why a vector helps

Because vectors have geometry. Two vectors can be close together or
far apart, and training arranges the table so that **tokens used in
similar contexts end up close together**.

<Figure
  slug="llm-embeddings-inline-cutout"
  alt="A wide board where small chips sit at different heights and distances, similar chips clustered close together and unrelated ones far apart"
/>

That single arrangement gives the model something ids never could: the
ability to generalize. It has seen "the cat sat on the mat". If "dog"
sits near "cat" in the space, then "the dog sat on the mat" is
partially handled already, without ever having been observed.

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      starterCode: `import numpy as np

# A tiny hand-built embedding space. Real ones have thousands of
# dimensions; here we use three so they can be read directly.
#            [ animal, size, domestic ]
embeddings = {
    "cat":    np.array([0.9, 0.2, 0.9]),
    "dog":    np.array([0.9, 0.4, 0.9]),
    "wolf":   np.array([0.9, 0.5, 0.1]),
    "kitten": np.array([0.9, 0.1, 0.9]),
    "truck":  np.array([0.0, 0.9, 0.2]),
}

for word, vec in embeddings.items():
    print(f"{word:>7}: {vec}")

print()
print("Distance from 'cat':")
for word, vec in embeddings.items():
    d = np.linalg.norm(embeddings["cat"] - vec)
    print(f"  {word:>7}: {d:.3f}")
`,
    },
  ]}
/>

`kitten` is nearest, `dog` next, `truck` furthest. Nobody wrote those
relationships down; in a real model they fall out of the training
objective, because words used in similar sentences get pushed toward
similar vectors.

The older way of turning text into vectors counts words. That is enough
for a lot of tasks and hopeless for others, and the difference shows up as
soon as two sentences mean the same thing in different words.

## The dimensions are not interpretable

The example above labels its three dimensions "animal", "size",
"domestic" for readability. **Real embedding dimensions have no such
labels.** Dimension 1,847 of a real model does not mean anything you
can name. The meaning lives in the overall arrangement, not in
individual axes.

This matters when you read popular explanations claiming a model
"has a dimension for gender". It does not, in any clean sense. What
exists are directions in the space along which certain contrasts vary,
and those directions are combinations of many dimensions.

## Position has to be added

Embeddings alone are unordered. The vectors for "dog bites man" and
"man bites dog" are the same three vectors, and any operation that
treats them as a set gives both the same answer.

So position information is added, either by adding a
position-dependent vector to each embedding or by encoding relative
positions in the attention step. Either way, **the model does not get
order for free**, and everything about word order in its behavior
comes from this addition.

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      starterCode: `import numpy as np

emb = {"dog": np.array([0.9, 0.2]), "bites": np.array([0.1, 0.8]),
       "man": np.array([0.5, 0.5])}

s1 = ["dog", "bites", "man"]
s2 = ["man", "bites", "dog"]

# Without position: sum the vectors (order-blind).
print("Order-blind representation:")
print("  'dog bites man':", sum(emb[w] for w in s1))
print("  'man bites dog':", sum(emb[w] for w in s2))
print("  Identical, so the model could not tell them apart.")

# With a simple position signal added:
def positioned(words):
    return sum(emb[w] + np.array([0.0, 0.1 * i]) for i, w in enumerate(words))

print()
print("With position added:")
print("  'dog bites man':", positioned(s1).round(3))
print("  'man bites dog':", positioned(s2).round(3))
`,
    },
  ]}
/>

<Callout type="info" title="Embeddings you can use directly">
Embedding models are also sold as a product in their own right, for
search and retrieval. You embed your documents once, embed the user's
query, and return the nearest documents. That is the core of
retrieval-augmented generation, and it is built entirely on the
geometry in this chapter.
</Callout>
