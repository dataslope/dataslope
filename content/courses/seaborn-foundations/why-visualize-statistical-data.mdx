You can describe a dataset with a handful of numbers, a mean here, a
standard deviation there, a correlation between two columns, and feel like
you *know* it. Those summaries are genuinely useful. They are also famous
for being **liars**.

A summary statistic is, by definition, a compression: it throws most of the
data away and keeps one number. Two datasets that look nothing alike can be
squeezed down to the *same* mean, the *same* spread, and the *same*
correlation. If you only ever look at the numbers, you would swear they were
identical. The moment you **plot** them, the illusion shatters.

This page is about that gap, between what statistics *say* and what the
data is *actually doing*, and why a picture closes it. It is the reason the
rest of this course exists.

## The eye is a pattern detector

Before we touch any code, hold onto one idea. Your visual system is the most
powerful pattern-recognition machine you will ever use. In a fraction of a
second it picks out **shape** (is the relationship straight or curved?),
**clusters** (are there separate groups?), **trends** (does y rise with x?),
**outliers** (is one point flung far from the rest?), and **gaps** (is a
region suspiciously empty?).

A table of summary numbers offers none of that. A mean tells you where the
center sits, not whether the data is one tidy cloud or two clouds with a
canyon between them. Standard deviation measures spread, not whether the
spread is symmetric or skewed. Correlation measures *linear* association,
and quietly ignores any pattern that is not a straight line.

So the case for statistical visualization is simple: **plots restore the
information that summaries compress away.** Here is the compression, drawn:
four datasets whose means, variances, and correlation agree to two decimal
places.

Let's prove it in code.

## Meet Anscombe's quartet

In 1973 the statistician Francis Anscombe built four small datasets to make
exactly this point. Each has 11 `(x, y)` pairs. They are now a rite of
passage. We load them from a tidy table where every row carries a `dataset`
label (the group, `"I"` through `"IV"`) alongside its `x` and `y`, all four
groups stacked into one long DataFrame.

<Figure
  slug="sns-why-visualize-anscombe-cutout"
  alt="Four framed plots in a row with the points arranged differently in each, one identical tile standing beneath every frame"
  caption="Francis Anscombe, 1973: four datasets, one set of summary statistics, four completely different pictures."
/>

Let's start the way many people start with a new dataset: by computing
summary statistics per group and reading the numbers off a table.

<CodeBlock
  adapter="python"
  datasets={[{ path: "anscombes_quartet.csv", stageAs: "anscombe.csv" }]}
  files={[
    {
      filename: "main.py",
      starterCode: `import pandas as pd

# Four datasets (I-IV), stacked tidy: a dataset label, plus x and y.
anscombe = pd.read_csv("anscombe.csv")

# Summarize each group: mean of x, mean of y, their standard deviations,
# and the correlation between x and y.
summary = anscombe.groupby("dataset").agg(
    x_mean=("x", "mean"),
    y_mean=("y", "mean"),
    x_std=("x", "std"),
    y_std=("y", "std"),
)

# Correlation has to be computed per group separately.
corr = anscombe.groupby("dataset").apply(
    lambda g: g["x"].corr(g["y"]), include_groups=False
)
summary["corr_xy"] = corr

display(summary.round(2))
`,
    },
  ]}
/>

Read that table the way a busy analyst would. Every column is essentially
**constant across the four groups**: each `x` averages 9.0, each `y` averages
about 7.50, the standard deviations match to two decimals, and the
correlation between `x` and `y` is about 0.82 every time. By every number
here, the four datasets are *the same dataset*.

If summaries were the whole story, we would stop now and treat all four
identically. That would be a mistake.

<Callout type="info" title="Why these particular numbers?">
Anscombe reverse-engineered the four groups so their summaries would
coincide. The shared correlation of ~0.82 even implies the *same* best-fit
regression line, same slope, same intercept. The statistics are not
approximately equal by luck; they were *designed* to be equal.
</Callout>

## Now look at them

Here is the payoff. We hand the same table to Seaborn and ask for one panel
per `dataset`. `lmplot` draws a scatter of the points **and** overlays the
straight regression line that those identical statistics describe.

<CodeBlock
  adapter="python"
  datasets={[{ path: "anscombes_quartet.csv", stageAs: "anscombe.csv" }]}
  files={[
    {
      filename: "main.py",
      starterCode: `import pandas as pd
import seaborn as sns

sns.set_theme(style="whitegrid")
anscombe = pd.read_csv("anscombe.csv")

# One panel per dataset; a regression line in each.
sns.lmplot(
    data=anscombe,
    x="x",
    y="y",
    col="dataset",
    col_wrap=2,
    height=3,
    facet_kws={"sharex": True, "sharey": True},
    line_kws={"color": "crimson"},
)
`,
    },
  ]}
/>

Four wildly different worlds, and the *same* red line slicing through each:

* **Dataset I** is what the statistics led you to expect: a genuine, noisy
  linear relationship. The line is honest here.
* **Dataset II** is a clean **curve**. There is a strong relationship, but it
  is not a straight line at all. A correlation of 0.82 and a straight fit
  badly misrepresent it.
* **Dataset III** is a tight straight line *except for one outlier* that
  drags the fitted line off the true trend. Without the plot you would never
  suspect a single rogue point is steering your model.
* **Dataset IV** is the most unsettling: `x` is constant for ten points, and a
  *single* far-right point, a **high-leverage** observation, invents an
  entire slope out of nothing. Remove that one point and the "relationship"
  evaporates.

Same mean, same spread, same correlation, same regression line, four
completely different stories. That is the gap between numbers and reality,
made visible in a single figure.

<Callout type="warn" title="A correlation is not a shape">
A correlation coefficient answers one narrow question: *how close to a
straight line is this?* It says nothing about curves, clusters, or outliers.
Datasets II, III, and IV all score ~0.82 while violating the spirit of that
number entirely. Always plot before you trust a single statistic to
summarize a relationship.
</Callout>

<MultipleChoice
  markdown={`All four Anscombe datasets share nearly the same mean, standard deviation,

  > The means really are (essentially) equal, that is the whole setup. Plotting does not contradict the summary numbers; it adds information they never carried.

## Exploratory vs. explanatory visualization

It helps to name *why* you are drawing a chart, because the two main reasons
pull in different directions.

**Exploratory** visualization is for **you**, while you still don't know what
the data holds. You make many quick, rough plots, change a variable, add a
color, switch chart types, hunting for structure and surprises. Speed and
breadth matter more than polish. Anscombe's quartet is a parable about this
phase: skip it and you ship conclusions built on a mirage.

**Explanatory** visualization is for an **audience**, once you *have* found
something and want to communicate it clearly. Now you slow down: one careful
chart, good labels, a deliberate color choice, everything in service of a
single message.

Most of this course lives in the exploratory world, building the instinct to
*see* structure, but the aesthetic skills we cover later (themes, palettes,
annotations) are what carry a finding across the bridge into explanation.

<Callout type="tip" title="The goal of statistical visualization">
Boiled down to one sentence: **the goal is to see structure**, the shape,
groups, trends, and anomalies that summary numbers average away. Keep asking
the three questions from the introduction of every plot you make: what does
it reveal, what does it hide, and when would it break?
</Callout>

## It is not a fluke: the Datasaurus

If you suspect Anscombe rigged a rare special case in 1973, a modern sequel
puts that to rest. In 2017 Justin Matejka and George Fitzmaurice published
the **Datasaurus dozen**: thirteen datasets that all share the same means,
the same standard deviations, and the same correlation to two decimal
places, and one of them is shaped, unmistakably, like a **dinosaur**. (The
dino itself was drawn by Alberto Cairo; Matejka and Fitzmaurice built the
twelve siblings around it with an optimization that nudges points into a new
shape while pinning the summary statistics in place.)

<Figure
  slug="sns-why-visualize-statistical-data-eye-pattern-detector-inline-cutout"
  alt="A dense board of filled cells beside a chart of the same figures, a shape leaping out of the chart"
/>

Let's confirm the "identical statistics" half first, the way we did with
Anscombe. Group the thirteen shapes and read off their summaries.

<CodeBlock
  adapter="python"
  datasets={[{ path: "datasaurus_dozen.csv", stageAs: "datasaurus.csv" }]}
  files={[
    {
      filename: "main.py",
      initCode: `import pandas as pd
datasaurus = pd.read_csv("datasaurus.csv")`,
      starterCode: `# Mean and spread of x and y, per shape.
summary = datasaurus.groupby("dataset").agg(
    x_mean=("x", "mean"),
    y_mean=("y", "mean"),
    x_std=("x", "std"),
    y_std=("y", "std"),
)
display(summary.round(2))
`,
    },
  ]}
/>

Thirteen rows, and every column is essentially constant: each shape centers
near `(54.3, 47.8)` with the same spreads. By the numbers, these are the
same dataset thirteen times over. Now plot a few of them.

<CodeBlock
  adapter="python"
  datasets={[{ path: "datasaurus_dozen.csv", stageAs: "datasaurus.csv" }]}
  files={[
    {
      filename: "main.py",
      initCode: `import pandas as pd
import seaborn as sns

sns.set_theme(style="whitegrid")

      starterCode: `# Pick four shapes that share the same summary statistics.
shapes = ["dino", "star", "x_shape", "bullseye"]

sns.relplot(
    data=subset,
    x="x",
    y="y",
    col="dataset",
    col_wrap=2,
    height=2.6,
)
`,
    },
  ]}
/>

A dinosaur, a star, an X, and a bullseye, four pictures that could not be
more different, sharing one set of summary numbers. The takeaway is not
subtle: *for any* set of summary statistics there are endlessly many datasets
that produce them. Summaries narrow the possibilities; only a picture pins
down which one you actually have.

- Because it always underestimates the true value.
  > A mean is not biased low by nature; it is simply a summary. The issue is lost detail, not a systematic error.
- [o] Because it represents many data points with a single number, discarding the detail of how those points are arranged.
  > A mean keeps one fact (the center) and throws away shape, spread, clustering, and outliers, which is exactly why different datasets can share a mean.
- Because it makes the file smaller on disk.
  > "Compression" here is about information, not storage. The point is conceptual, not about bytes.
- Because it can only be computed on small datasets.
  > Means are computed on datasets of any size. The lesson is about what summaries omit, not about dataset size.
