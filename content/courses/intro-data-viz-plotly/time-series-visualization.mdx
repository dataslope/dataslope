Time-series data, anything indexed by date or timestamp, is the
most common kind of data in business and science. It deserves its
own chapter because:

- Time has structure (years, months, weeks, hours, holidays,
  seasons).
- The eye reads horizontal-time charts very fluently.
- A handful of specific pitfalls are *unique* to time series.

## The default: a line chart with time on x

For evenly-spaced, continuous time data, a line chart with x = time
is almost always the right starting point.

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      starterCode: `import plotly.express as px

df = px.data.stocks()

# Convert the wide stocks frame to long form
long = df.melt(id_vars="date", var_name="ticker", value_name="price")

fig = px.line(
    long,
    x="date",
    y="price",
    color="ticker",
    template="simple_white",
    title="Tech stocks (normalized to 1.0)",
    labels={"date": "Date", "price": "Normalized price"},
)
fig.show()
`,
    },
  ]}
/>

Plotly recognizes `date` as a datetime column and gives you a
**range slider** if you ask:

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      starterCode: `import plotly.express as px

df = px.data.stocks()
long = df.melt(id_vars="date", var_name="ticker", value_name="price")

fig = px.line(
    long,
    x="date",
    y="price",
    color="ticker",
    template="simple_white",
    title="Tech stocks with range slider",
    labels={"date": "Date", "price": "Normalized price"},
)
fig.update_xaxes(rangeslider_visible=True)
fig.show()
`,
    },
  ]}
/>

Drag the slider below the chart to zoom into any time window.

## Resampling: aggregating to a more useful granularity

Raw time-series data is often too granular for the chart you want.
You may have *per-minute* data but want to see *daily* trends.
Pandas' `.resample()` is the workhorse:

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      starterCode: `import pandas as pd
import numpy as np
import plotly.express as px

# Fabricate hourly data over 30 days
hours = pd.date_range("2024-01-01", periods=30 * 24, freq="H")
np.random.seed(0)
val = (
    50 + np.sin(np.arange(len(hours)) * 0.05) * 10 + np.random.normal(0, 3, len(hours))
)
df = pd.DataFrame({"timestamp": hours, "value": val})

# Aggregate to daily means:
daily = df.set_index("timestamp").resample("D").mean().reset_index()

fig = px.line(
    daily,
    x="timestamp",
    y="value",
    template="simple_white",
    title="Hourly noise smoothed to daily means via .resample('D')",
    labels={"timestamp": "Date", "value": "Mean value"},
)
fig.show()
`,
    },
  ]}
/>

Resampling is the "zoom level" of time analysis: minute, hour, day,
week, month, quarter, year. Pick the level that matches the
*story* you're telling.

## Moving averages: smoothing noisy series

A common pattern: the data is *noisy* day-to-day but has a clear
weekly or monthly trend. A **moving average** smooths the line so
the trend is visible.

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      starterCode: `import pandas as pd
import numpy as np
import plotly.express as px

dates = pd.date_range("2024-01-01", periods=120)
np.random.seed(1)
values = 100 + np.cumsum(np.random.normal(0, 5, 120))

df = pd.DataFrame({"date": dates, "value": values})
df["rolling_7"] = df["value"].rolling(7, center=True).mean()
df["rolling_30"] = df["value"].rolling(30, center=True).mean()

long = df.melt(id_vars="date", var_name="series", value_name="v").dropna()

fig = px.line(
    long,
    x="date",
    y="v",
    color="series",
    template="simple_white",
    title="Daily value with 7-day and 30-day moving averages",
    labels={"date": "Date", "v": "Value"},
)
fig.show()
`,
    },
  ]}
/>

The 30-day average is the *smoothest* and reveals the underlying
trend; the 7-day catches *weekly* structure; the raw daily shows
the noise. All three layered gives the whole story.

## Common time-series pitfalls

1. **Non-monotonic x-axis.** If your DataFrame isn't sorted by
   date, the line wiggles backwards through time. Always
   `df.sort_values("date")` before plotting.
2. **Inconsistent time gaps.** A daily chart that's missing
   weekends becomes misleading, Plotly will *interpolate* across
   the gap as if Saturday's value smoothly became Monday's.
3. **Calendar vs business time.** For stock prices, you may want
   to skip weekends and holidays, set
   `fig.update_xaxes(rangebreaks=[dict(bounds=["sat", "mon"])])`.
4. **Day-of-week effects.** Most business data has strong weekly
   seasonality. Don't compute a "trend" without considering it.
5. **Axis truncation can be more justified.** For time series
   showing change, starting the y-axis at a non-zero value is
   *sometimes* acceptable, but always label it clearly.

## Skipping non-trading days

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      starterCode: `import plotly.express as px

df = px.data.stocks()

fig = px.line(
    df,
    x="date",
    y="GOOG",
    template="simple_white",
    title="GOOG with weekends skipped (no flat spots over Sat-Sun)",
    labels={"date": "Date", "GOOG": "Normalized price"},
)

# Hide weekend gaps so the chart compresses to trading days
fig.update_xaxes(rangebreaks=[dict(bounds=["sat", "mon"])])
fig.show()
`,
    },
  ]}
/>

Notice the x-axis no longer has flat "no movement" stretches over
weekends.

## Seasonal patterns: faceting by year

To compare years on the same calendar, facet by year (or use a
*year-over-year* plot where the x-axis is just month/day):

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      starterCode: `import pandas as pd
import plotly.express as px

df = px.data.gapminder().query("country in ['China', 'India', 'United States']")

fig = px.line(
    df,
    x="year",
    y="lifeExp",
    color="country",
    facet_col="country",
    template="simple_white",
    title="Life expectancy, faceted per country",
    labels={"year": "Year", "lifeExp": "Life expectancy"},
)
fig.show()
`,
    },
  ]}
/>

Facets are excellent for time series too, they let you see each
group's *shape* clearly, and shared axes ensure honest comparison.

## Check your understanding

<MultipleChoice
  markdown={`What is **.resample('D').mean()** on a pandas time-indexed DataFrame doing?

- Sorting the data alphabetically.
  > \`resample()\` groups rows by a time frequency, not by alphabetical order; sorting alphabetically on a datetime index would be unusual and is not what this method does.
- Filling missing values.
  > Filling missing values is the job of methods like \`fillna()\` or \`interpolate()\`; \`resample()\` aggregates rows into time buckets, which may produce NaN for empty periods but does not fill them.
- [o] Aggregating the data to **daily** frequency, computing the mean of all rows that fall in each day.
  > **.resample('D')** groups rows by calendar day. **.resample('W')** would be weekly, **.resample('M')** monthly. Combined with an aggregation like **.mean()**, **.sum()**, or **.last()**, this is the standard way to change the granularity of a time series.
- Duplicating each row.
  > \`resample()\` aggregates multiple rows per time bucket into a single summary value; it reduces the number of rows, not duplicates them.

Resampling is the time-series equivalent of **groupby**. Master it and time charts become much easier to compose.`}
/>

<MultipleChoice
  markdown={`Why is a **moving average** often useful for noisy daily time-series data?

- It increases the data resolution.
  > A moving average *reduces* resolution by replacing individual data points with windowed averages; it is a smoothing technique, not an upsampling one.
- It is required by Plotly.
  > Plotly renders time-series line charts without any smoothing; a moving average is an optional preprocessing step the analyst adds, not a Plotly requirement.
- [o] It smooths short-term noise so the underlying weekly or monthly trend becomes visible.
  > Real-world series (web traffic, sales, sensor readings) are noisy day-to-day but often have meaningful longer-term trends. A 7-day or 30-day moving average filters out the noise. Show the raw and the smoothed series together so readers can see both layers.
- It removes outliers.
  > A moving average does not detect or remove outliers; extreme values are included in the window averages and still influence the smoothed line, just diluted by neighboring values.

Smoothing is *averaging*, not deleting. Outliers still affect a moving average; they're just averaged with their neighbors.`}
/>

<MultipleChoice
  markdown={`If your line chart's x-axis is a **date** and the line zigzags backward in time, what is the most likely cause?

- The DataFrame contains negative values.
  > Negative y-values do not affect the direction of the x-axis; backward zigzags on the time axis are caused by row ordering, not by the values being plotted.
- The dates are in the wrong time zone.
  > A timezone mismatch might shift data points earlier or later, but would not cause the line to visibly zigzag *backward* through time; unsorted rows are the typical culprit.
- [o] The DataFrame is not sorted by date, Plotly draws lines in DataFrame row order, not date order.
  > Plotly Express connects points in the *order they appear in the DataFrame*. If your rows aren't sorted by the x-column, the line walks through time in whatever order the rows arrived. The fix is one line: **df = df.sort_values("date")**.
- The y-axis is on a log scale.
  > The y-axis scale affects vertical rendering, not the horizontal progression of time; a log y-axis would not cause lines to move backward along the date axis.

This is one of those bugs that confuses everyone exactly once. After that, you sort first as a reflex.`}
/>

<MultipleChoice
  markdown={`Which Plotly chart configuration **hides weekend gaps** in a stock-price line chart, so the x-axis only shows trading days?

- Filtering the DataFrame to weekdays only.
  > Dropping weekend rows removes the data, but the x-axis is still a continuous date axis, so Plotly leaves the empty Saturday-Sunday span and draws a straight line across it. The gap remains visible.
- **fig.update_layout(weekends=False)**.
  > There is no **weekends** option on **update_layout**. This looks plausible but isn't a real Plotly setting.
- [o] **fig.update_xaxes(rangebreaks=[dict(bounds=["sat", "mon"])])**.
  > **rangebreaks** tells Plotly to *compress* certain ranges out of the x-axis. The **bounds** form hides the weekend gap; there are also **pattern** and **values** variants for holidays. Without this, weekend gaps appear as flat plateaus that misrepresent the data.
- This isn't possible in Plotly.
  > Plotly does support this directly through **rangebreaks**, so this option is incorrect.

Time-series charts have many small configuration options like this. Bookmark Plotly's time-series documentation.

*Hint: this chapter showed the exact setting used to skip weekends, it operates on the x-axis, not on the data or the layout.*`}
/>
