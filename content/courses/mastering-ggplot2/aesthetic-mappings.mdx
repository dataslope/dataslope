If data is the foundation, **aesthetic mappings** are the heart of the
grammar. The word "aesthetic" here is jargon, and it trips people up,
so let us define it precisely.

## What "aesthetic" means in ggplot2

An **aesthetic** is any **visual property of a mark** that can carry
information:

- **position**, x, y
- **color** (outline) and **fill** (interior)
- **size**
- **shape**
- **alpha** (transparency)
- **linetype**

An **aesthetic mapping** is a *correspondence between a data column and
one of these visual properties*. "Map `displ` to x." "Map `class` to
color." You declare mappings inside `aes()`.

| Data column | Aesthetic |
| --- | --- |
| `displ` | x position |
| `hwy` | y position |
| `class` | color |
| `cty` | size |

Those four rows *are* a call to
`aes(x = displ, y = hwy, color = class, size = cty)`. Each row is one
mapping.

## Aesthetics are information channels

Here is the deep idea: **each aesthetic is a channel through which a
variable can be seen.** Position is the strongest channel; color and
size are weaker but let you pack *more variables* into one chart. A
2-D scatter shows two variables through position; map color and size
too and you are showing four variables at once.

The channels are not equally good, though, and the ranking is measured
rather than aesthetic. The same difference read as a position, a length,
an angle, an area, and a colour:

<Chart slug="encoding-accuracy" />

That is the reason to spend `x` and `y` on the comparison your reader
actually has to make, and to put the variable they only need to
distinguish into colour.

<CodeBlock adapter="r"
  datasets={[{ path: "palmer-penguins.csv", stageAs: "penguins.csv" }]}
  files={[{ filename: "main.r",
    initCode: `library(ggplot2)\npenguins <- read.csv("penguins.csv")\npenguins <- na.omit(penguins)`,
    starterCode: `# Four variables in one plot, each through its own aesthetic channel.
ggplot(penguins, aes(
  x = flipper_length_mm, y = body_mass_g,
  color = species, size = bill_length_mm
)) +
  geom_point(alpha = 0.7)
` }]} />

Read the channels: x = flipper length, y = body mass, color = species,
size = bill length. Four columns, four aesthetics, one chart. Each
mapping also produced its own **guide** (the axes, the color legend,
the size legend) automatically. Notice how the three species pull apart
into clusters, the penguins are a favorite teaching set precisely
because so many of their variables separate the groups cleanly.

<Callout type="warn" title="Channels have a budget">
Just because you *can* map many aesthetics does not mean you *should*.
Every extra channel adds cognitive load. Color + size + shape all at
once can overwhelm a reader. Map what the *question* needs, not
everything you have.
</Callout>

## The same column can drive several aesthetics

Mapping one variable to *two* aesthetics at once **reinforces** it,
making groups easier to tell apart (and more accessible to readers who
have trouble distinguishing colors):

<CodeBlock
  adapter="r"
  files={[
    {
      filename: "main.r",
      starterCode: `library(ggplot2)

# drv drives BOTH color and shape: redundant encoding, easier to read.
ggplot(mpg, aes(displ, hwy, color = drv, shape = drv)) +
  geom_point(size = 2.5)
`,
    },
  ]}
/>

Both legends merge into one because they encode the same variable,
another automatic courtesy from the mapping system.

## Aesthetics depend on the geom

Not every geom understands every aesthetic. A `geom_point()` uses
`shape`; a `geom_line()` ignores `shape` but uses `linetype`. A bar
uses `fill` (its interior) more than `color` (its border). This is not
arbitrary, it follows from *what kind of mark* the geom draws.

<CodeBlock
  adapter="r"
  files={[
    {
      filename: "main.r",
      starterCode: `library(ggplot2)

# 'fill' colors the interior of bars; 'color' would only outline them.
ggplot(mpg, aes(x = class, fill = drv)) +
  geom_bar()
`,
    },
  ]}
/>

We will return to `color` vs. `fill` repeatedly. For now: **points and
lines use `color`; areas and bars use `fill` for their interior.**

## Mappings, not assignments

A subtle but vital point: `aes(x = displ)` is **not** "set x to the
value displ." It is "**let the column `displ` *vary* x across the
rows.**" Each row gets its own x from its own `displ`. A mapping is a
*rule applied to every row*, not a single value. This distinction is
the entire subject of the next page, mapping versus setting.

## Key takeaways

- An **aesthetic** is an information-carrying visual property: position,
  color, fill, size, shape, alpha, linetype.
- An **aesthetic mapping** (`aes()`) connects a *column* to an
  aesthetic, applied **per row**.
- Each mapping generates its own **guide** (axis or legend)
  automatically.
- Mapping more aesthetics shows more variables, but spend the
  "channel budget" wisely.
- Which aesthetics matter depends on the **geom**: points/lines use
  `color`; bars/areas use `fill` for their interior.
