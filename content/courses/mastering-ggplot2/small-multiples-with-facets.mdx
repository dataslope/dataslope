**Faceting** splits your data into subsets and draws a *separate panel*
for each, all sharing the same scales. The result, a grid of small,
comparable charts, is one of the most effective tools in all of data
visualization, and ggplot2 makes it a one-line addition.

## The problem facets solve

Mapping a grouping variable to color works until there are too many
groups; then the chart becomes an unreadable tangle, and the same lines
split into panels stop being a tangle at all:

<Chart slug="spaghetti-vs-facets" />

Watch a color mapping struggle:

<CodeBlock
  adapter="r"
  files={[
    {
      filename: "main.r",
      starterCode: `library(ggplot2)

# Seven classes overlaid by color: busy and hard to compare.
ggplot(mpg, aes(displ, hwy, color = class)) +
  geom_point() +
  geom_smooth(method = "lm", se = FALSE)
`,
    },
  ]}
/>

Now give each class its **own panel** instead:

<CodeBlock
  adapter="r"
  files={[
    {
      filename: "main.r",
      starterCode: `library(ggplot2)

# One panel per class -> compare like with like, at a glance.
ggplot(mpg, aes(displ, hwy)) +
  geom_point() +
  geom_smooth(method = "lm", se = FALSE) +
  facet_wrap(~class)
`,
    },
  ]}
/>

One busy panel with 7 overlapping groups becomes, via
`facet_wrap(~ class)`, 7 small panels on shared axes, one group each.
Differences *between* panels are then differences in the *data*.

## Why shared scales are the secret

The magic ingredient is that **every panel uses the same x and y
scales by default.** Because the axes are identical, any difference you
see *between* panels is a real difference in the *data*, not an
artifact of different scaling. Your eye compares parallel pictures far
faster than it parses one crowded picture.

<Callout type="info" title="The deep idea behind small multiples">
Faceting works because it removes a variable from the *visual clutter*
and turns it into *spatial position* (which panel). Comparison becomes
effortless precisely because everything except the faceting variable is
held constant across panels.
</Callout>

## facet_wrap: one variable, wrapped into a grid

`facet_wrap(~ var)` lays panels out in rows and columns that "wrap"
like text. Control the shape with `nrow` or `ncol`. Here one panel per
penguin species makes each species' flipper-to-mass relationship easy
to compare on shared axes:

<CodeBlock adapter="r"
  datasets={[{ path: "palmer-penguins.csv", stageAs: "penguins.csv" }]}
  files={[{ filename: "main.r",
    initCode: `library(ggplot2)\npenguins <- read.csv("penguins.csv")\npenguins <- na.omit(penguins)`,
    starterCode: `ggplot(penguins, aes(flipper_length_mm, body_mass_g)) +
  geom_point(alpha = 0.6) +
  facet_wrap(~species, nrow = 1)
` }]} />

## facet_grid: a 2-D matrix of two variables

`facet_grid(rows ~ cols)` makes a true grid: one variable defines the
rows, another the columns, so every panel is a *combination* of both.
This is ideal for crossing two categorical variables:

<CodeBlock
  adapter="r"
  files={[
    {
      filename: "main.r",
      starterCode: `library(ggplot2)

# Rows = drivetrain, columns = number of cylinders.
ggplot(mpg, aes(displ, hwy)) +
  geom_point() +
  facet_grid(drv ~ cyl)
`,
    },
  ]}
/>

Read it like a table: moving **down** changes drivetrain, moving
**across** changes cylinder count. Empty panels honestly show
combinations that do not occur in the data.

| | `facet_wrap(~ a)` | `facet_grid(a ~ b)` |
| --- | --- | --- |
| Variables | one (sometimes two) | two, one per dimension |
| Layout | wrapped into a grid to fit | strict rows × columns matrix |
| Best for | many levels of one variable | the crossing of two variables |

## The free-scales escape hatch

Sometimes panels cover wildly different ranges and shared scales squash
some panels flat. `scales = "free_y"` (or `"free_x"`, `"free"`) lets
each panel scale independently:

<CodeBlock
  adapter="r"
  files={[
    {
      filename: "main.r",
      starterCode: `library(ggplot2)

ggplot(mpg, aes(displ, hwy)) +
  geom_point() +
  facet_wrap(~drv, scales = "free_y")
`,
    },
  ]}
/>

<Callout type="warn" title="Free scales break comparability">
Independent scales make each panel readable *on its own* but **destroy
the cross-panel comparison** that makes small multiples powerful, a
tall bar in one panel may represent a smaller value than a short bar in
another. Use free scales sparingly and label them clearly.
</Callout>

## Key takeaways

- **Faceting** splits data into per-group panels, small multiples that
  the eye compares quickly.
- Panels **share scales by default**, so between-panel differences are
  real data differences.
- `facet_wrap(~ var)` wraps one variable's levels into a grid;
  `facet_grid(rows ~ cols)` crosses two variables into a matrix.
- `scales = "free_*"` lets panels scale independently but **breaks
  comparability**, use it cautiously.
