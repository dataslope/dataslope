Your page is viewed on a 6-inch phone and a 27-inch monitor, often the
same day. **Responsive design** is the craft of one layout that adapts
to both, no separate "mobile site" required.

## Start with fluid units

Half of responsiveness is just *not* hard-coding pixel widths:

- **`%`, `fr`, `auto`** let boxes share available space.
- **`max-width`** caps a box on big screens without forcing a width on
  small ones: `max-width: 60rem; width: 100%`.
- **`rem`** sizes type relative to the root, so everything scales
  together.
- **`vw`/`vh`** are percentages of the viewport itself.

And one line every responsive page needs, in the HTML `<head>`, so
phones don't pretend to be desktops:

```html
<meta name="viewport" content="width=device-width, initial-scale=1" />
```

## Media queries: different rules at different sizes

A **media query** applies CSS only when a condition holds, most often
a width threshold (a **breakpoint**):

```css
/* base styles apply everywhere */
.grid { grid-template-columns: repeat(3, 1fr); }

/* override only on narrow screens */
@media (max-width: 600px) {
  .grid { grid-template-columns: 1fr; }
}
```

## Mobile-first

The habit most teams follow: write the **small-screen** layout as the
base (no media query), then *add* complexity for larger screens with
`min-width` queries. It tends to produce simpler CSS, the base case is
the constrained one, and enhancements pile on only where there's room.

<Callout type="info" title="You already met a query-free responsive trick">
`grid-template-columns: repeat(auto-fit, minmax(150px, 1fr))` from the
Grid lesson reflows columns to fit any width, no media query at all.
Reach for media queries when a layout needs to *change shape*, not
just *fit*.
</Callout>
