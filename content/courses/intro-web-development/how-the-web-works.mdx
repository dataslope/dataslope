Before writing any code, it's worth knowing what actually happens when
you visit a web page. The story has two characters: a **server** and a
**browser**.

## The round trip

1. You type `example.com` and press Enter.
2. Your browser sends an **HTTP request** across the internet to the
   server that hosts that site: *"please send me the page."*
3. The server responds with a text file written in **HTML**.
4. Your browser reads that HTML top-to-bottom and **renders** it,
   turning tags into headings, paragraphs, buttons, and images on your
   screen.
5. Along the way the HTML may reference more files, **CSS**
   stylesheets and **JavaScript** programs, and the browser fetches
   and applies those too.

The crucial insight: a web page isn't a picture that gets downloaded.
It's a *program-like description* that your browser executes. The
server sends text; **your machine** does the rendering. That's why the
same page can adapt to a phone screen, why you can zoom text, and why
a page can keep working interactively without talking to the server
again.

## The three languages, one page

Here's a complete, self-contained page that uses all three languages
at once. Don't worry about understanding every line, the next ten
lessons unpack all of it. Run it, then poke at it:

<CodeBlock
  adapter="web"
  files={[
    {
      filename: "index.html",
      starterCode: `<!DOCTYPE html>
<html>
  <head>
    <!-- CSS: what things LOOK like -->
    <style>
    body {
      font-family: system-ui, sans-serif;
      margin: 2rem;
    }
    button {
      padding: 0.4rem 1rem;
      font-size: 1rem;
      cursor: pointer;
    }
    .visits {
      color: #16a34a;
      font-weight: bold;
    }
    </style>
  </head>
  <body>
    <!-- HTML: what things ARE -->
    <h1>My first page</h1>
    <p>You have clicked <span class="visits" id="count">0</span> times.</p>
    <button id="btn">Click me</button>

    <!-- JavaScript: what things DO -->
    <script>
    var count = 0;
    var button = document.querySelector("#btn");
    var display = document.querySelector("#count");

    button.addEventListener("click", function () {
      count = count + 1;
      display.textContent = count;
      console.log("clicked! count is now", count);
    });
    </script>
  </body>
</html>
`,
    },
  ]}
/>

A few things to notice:

- The **preview is a live page**. Click its button, the number
  changes without re-running anything, because the JavaScript keeps
  running inside the page.
- `console.log(...)` output appears in the **output panel** under the
  preview when the page runs. The console is the developer's window
  into a page, you'll use it constantly.
- The `<style>` and `<script>` blocks live *inside* the HTML here. In
  the CSS and JavaScript lessons you'll move them into their own
  files, the way real projects do.

## Where your lessons run

On a real project you'd save this text as `index.html` on disk and
open it in a browser, or put it on a server for the world. Here, the
course renders your page in a **sandboxed preview**, an isolated
mini-browser-tab inside the lesson. It behaves like a normal page (it
runs scripts, applies styles, shows alerts) but it can't touch the
rest of this site. Same skills, safe playground.
