## Components and JSX

A React app is built from **components**, functions that return
markup. The markup-in-JavaScript syntax is called **JSX**:

```tsx
function Welcome() {
  return <h1>Hello from a component!</h1>;
}
```

JSX looks like HTML with three differences you'll hit immediately:
`class` becomes `className`, `{curly braces}` embed JavaScript
expressions, and components compose like elements: `<Welcome />`.

These lessons use **TSX**, JSX with TypeScript, compiled entirely
in your browser (the first Run downloads the ~3 MB toolchain once).

<CodeBlock
  adapter="react"
  files={[
    {
      filename: "main.tsx",
      starterCode: `import { createRoot } from "react-dom/client";

function Badge({ label }: { label: string }) {
  return (
    <span
      style={{
        background: "#dbeafe",
        color: "#1d4ed8",
        borderRadius: 999,
        padding: "2px 12px",
        fontWeight: 600,
      }}
    >
      {label}
    </span>
  );
}

function App() {
  const topics = ["HTML", "CSS", "JavaScript", "React"];
  return (
    <main style={{ fontFamily: "system-ui", margin: 24 }}>
      <h1>What I've learned</h1>
      <div style={{ display: "flex", gap: 8 }}>
        {topics.map((topic) => (
          <Badge key={topic} label={topic} />
        ))}
      </div>
    </main>
  );
}

createRoot(document.getElementById("root")!).render(<App />);
`,
    },
  ]}
/>

Three ideas in that one file:

- **Props**, `Badge` receives `label` like a function argument.
  Same component, different data, four badges.
- **Lists**, `topics.map(...)` turns an array into elements; `key`
  tells React which is which.
- **Mounting**, `createRoot(...).render(<App />)` attaches the
  component tree to the page's `<div id="root">`. Every React app
  has exactly one of these lines.

## State, the scoreboard, the React way

`useState` gives a component a piece of state and a function to
change it. Call the setter and React re-renders, no
`querySelector`, no manual `textContent` updates, no
reset-the-variable-AND-the-display bugs:

<CodeBlock
  adapter="react"
  files={[
    {
      filename: "main.tsx",
      starterCode: `import { useState } from "react";
import { createRoot } from "react-dom/client";

function Scoreboard() {
  const [home, setHome] = useState(0);
  const [away, setAway] = useState(0);

  return (
    <main style={{ fontFamily: "system-ui", margin: 24 }}>
      <h1>
        Home {home}, {away} Away
      </h1>
      <button onClick={() => setHome(home + 1)}>+1 Home</button>{" "}
      <button onClick={() => setAway(away + 1)}>+1 Away</button>{" "}
      <button
        onClick={() => {
          setHome(0);
          setAway(0);
        }}
      >
        Reset
      </button>
    </main>
  );
}

createRoot(document.getElementById("root")!).render(<Scoreboard />);
`,
    },
  ]}
/>

Compare this to the vanilla version from the project lesson: the
display can never drift from the variables, because the display *is a
function of* the variables.

import { createRoot } from "react-dom/client";

function LikeButton() {
  const [likes, setLikes] = useState(0);

  return (
    <main style={{ fontFamily: "system-ui", margin: 24 }}>
      <h1>Likes: {likes}</h1>
      <button onClick={() => setLikes(likes + 1)}>👍 Like</button>
    </main>
  );
}

createRoot(document.getElementById("root")!).render(<LikeButton />);
`,
    },
  ]}

    },

}`,
    },
  ]}
/>

That's the core React loop: state → render → event → new state.
