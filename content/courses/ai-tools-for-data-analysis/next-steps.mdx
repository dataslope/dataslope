## The whole course on one page

**Before you ask**

1. Paste the schema: column names and types.
2. State the grain: what one row represents.
3. State the quirks: test accounts, backfills, units, what null means.
4. State what a correct answer must contain.

**When you ask**

5. Request steps with intermediate variables, not one-liners.
6. Request row counts printed after each filter.
7. Request the assumptions it could not verify.
8. Ask for one stage at a time.

**When you get an answer**

9. Check the shape: is the row count what you expected?
10. Check the magnitude against your prior.
11. Check that the parts sum to the whole.
12. Spot-check one row by hand from the raw data.

**Before it leaves your screen**

13. Every identifier exists and means what you think.
14. Every literal in a filter exists in the data.
15. Joins: grain checked, type checked, row count explained.
16. Aggregates: right denominator, right `COUNT` variant, no double counting.

## The five failure modes

| Mode | Signature |
| --- | --- |
| Invented columns | Empty result, zero total, or a column you do not recognize |
| Broken joins | Row count changed unexpectedly across a join |
| Aggregation traps | Parts do not sum to the whole, percentages above 100% |
| Silent nulls and types | Grouped total below column total, text sorting as "10" then "9" |
| Confidence without accuracy | A simple-looking answer nobody checked |

## The one idea to keep

If you remember nothing else:

> **Delegate the tasks you can check faster than you could do them.
> Do the rest yourself.**

Every recommendation in this course follows from that. It is also the
rule that will still apply when the model names on the tool-landscape
page look quaint.
