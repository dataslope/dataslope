Everything so far has assumed a conversation: you ask, it answers, you
decide what to do. The direction of travel in 2026 is toward
assistants that **act**, running queries, reading files, and executing
multi-step plans without a human between each step.

## What makes something an agent

The distinction is not intelligence, it is the loop.

A chat assistant produces text and stops. An agent produces an action,
observes the result, and decides what to do next, repeatedly, until it
judges the task done. Concretely:

```text
1. Read the schema for the orders table
2. (sees the schema)
3. Run a query counting rows by status
4. (sees the counts, notices an unexpected status value)
5. Run a query investigating that value
6. (sees the result)
7. Report back
```

Steps 2, 4, and 6 are the difference. The agent is reacting to what it
found rather than executing a plan fixed in advance.

## The plumbing: MCP

The **Model Context Protocol** is the open standard that connects
assistants to tools and data. Anthropic introduced it in late 2024 and
by 2026 it had been adopted across OpenAI, Google, and Microsoft,
along with a large ecosystem of servers for databases, file stores,
issue trackers, and internal APIs.

For an analyst, the practical significance is narrow and real: an MCP
connection to your warehouse means the assistant can **look up your
schema instead of guessing it**, which removes the single most common
defect covered in this course.

## What gets better

* **No more invented columns.** It can list tables and describe them.
* **Self-correction on real errors.** A failing query produces a real
  error message it can act on.
* **Multi-step investigation.** Following an anomaly across three
  tables is the kind of task where the loop genuinely pays.

## What gets harder

* **Verification surface grows.** Instead of one query to review, you
  have a sequence of eight, plus the reasoning that connected them.
  Reviewing a trajectory is meaningfully harder than reviewing a
  query.
* **Errors compound.** A wrong conclusion at step 3 shapes steps 4
  through 8. The final answer can be confidently wrong in a way that
  is much more work to unpick than a single bad query.
* **Actions are not always reversible.** A read-only agent is safe in
  the way a chat assistant is safe. An agent with write access is a
  different category of thing entirely.
* **Cost becomes less predictable.** A loop decides how many steps to
  take, and a wide `SELECT` against a large table can be expensive in
  a way a chat message never is.

<Callout type="warn" title="The verification principle, restated for agents">
The rule does not change: never accept a number you have not checked.
What changes is that the checking now has to cover the *path*, not
just the final query. Ask the agent to show every query it ran, and
review the sequence.
</Callout>

## What the analyst's job becomes

Less writing queries, more **specifying tasks precisely and auditing
trajectories**. That is a genuine shift in the work, and it rewards
exactly the skills this course has been drilling: knowing what correct
looks like before you see the answer, and having a routine for
checking it.
