When an agent finishes, it tells you what it did. Treat that message as
a claim. The diff is the record, and reading it is the habit that
separates using an agent from trusting one.

## Start with the list of files

{/*
- `git diff --stat` or `--name-only` first. A file you did not expect
  is the cheapest red flag to spot.
- Lockfiles, config, CI workflows and test fixtures deserve a second
  look even when expected.
*/}

## Then the tests

{/*
- Did any test change? Was an assertion loosened, a case deleted, a
  test skipped? (Detail in Verifying with Tests.)
- New tests: do they test the change, or just run it?
*/}

## Then the logic

{/*
- Read the change against the request: does it do what was asked, and
  only that?
- Look for new helpers that duplicate existing ones, and broad
  exception handlers (Common Failure Modes).
*/}
