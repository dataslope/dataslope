An agent will attempt whatever you type. Whether it finishes the task
you meant depends on four things you can put in the request: what you
want, what it cannot find out on its own, what it must not do, and how
anyone will know it is done.

## The goal

{/*
- State the outcome, not the activity. "Make parse_date read 03/04/2026
  as 3 April" rather than "look at the date code".
- One goal per request (see Sizing a Task).
*/}

## Context it cannot discover

{/*
- What the agent can read for itself: the code. What it cannot: why
  the code is like that, what the users expect, which of two behaviors
  is the bug.
- Point at files and functions by name. It saves a search and anchors
  the change.
*/}

## Constraints

{/*
- What must not change: public function signatures, other modules,
  dependencies, the database schema.
- Without them, "done" can include a refactor you did not ask for
  (see Common Failure Modes, scope creep).
*/}

## A test for done

{/*
- The part most requests leave out. A command that passes, a test that
  exists, an output that matches.
- An agent that can run the check will usually run it. One that cannot
  will declare success by its own standard.
*/}
