A `str` in Python 3 is an immutable sequence of Unicode code points. Strings are one of the most-used types in the language-text is everywhere-and Python gives you a rich toolkit for working with them.

## Real-world context: Text is everywhere

Strings show up in almost every program:
- **Web apps:** HTTP headers, JSON payloads, URLs, query parameters, HTML templates.
- **Data pipelines:** CSV rows, log lines, file paths, column names.
- **Automation scripts:** command output, configuration files, environment variables.
- **Games:** dialogue, item names, save files.

Understanding strings-indexing, slicing, formatting, and the immutability gotcha-is essential to productive Python programming.

### Escape sequences

| Sequence | Meaning |
| --- | --- |
| `\\n` | newline |
| `\\t` | tab |
| `\\\\` | backslash |

## Indexing and slicing

Strings are sequences, so they support indexing (`s[i]`) and slicing (`s[start:stop:step]`). Indices are zero-based; negative indices count from the end.

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      starterCode: `s = "Python"
print(s[0])  # 'P'
print(s[-1])  # 'n'
`,
    },
  ]}
/>

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      starterCode: `s = "Python"
print(s[1:4])  # 'yth'
print(s[:2])  # 'Py'
print(s[2:])  # 'thon'
`,
    },
  ]}
/>

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      starterCode: `s = "Python"
print(s[::-1])  # 'nohtyP' (reverse)
print(s[::2])  # 'Pto' (every other character)
`,
    },
  ]}
/>

Slicing **never raises `IndexError`**, even with out-of-range bounds. It just returns whatever overlaps.

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      starterCode: `s = "Python"
print(s[100:200])  # '' (empty string, no error)
`,
    },
  ]}
/>

<Callout type="info" title="Unicode and len(): the emoji surprise">
In Python 3, `len(s)` returns the number of Unicode code points, not bytes. Most characters are one code point, but some emoji and complex scripts can surprise you:

```python
print(len("👍"))         # 1 (single code point)
print(len("👨‍👩‍👧‍👦"))      # 7 (family emoji is a sequence of code points + zero-width joiners)
```

If you need byte length, encode first: `len(s.encode("utf-8"))`.
</Callout>

## Strings are immutable

You **cannot** mutate a string in place. Methods like `upper()`, `replace()`, and `strip()` return **new** strings.

<Figure
  slug="python-strings-inline-cutout"
  alt="A ribbon of letter tiles being cut, joined and reversed by three small hand tools"
/>

That has a consequence worth knowing before you write your first loop over
text: `s += piece` inside a loop is not appending, it is copying everything
accumulated so far into a fresh string each time.

<Chart slug="string-concat-quadratic" />

Use `"".join(pieces)` instead, which walks the list once.

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      starterCode: `s = "hello"
try:
    s[0] = "H"
except TypeError as e:
    print("TypeError:", e)
`,
    },
  ]}
/>

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      starterCode: `s = "hello"
print(s.upper())  # returns "HELLO"
print(s)  # unchanged
`,
    },
  ]}
/>

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      starterCode: `s = "hello"
s = s.upper()  # rebinding is how you "change" a string
print(s)
`,
    },
  ]}
/>

<Callout type="warn" title="Immutability gotcha">
Because strings are immutable, repeatedly concatenating with `+=` in a loop is O(n²), each operation creates a new string and copies everything.

**Bad:**
```python
result = ""
for i in range(1000):
    result += str(i)  # creates a new string each time
```

**Good:**
```python
parts = []
for i in range(1000):
    parts.append(str(i))
result = "".join(parts)
```

`str.join()` is the idiomatic way to build a string from many pieces.
</Callout>

## Formatting: f-strings (the killer feature)

**f-strings** (Python 3.6+) are the modern, recommended way to build strings. Put any expression inside `{ ... }`.

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      starterCode: `name = "Ada"
score = 87.4321

print(f"{name} scored {score}")
`,
    },
  ]}
/>

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      starterCode: `name = "Ada"
score = 87.4321

print(f"{name} scored {score:.1f}")  # one decimal place
`,
    },
  ]}
/>

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      starterCode: `name = "Ada"
score = 87.4321

print(f"{name:>10} | {score:>6.2f}")  # right-aligned, widths
print(f"{score:,.2f}")  # thousands separator
`,
    },
  ]}
/>

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      starterCode: `score = 87.4321

print(f"{score=}")  # debug form (Python 3.8+)
`,
    },
  ]}
/>

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      starterCode: `score = 87.4321

# Expressions are fine inside the braces.
print(f"double = {score * 2:.2f}")
`,
    },
  ]}
/>

<Callout type="info" title="f-string format mini-language">
The part after `:` in `{value:format}` is a powerful mini-language:

- `.Nf`, N decimal places for floats
- `>width`, right-align in width
- `<width`, left-align
- `^width`, center
- `,`, thousands separator
- `0Nf`, zero-pad
- `%`, multiply by 100 and add percent sign

Full spec: [Format Specification Mini-Language](https://docs.python.org/3/library/string.html#formatspec).
</Callout>

Other formatting styles you'll see in older code:

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      starterCode: `name = "Ada"
score = 87.4

# str.format (Python 3.0+)
print("{} scored {:.1f}".format(name, score))

# Old % formatting (still works, ported from C printf)
print("%s scored %.1f" % (name, score))
`,
    },
  ]}
/>

## Bytes vs strings

`str` holds Unicode code points; `bytes` holds raw 8-bit values. Use `.encode()` to go from `str` to `bytes` and `.decode()` to go back. The default codec is UTF-8.

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      starterCode: `s = "café"
b = s.encode("utf-8")
print(b, len(b), len(s))
`,
    },
  ]}
/>

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      starterCode: `s = "café"
b = s.encode("utf-8")
print(b.decode("utf-8"))
`,
    },
  ]}
/>

<Callout type="warn" title="str vs bytes: a common source of bugs">
File I/O, network I/O, and many libraries return `bytes`, not `str`. If you try to concatenate `str` and `bytes`, you'll get a `TypeError`. Always decode bytes to strings before working with text:

```python
response = b"Hello"  # from a network request
# Bad: "Greeting: " + response  # TypeError
# Good: "Greeting: " + response.decode("utf-8")
```
</Callout>

How many bytes a character costs depends on the character. UTF-8 spends
one byte on ASCII and up to four on everything else, which is why
`len(s)` and `len(s.encode())` disagree.
