`bool` has exactly two values: `True` and `False`. Both are written capitalized, and both are singleton objects. Understanding how Python evaluates truthiness-what counts as true or false in a boolean context-is key to writing idiomatic code.

## Real-world context: Truthiness everywhere

Booleans and boolean logic are fundamental to control flow. In real-world code, you'll see:
- **Conditional checks:** `if user.is_authenticated:`, `if response.ok:`, `if items:`
- **Filtering:** `[x for x in data if x > 0]`
- **Short-circuit evaluation:** `value = user_input or default`
- **Guard clauses:** `if not ready: return`

Python's truthiness rules make code concise and readable. Instead of `if len(items) > 0:`, you write `if items:`.

<Callout type="info" title="The origin of 'boolean'">
The term "boolean" comes from **George Boole** (1815–1864), an English mathematician who developed Boolean algebra, a system of logic with just two values: true and false. His work laid the foundation for digital circuit design and all of computer science.
</Callout>

### bool is a subclass of int

`bool` inherits from `int`, so `True` and `False` behave as `1` and `0` in arithmetic contexts.

<Figure
  slug="python-booleans-two-boolean-values-inline-cutout"
  alt="A switch with exactly two positions and no travel between them"
  caption="A `bool` has exactly two settings, which is why Python can treat them as 1 and 0."
/>

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      starterCode: `print(True == 1, False == 0)
print(isinstance(True, int))
`,
    },
  ]}
/>

That is not a quirk to memorise so much as a fact to exploit. Because
`True` *is* `1`, summing a list of booleans counts how many of them are
true, which is the shortest way to answer "how many rows passed?"

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      starterCode: `print(True + True + True)  # 3
print(False * 100)  # 0
`,
    },
  ]}
/>

<Callout type="warn" title="The 'is True' antipattern">
**Never write `if x is True:`**, it checks whether `x` is the exact `True` object, not whether `x` is truthy. This breaks with values like `1`, `"hello"`, or `[1, 2, 3]` that are truthy but not `True`.

**Bad:**
```python
if len(items) > 0 is True:  # convoluted and wrong
```

**Good:**
```python
if items:  # Pythonic truthiness check
```
</Callout>

## Comparison operators

| Operator | Meaning |
| --- | --- |
| `==`, `!=` | value equality / inequality |
| `<`, `<=`, `>`, `>=` | ordering |
| `is`, `is not` | identity (same object?) |
| `in`, `not in` | membership in a sequence/container |

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      starterCode: `print(3 < 5 <= 5)  # chained comparisons! Same as (3 < 5) and (5 <= 5)
`,
    },
  ]}
/>

Most languages would read `3 < 5 <= 5` as `(3 < 5) <= 5`, comparing a
boolean to a number. Python chains it the way mathematicians write it.

The `in` operator asks a different question, membership rather than
ordering, and it works on any container:

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      starterCode: `print("a" in "banana")
print(2 in [1, 2, 3])
`,
    },
  ]}
/>

`is` is different again. It does not compare values at all:

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      starterCode: `print(None is None)
print(True is True)
`,
    },
  ]}
/>

### `==` vs `is`

`==` asks "are these **equal** in value?". `is` asks "are these the **same object** in memory?".

<Figure
  slug="python-booleans-comparison-operators-inline-cutout"
  alt="Two blocks on a balance whose needle rests hard against one of two stops"
  caption="A comparison weighs two values and lands on exactly one of `True` or `False`."
/>

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      starterCode: `a = [1, 2, 3]
b = [1, 2, 3]
print(a == b)  # True, same contents
print(a is b)  # False, different list objects
`,
    },
  ]}
/>

Two lists with identical contents are equal but not identical. That
distinction only matters occasionally, but when it matters it matters a
lot: `None` is a single object that exists exactly once in a running
program, so identity is the right test for it.

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      starterCode: `x = None
print(x is None)  # the idiomatic check
`,
    },
  ]}
/>

For singletons like `None`, `True`, `False`, always use `is`.

## Truthiness

Any object can be tested in a boolean context (e.g., `if`, `while`, `and`, `or`). Python's rules:

- **Falsy:** `False`, `None`, any zero (`0`, `0.0`, `0j`), any empty container (`""`, `[]`, `()`, `{}`, `set()`), and instances of classes that define `__bool__` to return `False` or `__len__` to return `0`.
- **Truthy:** everything else.

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      starterCode: `for value in [0, 1, "", "hi", [], [0], None, {}, {0: 0}]:
    print(f"{value!r:>10} -> {bool(value)}")
`,
    },
  ]}
/>

This is why idiomatic Python writes `if items:` instead of `if len(items) > 0:`.

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      starterCode: `items = [1, 2, 3]
if items:
    print("We have items!")
`,
    },
  ]}
/>

The negative form reads just as well:

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      starterCode: `items = []
if not items:
    print("Empty list!")
`,
    },
  ]}
/>

<Callout type="warn" title="The 0 == False surprise">
Because `False` equals `0`, you can get unexpected behavior if you're not careful:

```python
count = 0
if count == False:  # True! (but don't write this)
    print("count is zero")
```

**Better:** use truthiness or an explicit comparison:
```python
if not count:       # Pythonic
if count == 0:      # explicit
```
</Callout>

## Logical operators: `and`, `or`, `not`

Python's logical operators are written as English words, not symbols (`&&`, `||`, `!` like in C or JavaScript).

<Figure
  slug="python-booleans-inline-cutout"
  alt="A single two-position switch on a panel with a lamp above it, lit in one position and dark in the other"
  caption="Every condition your program tests comes down to one switch: `True` or `False`."
/>

### Pure boolean logic

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      starterCode: `print(True and False)
print(True or False)
print(not True)
`,
    },
  ]}
/>

### Short-circuit evaluation

`and` and `or` **short-circuit**: they stop evaluating as soon as the result is determined.

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      starterCode: `def expensive():
    print("expensive() called")
    return True

print(False and expensive())  # expensive() is never called
`,
    },
  ]}
/>

`False and anything` is already `False`, so Python never runs the right
side. `or` short-circuits from the other direction:

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      starterCode: `def expensive():
    print("expensive() called")
    return True

print(True or expensive())  # expensive() is never called
`,
    },
  ]}
/>

### Operators return operands, not just True/False

**Key insight:** `and` and `or` don't always return `True` or `False`. They return one of the operands.

- `x and y` returns `x` if `x` is falsy, otherwise `y`.
- `x or y` returns `x` if `x` is truthy, otherwise `y`.

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      starterCode: `print(True and "hello")  # 'hello'
print(False or "default")  # 'default'
`,
    },
  ]}
/>

Chain more than two and the rule still holds, one operand at a time,
left to right:

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      starterCode: `print(None or 0 or "first truthy")  # 'first truthy'
print("a" and "b" and "c")  # 'c'
`,
    },
  ]}
/>

<Callout type="info" title="Why operators return operands">
This design enables a common idiom: using `or` to supply a default value.

```python
name = user_input or "Anonymous"
```

If `user_input` is an empty string (falsy), `name` becomes `"Anonymous"`. If it's a non-empty string (truthy), `name` becomes `user_input`.

**Gotcha:** This breaks if `0` is a valid input, because `0` is falsy:
```python
count = user_count or 10  # if user_count is 0, this gives 10!
```

For such cases, use an explicit `None` check:
```python
count = user_count if user_count is not None else 10
```
</Callout>

### Common idiom: default values

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      starterCode: `name = ""
print(name or "Anonymous")  # "Anonymous"
`,
    },
  ]}
/>

That is the idiom working as intended. Here is the same idiom quietly
going wrong:

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      starterCode: `# Careful: 0 is falsy, so 'or' replaces it
count = 0
print(count or 10)  # 10, probably not what you want!
`,
    },
  ]}
/>

A user who really did order zero items gets told they ordered ten. When
`0` is a legitimate value, test for `None` instead of for truthiness:

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      starterCode: `# Use a None check for cases where 0 is valid
count = 0
print(count if count is not None else 10)  # 0
`,
    },
  ]}
/>

## Conditional expressions (ternary operator)

Python's ternary form puts the condition in the **middle**:

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      starterCode: `age = 17
status = "adult" if age >= 18 else "minor"
print(status)
`,
    },
  ]}
/>

Read it left to right as a sentence: *the value `"adult"`, if the age is
at least 18, otherwise `"minor"`.* It is an expression, not a statement,
so it can go anywhere a value can go, including inside another
expression:

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      starterCode: `x = 10
abs_x = x if x >= 0 else -x
print(abs_x)
`,
    },
  ]}
/>
