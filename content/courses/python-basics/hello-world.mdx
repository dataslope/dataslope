There is a tradition, almost as old as programming itself, that the first
program you write in any language should print the words "Hello, World!".
Python makes that exactly as short as you would hope.

<Figure
  slug="python-basics-hello-world-cutout"
  alt="The Dataslope marmot waving beside a retro computer monitor showing a single glowing speech bubble"
/>

<CodeBlock

      starterCode: `print("Hello, World!")
`,

That is the entire program. No `main`, no semicolons, no header files, no
compilation step. One line, and it runs. Compare that to the same program in
C, which needs an `#include`, a `main` function, a `return`, and curly braces
just to print one line. Python's brevity here is not an accident, it is a
design value, and we will see where that value came from in a moment.

browser is your Python.
</Callout>

## Why "Hello, World"?

The phrase has a real origin. It dates to Brian Kernighan, who used it in a
1972 tutorial for the **B** programming language at Bell Labs, and it became
famous when it reappeared in *The C Programming Language* (1978), the book he
wrote with Dennis Ritchie. It has been the ritual first program ever since.

<Figure
  slug="python-hello-world-hello-world-inline-cutout"
  alt="A machine's very first stroke leaving one short strip of type in an empty tray"
  caption="Your first program does one thing: put a single line of text on the screen."
/>

The choice is also practical. Printing output is the simplest possible form of
**input/output**, I/O, and every program is, at bottom, about I/O: it reads
some data, transforms it, and writes some results. `print` is your first taste
of that loop, which is why we begin here rather than with arithmetic or
variables.

## The `print` function

`print` is a built-in function that writes its arguments to **standard
output**, usually the terminal, or in our case the output panel below each
block. It is more flexible than it first looks.

<Figure
  slug="python-hello-world-print-function-inline-cutout"
  alt="A small machine with a printer on its side pushing out one short strip"
  caption="`print()` takes whatever you hand it and sends one line to standard output."
/>

When you pass several arguments, `print` joins them with a space:

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      starterCode: `print("Hello,", "World!")
`,
    },
  ]}
/>

You can change that separator with the `sep` keyword. This is handy for joining
fields without building a string by hand:

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      starterCode: `print("2025", "11", "30", sep="-")
`,
    },
  ]}
/>

And you can change what gets printed *after* the arguments with `end`. By
default that is a newline (`"\\n"`), which is why each `print` lands on its own
line. Override it and two prints share a line:

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      starterCode: `print("loading", end="...")
print("done")
`,
    },
  ]}
/>

Finally, `print` is not limited to strings. You can hand it numbers, lists,
dictionaries, almost anything, Python calls `str()` on each argument to turn
it into text first:

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      starterCode: `print(42)
print([1, 2, 3])
print({"name": "Ada", "year": 1815})
print(3.14, type(3.14))
`,
    },
  ]}
/>

## Comments

A comment is a note to humans that the interpreter ignores. In Python, a comment
starts with `#` and runs to the end of the line.

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      starterCode: `# This is a comment. The interpreter skips it entirely.
x = 1 + 2  # A comment can also sit at the end of a line.

print(x)
`,
    },
  ]}
/>

Notice what Python does *not* have: a `/* ... */` style for multi-line comments.
That omission is deliberate. The rationale was that long comments should be
broken into short lines anyway, and a block of `#` lines does that job fine.
People sometimes use a triple-quoted string to "comment out" a block, but be
careful, that is a string the interpreter actually evaluates and then throws
away, not a true comment:

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      starterCode: `"""
This is a string literal, not a comment. Python evaluates it,
then discards it because nothing keeps a reference. It is fine
for short notes at the top of a file, but '#' is the real comment.
"""

x = 10
print(x)
`,
    },
  ]}
/>

## Docstrings

There is one place where that "string at the top" trick is not a throwaway. A
string written as the **first statement** of a module, function, or class is
called a **docstring**, and Python keeps it around. Tools like `help()`, your
editor, and documentation generators read it to show what your code does.

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      starterCode: `def add(a, b):
    """Return the sum of two numbers."""
    return a + b

help(add)
`,
    },
  ]}
/>

Run that and you will see Python report the docstring back to you. It is stored
in the function's `__doc__` attribute. Docstrings are a convention rather than a
language keyword, but they are so universal that the whole Python tooling
ecosystem is built around them.

<Callout type="info" title="PEP 257: how to write a docstring">
[PEP 257](https://peps.python.org/pep-0257/), one of the numbered Python Enhancement
Proposals that record the language's conventions, lays out the rules: use
triple double-quotes (`"""like this"""`), put a one-line summary first, and add
details in later paragraphs. Documentation tools such as Sphinx, MkDocs, and
pdoc parse these docstrings to build entire API references automatically.
</Callout>

## The Zen of Python

Python's brevity, its dislike of boilerplate, its preference for one obvious way
to do things, these are not random. They are written down. Run the line below:

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      starterCode: `import this
`,
    },
  ]}
/>

What prints is **the Zen of Python**, a set of 19 guiding aphorisms, "Beautiful
is better than ugly," "Explicit is better than implicit," "Simple is better than
complex," "Readability counts." They were written by **Tim Peters**, one of
Python's most prolific early contributors, and they have been hidden inside
Python as an Easter egg since 2004. You can return to them any time by running
`import this`. They explain a surprising amount of why Python looks the way it
does, including the most famous decision of all, which we tackle on the next
page: significant whitespace.

## Test your knowledge

<MultipleChoice
  markdown={`What does the following snippet print?

\`\`\`python
print("a", "b", "c", sep="-", end="!")
\`\`\`

- [o] \`a-b-c!\`
  > Items are joined by \`sep\` and \`end\` is appended after them.
- \`a b c\`
  > The default \`sep\` is a single space, but here it has been overridden to \`"-"\`.
- \`a-b-c\\n\`
  > \`end\` was overridden too, so there is no trailing newline.
- \`a-b-c!\\n\`
  > The default \`end\` is \`"\\n"\`, but it was overridden to \`"!"\`.`}
/>

<MultipleChoice
  markdown={`What is a docstring?

- [o] A string literal at the top of a module, function, or class, used for documentation
  > Docstrings are stored in \`__doc__\` and read by \`help()\` and documentation tools.
- Any triple-quoted string in the code
  > Not quite. It must be the first statement in a module, function, or class.
- A string that is never executed
  > All string literals are evaluated, but docstrings are retained for introspection.
- A comment that starts with \`#\`
  > That is a regular comment, not a docstring.`}
/>

<MultipleChoice
  markdown={`Which of the following prints "Hello" with no trailing newline?

- [o] \`print("Hello", end="")\`
  > Setting \`end=""\` removes the newline.
- \`print("Hello", newline=False)\`
  > The parameter is named \`end\`, not \`newline\`.
- \`print("Hello", end="\\n")\`
  > \`end="\\n"\` is already the default, so this still prints a trailing newline.
- \`print("Hello", sep="")\`
  > \`sep\` controls how multiple arguments are joined, not the ending.`}
/>
