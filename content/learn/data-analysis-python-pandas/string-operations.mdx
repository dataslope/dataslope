codes, comments, log messages. Pandas exposes nearly all of
Python's string methods on whole columns via the `.str`
accessor.

## The basic shape

Any text column has a `.str` namespace. Methods you call on it
behave element-wise.

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      starterCode: `import pandas as pd

s = pd.Series(["  Aiko  ", "BILAL", "chen", "Diego "])

print(s.str.strip())
print()
print(s.str.upper())
print()
print(s.str.lower())
print()
print(s.str.title())
print()
print(s.str.len())
`,
    },
  ]}
/>

## Search and contains

`.contains` returns a boolean mask — perfect for filters:

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      starterCode: `import pandas as pd

df = pd.DataFrame(
    {
        "title": [
            "Senior Data Engineer",
            "Marketing Lead",
            "Data Scientist",
            "Sales Rep",
        ],
    }
)

# Anyone with "Data" in their title (case-insensitive)
print(df[df["title"].str.contains("Data", case=False)])
print()

# Anyone with "Lead" OR "Senior"
print(df[df["title"].str.contains("Lead|Senior", regex=True)])
`,
    },
  ]}
/>

By default, `.contains` uses regex. Use `regex=False` for
literal substring matching (faster and safer when the pattern
contains special chars).

## Split, slice, and extract

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      starterCode: `import pandas as pd

emails = pd.Series(["aiko@example.com", "bilal@work.io", "chen@uni.edu"])

# Split by '@' → returns lists
print(emails.str.split("@").head())
print()

# Get the first element after split
print(emails.str.split("@").str.get(0))
print()

# Get with expand=True returns a DataFrame
parts = emails.str.split("@", expand=True)
parts.columns = ["user", "domain"]
print(parts)
print()

# Or slice characters by position
print(emails.str[:5])  # first 5 chars
`,
    },
  ]}
/>

`.split(..., expand=True)` is one of the most useful patterns —
it lets you turn one column into many in a single call.

## Extract with regex

When the pattern is more structured, `str.extract` pulls out
named groups.

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      starterCode: `import pandas as pd

logs = pd.Series(
    [
        "2024-03-18 14:23:01 INFO  User logged in",
        "2024-03-18 14:24:55 ERROR Database timeout",
        "2024-03-18 14:25:10 WARN  Slow query: 1.4s",
    ]
)

parsed = logs.str.extract(
    r"(?P<date>\\d{4}-\\d{2}-\\d{2}) (?P<time>\\d{2}:\\d{2}:\\d{2}) (?P<level>\\w+)\\s+(?P<msg>.*)"
)
print(parsed)
`,
    },
  ]}
/>

Named groups become column names. This is hugely useful for
turning log files into a real DataFrame.

## A small cleaning example

Bringing several pieces together — normalizing employee names:

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      starterCode: `import pandas as pd

raw = pd.Series(
    [
        " aiko TANAKA ",
        "Bilal  Khan",  # double space
        "chen ZHANG",
        "DIEGO  ramirez",
        "",
        None,
    ]
)

clean = (
    raw.str.strip()  # outer spaces
    .str.replace(r"\\s+", " ", regex=True)  # collapse internal whitespace
    .str.title()  # nice casing
    .replace("", pd.NA)  # empties → missing
)
print(clean)
`,
    },
  ]}
/>

## Working with NaN in string columns

By default, string methods *propagate* NaN — a NaN input yields
a NaN output. Boolean methods (`contains`, `startswith`) can
optionally fill NaN with True/False using `na=`.

<CodeBlock
  adapter="python"
  files={[
    {
      filename: "main.py",
      starterCode: `import pandas as pd

s = pd.Series(["Engineer", None, "Sales", "Lead Engineer"])

print(s.str.contains("Engineer"))
print()
print(s.str.contains("Engineer", na=False))  # NaN → False
`,
    },
  ]}
/>

This `na=False` is *essential* when using `.contains` inside a
boolean filter — otherwise you get cryptic errors about NaN in
boolean indexers.

  markdown={`Why use the \`.str\` accessor at all?

- Pandas requires it
  > Pandas does not require the \`.str\` accessor; you can call \`.apply(str.upper)\` instead, but \`.str\` is the idiomatic, more readable approach.
- It is faster than Python loops
  > Speed is a benefit, but the primary reason to use \`.str\` is that it exposes Python's string methods as vectorized column operations with clean, readable syntax.
- [o] It provides vectorized string operations on whole columns of text — clean syntax and far faster than writing a Python for-loop over each value
  > \`.str.upper()\` on a million-row column is one call, not a million.
- It works only on integers
  > The \`.str\` accessor is specifically for string (object or StringDtype) columns; it does not work on integer columns.

The \`.str\` accessor is one of Pandas's most quietly powerful features.`}
/>

<MultipleChoice
  markdown={`Calling \`s.str.contains("foo")\` on a column with a NaN value will:

- Return True everywhere
  > Returning True for a NaN value would silently include rows with missing data in a filter, which is rarely the intended behavior.
- Return False everywhere
  > Returning False would silently exclude NaN rows from a filter; the actual default behavior is to propagate the NaN, making the missing position visible.
- [o] Propagate the NaN — the result has NaN at that position by default
  > Use \`na=False\` (or \`na=True\`) to coerce the NaN to a definite boolean — required if you want to use the result as a filter mask.
- Throw an error
  > \`str.contains\` does not raise an error when it encounters NaN; it returns NaN at that position by default, which only becomes a problem if you try to use the result as a boolean filter.

Forgetting \`na=False\` is a classic gotcha when filtering string columns that contain nulls.`}
/>

<MultipleChoice
  markdown={`What is the practical advantage of \`str.split("@", expand=True)\`?

- It is faster than not expanding
  > Performance is similar either way; the difference is in the return type, not speed.
- It returns a Series of lists
  > Without \`expand=True\`, the result is a Series of lists (one list per row) — \`expand=True\` is what converts it into a DataFrame.
- [o] It returns a DataFrame, one column per split piece — perfect for splitting one column into many
  > Useful for emails, names, addresses, anything with predictable delimiters.
- It removes the @ sign
  > The split delimiter is used as the splitting boundary and does not appear in the resulting pieces, but the motivation for \`expand=True\` is the DataFrame output, not delimiter removal.

The \`expand=True\` flag is the difference between a hard-to-use Series-of-lists and a friendly DataFrame.`}
