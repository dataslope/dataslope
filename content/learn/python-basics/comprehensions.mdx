A **comprehension** is a compact way to build a list, dict, set, or
generator by transforming and filtering an iterable. They are arguably
the most Pythonic feature in the language and once you internalize the
shape, you will reach for them constantly.

## List comprehensions

The general form:

```text
[expression for item in iterable if condition]
```

<CodeBlock
  adapter="python"
  initialCode={`squares = [x * x for x in range(1, 6)]
print(squares)

evens = [x for x in range(20) if x % 2 == 0]
print(evens)

upper = [w.upper() for w in ["a", "b", "c"]]
print(upper)
`}
/>

A list comprehension is equivalent to:

```python
result = []
for x in iterable:
    if condition:
        result.append(expression)
```

The comprehension is usually preferable because it states *what* you
want rather than *how*. But if your transformation has more than one
filter or grows beyond a single line, fall back to an explicit loop.

## Nested loops in comprehensions

Multiple `for` clauses behave like nested loops, left to right.

<CodeBlock
  adapter="python"
  initialCode={`pairs = [(x, y) for x in range(3) for y in range(3) if x != y]
print(pairs)

flat = [n for row in [[1, 2], [3, 4], [5, 6]] for n in row]
print(flat)
`}
/>

## Dict comprehensions

<CodeBlock
  adapter="python"
  initialCode={`squares_map = {x: x * x for x in range(1, 6)}
print(squares_map)

prices = {"apple": 1.0, "banana": 0.5, "cherry": 3.0}
expensive = {fruit: price for fruit, price in prices.items() if price >= 1.0}
print(expensive)

# Inverting a dict.
inverted = {v: k for k, v in prices.items()}
print(inverted)
`}
/>

## Generator expressions

Drop the brackets and you get a **generator expression** instead.
It produces items lazily, one at a time, which is great for memory.

<CodeBlock
  adapter="python"
  initialCode={`# List comprehension allocates the full list up front.
list_total = sum([x * x for x in range(1_000_000)])

# Generator expression streams one square at a time.
gen_total = sum(x * x for x in range(1_000_000))

print(list_total, gen_total, list_total == gen_total)
`}
/>

When a generator expression is the only argument to a function, the
inner parentheses can be dropped:

```python
sum(x * x for x in xs)        # nice
sum((x * x for x in xs))      # also fine, just noisier
```

## A note on readability

Comprehensions are powerful, but stacking too much logic into one
makes for unreadable code. Rule of thumb:

- Up to one `for` and one `if`: prefer the comprehension.
- More than that, or a complex expression: write a loop.
