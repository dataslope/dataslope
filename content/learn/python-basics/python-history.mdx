Python is a high-level, interpreted programming language created by
Guido van Rossum and first released in **February 1991**. Guido was
working at CWI in the Netherlands at the time and started Python as a
hobby project over the 1989 Christmas holidays. The name has nothing
to do with snakes: Guido was a fan of *Monty Python's Flying Circus*.

## A short timeline

## Design philosophy

Python's design is deeply influenced by **ABC**, an earlier teaching
language Guido helped build. The guiding ideas are captured in *The
Zen of Python* (PEP 20), which you can read at any time by running
`import this`.

The Zen prizes **readability**, **explicitness**, and **one obvious
way** to do something. These values explain a lot of Python's choices,
including its most famous one: significant whitespace.

## Why indentation is part of the syntax

Most languages use braces or `begin`/`end` keywords for blocks; Python
uses indentation. Guido's reasoning was that programmers indent code
to communicate structure to humans anyway, so the compiler may as well
trust that indentation rather than ignore it. The result is that
**badly indented code simply will not run**, which keeps every Python
codebase visually consistent.

## Tabs vs spaces: the never-ending debate

If you read PEP 8 (the official style guide) you will find a clear
answer:

> **Spaces are the preferred indentation method. Tabs should be used
> solely to remain consistent with code that is already indented with
> tabs.**

PEP 8 also recommends **four spaces per indentation level**. Why four?
It is wide enough to make nested blocks visually obvious but narrow
enough that deeply nested code still fits on screen.

A few practical points behind the debate:

1. **Python 3 forbids mixing tabs and spaces** for indentation inside
   the same block. Python 2 allowed it and silently treated a tab as
   "however many spaces it takes to reach the next multiple of 8",
   which caused famously confusing bugs.
2. **Editors differ on tab width.** A file indented with tabs can look
   2-space-wide in one editor and 8-space-wide in another. Spaces
   render identically everywhere.
3. **Accessibility argument for tabs.** Tabs let each developer
   configure their preferred visual width without changing the source.
   This is the strongest argument in favor of tabs.
4. **Tooling.** Almost every Python formatter (`black`, `autopep8`,
   `yapf`) defaults to four spaces. Going against the grain costs
   you time.

The community has effectively settled on **four spaces**, and that is
what we will use throughout this course.

## CPython, PyPy, and friends

The reference implementation of Python is **CPython**, written in C.
When people say "Python", they almost always mean CPython. A few
alternative implementations exist:

- **PyPy** uses a just-in-time compiler and can be much faster on
  pure-Python workloads.
- **Jython** runs on the JVM and can call Java libraries directly.
- **IronPython** targets the .NET runtime.
- **MicroPython** is a slim implementation for microcontrollers.
- **Pyodide** is CPython compiled to WebAssembly, which is what is
  running every code block on this page.

## The Python 2 to 3 transition

Python 3 was released in December 2008 and intentionally broke
backward compatibility to fix long-standing language warts. The
biggest changes were:

- `print` became a function: `print("hi")` instead of `print "hi"`.
- All strings are Unicode by default; `bytes` is a separate type.
- Integer division uses `//`; `/` always returns a float.
- `dict.keys()`, `range()`, `map()`, and friends return views/
  iterators instead of lists.

The transition took over a decade. Python 2 was officially sunset on
January 1, 2020. **In 2026 there is no reason to write new code in
Python 2.** Every example in this course assumes Python 3.
