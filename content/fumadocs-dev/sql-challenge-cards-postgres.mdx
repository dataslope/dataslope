## 1. JOIN basics

<SqlChallengeCard
  dialect="postgres"
  title="List orders with customer names"
  instructions={`Join \`orders\` and \`customers\` and return one row per order with the columns \`order_id\`, \`customer_name\`, and \`amount\`. Sort by \`order_id\` ascending.`}
  initSql={`CREATE TABLE customers (
  id   SERIAL PRIMARY KEY,
  name TEXT NOT NULL
);
CREATE TABLE orders (
  id          SERIAL PRIMARY KEY,
  customer_id INTEGER REFERENCES customers(id),
  amount      NUMERIC(10, 2)
);
INSERT INTO customers (name) VALUES ('Ada'), ('Linus'), ('Grace');
INSERT INTO orders (customer_id, amount) VALUES
  (1, 120.00), (2,  80.00),
  (1,  30.00), (3, 200.00),
  (2,  50.00);`}
  starterCode={`SELECT
  o.id AS order_id,
  c.name AS customer_name,
  o.amount
FROM
  orders o
  -- your JOIN and ORDER BY here
;`}
  solutionSql={`SELECT
  o.id AS order_id,
  c.name AS customer_name,
  o.amount
FROM
  orders o
  JOIN customers c ON c.id = o.customer_id
ORDER BY
  o.id ASC;`}
  tests={[
    {
      id: "row_count",
      name: "Returns 5 rows",
      description: "One per order",
      expectedRowCount: 5,
    },
    {
      id: "columns",
      name: "Has order_id, customer_name, amount",
      description: "In that exact order",
      expectedColumns: ["order_id", "customer_name", "amount"],
    },
    {
      id: "matches",
      name: "Matches the reference solution",
      description: "Same rows, same order",
      matchesSolution: true,
      ordered: true,
    },
  ]}
/>

## 2. CTE + aggregation

<SqlChallengeCard
  dialect="postgres"
  title="Top customer by total spend"
  instructions={`Return the single customer who has spent the most across all their orders, with columns \`customer_name\` and \`total_spent\`.`}
  initSql={`CREATE TABLE customers (
  id   SERIAL PRIMARY KEY,
  name TEXT NOT NULL
);
CREATE TABLE orders (
  id          SERIAL PRIMARY KEY,
  customer_id INTEGER REFERENCES customers(id),
  amount      NUMERIC(10, 2)
);
INSERT INTO customers (name) VALUES ('Ada'), ('Linus'), ('Grace');
INSERT INTO orders (customer_id, amount) VALUES
  (1, 120.00), (2,  80.00),
  (1,  30.00), (3, 200.00),
  (2,  50.00);`}
  starterCode={`-- Your query here:
SELECT
  c.name AS customer_name,
  0 AS total_spent
FROM
  customers c
LIMIT
  1;`}
  solutionSql={`WITH
  spend AS (
    SELECT
      customer_id,
      SUM(amount) AS total_spent
    FROM
      orders
    GROUP BY
      customer_id
  )
SELECT
  c.name AS customer_name,
  s.total_spent
FROM
  spend s
  JOIN customers c ON c.id = s.customer_id
ORDER BY
  s.total_spent DESC
LIMIT
  1;`}
  tests={[
    {
      id: "one_row",
      name: "Returns exactly one row",
      description: "The top customer",
      expectedRowCount: 1,
    },
    {
      id: "matches",
      name: "Matches the reference solution",
      description: "Grace, with 200.00",
      matchesSolution: true,
    },
  ]}
/>

## 4. Large result sets (infinite scroll)

The result pane virtualises its rows so a `SELECT *` against a 10k-row
table stays responsive — only the rows actually inside the viewport
are rendered. The **Tables** viewer above the editor pages its rows
in on scroll (infinite scroll) rather than loading all 10,000 up front.

<SqlChallengeCard
  dialect="postgres"
  title="Bucket 10,000 rows by score"
  instructions={`A 10,000-row table \`big\` is preloaded with a numeric \`score\` in [0, 100). Write a query that bins the rows into buckets of 10 (so \`bucket\` is \`0\`, \`10\`, \`20\`, …, \`90\`) and returns the bucket plus the row count, sorted by \`bucket\`.`}

  initSql={`CREATE TABLE big AS
SELECT
  s.i AS id,
  ('user_' || s.i) AS name,
  (s.i * 37 % 100) AS score
FROM generate_series(1, 10000) AS s(i);
`}
  starterCode={`SELECT
  *
FROM
  big
LIMIT
  5;`}
  solutionSql={`SELECT
  (score / 10) * 10 AS bucket,
  COUNT(*)::int AS n
FROM
  big
GROUP BY
  bucket
ORDER BY
  bucket;`}
  tests={[
    {
      id: "row_count",
      name: "10 buckets",
      description: "score in [0, 100) divided by 10",
      expectedRowCount: 10,
    },
    {
      id: "matches",
      name: "Matches the reference solution",
      description: "Same buckets, same counts, same order",
      matchesSolution: true,
      ordered: true,
    },
  ]}
/>

## 5. Remote dataset — Northwind from GitHub

`remoteInitSql` clones a complete sample database from the
[dataslope/datasets](https://github.com/dataslope/datasets) GitHub repo
before the first run — here the classic **Northwind** store (the
Postgres port, snake_case names). The script is fetched from
raw.githubusercontent.com and prepared for PGlite (psql meta-commands
and `CREATE DATABASE` lines are stripped); `initSql` (when present)
still runs afterwards for challenge-specific extras.

<SqlChallengeCard
