React challenge tests run inside the preview document after the
initial render commits, so they can assert on rendered output and even
dispatch clicks and await re-renders. Test bodies may be `async`, a
small `setTimeout` wait after `.click()` lets React flush the update.

function Counter() {

  return (
    <div style={{ fontFamily: "system-ui", margin: 24 }}>

## Modules across files (multi-file)

A challenge workspace can span several files. `main.tsx` mounts the app,
`App.tsx` holds the component, and plain modules (`.ts`) are imported the
way a real project imports them, esbuild bundles the whole workspace in
the browser before the preview renders. Tests still run against the
mounted DOM, so the split across files is invisible to them.

## Composing a component + styles (multi-file)

Here `App.tsx` imports a `StatusBadge` component from its own file and a
stylesheet through a plain `import "./styles.css"`. The CSS import
compiles straight into the preview document, so a test can assert the
rendered badge actually picks up its class-based styles.
