Welcome to **Dataslope · Fumadocs Dev**, a development-only gallery of
the executable MDX components (code blocks, challenge cards, and more)
used across the [courses](/courses), exercised against every language
and runtime shipped in the [Playground](/playground).

Every code block on these pages runs entirely in your browser. There's
no server round-trip, the same WebAssembly runtimes that power the
playground (Pyodide, WebR, php-wasm, browsercc, CheerpJ, .NET wasm)
are loaded on demand.

## Languages

- Python, Pyodide 3.14 with NumPy, Pandas, Matplotlib, Plotly
- R, WebR 4.5 with rich graphics and data frames
- JavaScript, native browser execution
- TypeScript, TypeScript transpiled in the browser
- Web (HTML/CSS/JS), live sandboxed page preview on native browser primitives
- React, TSX compiled in-browser by esbuild-wasm, modules from esm.sh
- PHP, php-wasm
- C, clang via browsercc
- C++, clang++ via browsercc
- Java, javac + the JVM via CheerpJ
- C#, Roslyn on .NET wasm

## Shell and version control

- Bash, just-bash over an in-memory filesystem. See [Bash Blocks](/fumadocs-dev/bash-blocks)
  and [Bash Challenge Cards](/fumadocs-dev/bash-challenge-cards).
- Git, isomorphic-git for the repository over that same shell. See
  [Git Blocks](/fumadocs-dev/git-blocks) and [Git Challenge Cards](/fumadocs-dev/git-challenge-cards).

These four components run commands rather than source, and their challenge
cards grade on **state** rather than printed output alone, which lets
objectives tick live as the learner works. A Git objective reads the
repository, because what `git commit` printed is beside the point; a shell
objective reads the output *and* the filesystem, because in a shell lesson
either one can be the deliverable.

## How code blocks work

- Each `<CodeBlock>` is independent. State you set in one block is
  **never** visible from another, even within the same page.
- Many blocks ship with collapsed *initialization code* that runs
  before your edits, handy for setting up imports or sample data.
- Outputs render the same way the playground does: `stdout` / `stderr`
  text, HTML tables (Pandas, R `data.frame`), images (Matplotlib,
  base R graphics), and interactive Plotly charts.
