C challenges compile your source to WebAssembly via **browsercc**
(clang + lld) and run the resulting WASI binary in your browser.

Because each run produces a fresh process, C challenges use the
**stdout-based** test mode (`expect: { ... }`), there's no
interpreter context to inject per-test assertions into.

## 2. Sum the first N integers

<ChallengeCard
  adapter="c"
  title="Sum 1..N"
  instructions={`Compute the sum of integers from 1 to \`N\` (inclusive) where \`N = 100\`, and print it followed by a newline. The expected output is \`5050\`.`}
  files={[
    {
      filename: "main.c",
      starterCode: `#include <stdio.h>

int main(void) {
  int N = 100;
  long sum = 0;
  // your code here
  printf("%ld\\n", sum);
  return 0;
}
`,
      solutionCode: `#include <stdio.h>

int main(void) {
  int N = 100;
  long sum = 0;
  for (int i = 1; i <= N; i++)
    sum += i;
  printf("%ld\\n", sum);
  return 0;
}
`,
    },
  ]}
  tests={[
    {
      id: "sum_100",
      name: "Sum of 1..100 is 5050",
      description: "Single line: `5050`",
      expect: { stdoutEquals: "5050" },
    },
  ]}
/>

## Multi-file challenge

Multi-file challenges open with a non-sortable, non-closeable tab bar
above the editor. Every file is staged into browsercc's virtual
filesystem before each run, so the entry translation unit can
`#include` sibling headers.

<ChallengeCard
  adapter="c"
  title="Implement greet() in utils.c"
  instructions={`Open \`utils.c\` and implement \`greet()\` so that it prints \`Hello, World!\` followed by a newline. \`main.c\` is provided, it calls \`greet()\` once.`}
  entryFilename="main.c"
  files={[
    {
      filename: "main.c",
      starterCode: `#include "utils.h"

int main(void) {
  greet();
  return 0;
}
`,
    },
    {
      filename: "utils.h",
      starterCode: `#ifndef UTILS_H\n#define UTILS_H\nvoid greet(void);\n#endif\n`,
    },
    {
      filename: "utils.c",
      starterCode: `#include "utils.h"
#include <stdio.h>

void greet(void) {
  // your code here
}
`,
      solutionCode: `#include "utils.h"
#include <stdio.h>

void greet(void) { printf("Hello, World!\\n"); }
`,
    },
  ]}
  tests={[
    {
      id: "greets",
      name: "Prints `Hello, World!`",
      description: "Exact stdout match",
      expect: { stdoutEquals: "Hello, World!" },
    },
  ]}
/>

## Reading standard input

A card takes the same `stdin` prop. On a card the input is part of the
*question*: the tests grade output produced from it, so the reference
solution is written against it and Reset restores it after a learner
experiments in the panel.

<ChallengeCard
  adapter="c"
  title="Average the numbers on stdin"
  stdin={`5
17
4
23
8
15`}
  instructions={`The first line of input is a count \`n\`; the next \`n\` lines each hold one
integer. Print the count and their mean, rounded to two decimals:

\`\`\`text
5 values, mean 13.40
\`\`\``}
  files={[
    {
      filename: "main.c",
      starterCode: `#include <stdio.h>

int main(void) {
  int n;
  if (scanf("%d", &n) != 1) return 1;
  // read n integers, then print the count and the mean
  return 0;
}
`,
      solutionCode: `#include <stdio.h>

int main(void) {
  int n;
  if (scanf("%d", &n) != 1) return 1;

  long total = 0;
  int read = 0;
  for (int i = 0; i < n; i++) {
    int value;
    if (scanf("%d", &value) != 1) break;
    total += value;
    read++;
  }

  printf("%d values, mean %.2f\\n", read, read ? (double)total / read : 0.0);
  return 0;
}
`,
    },
  ]}
  tests={[
    {
      id: "mean",
      name: "Prints the count and the mean",
      description: "Exact stdout match (trimmed)",
      expect: { stdoutEquals: "5 values, mean 13.40" },
    },
    {
      id: "no_stderr",
      name: "No diagnostics",
      description: "Stderr should be empty",
      expect: { noStderr: true },
    },
  ]}
/>
