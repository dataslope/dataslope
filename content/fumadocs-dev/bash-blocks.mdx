title: "Bash Blocks"
description: Sandbox for the `<BashBlock>` component, a real shell you can type into inside lesson prose.
---

`<BashBlock>` is a terminal, not a script runner. Type a command, press
Enter, read the output, type the next one. The session remembers where you
are: `cd src` then `ls` lists `src`, a variable you set stays set, and a
function you define stays defined.

The engine is just-bash over an in-memory filesystem, so pipes,
redirection, globs, loops and functions all work. Nothing is saved: a
reload starts over.

Every block gets its own working directory unless it opts into sharing one.

## Just type

No `commands` prop at all. The prompt shows where you are and a block
cursor blinks where you are typing.

`Tab` completes the way bash does: it fills in the longest common prefix,
and prints the candidates when the choice is genuinely ambiguous. The first
word completes against commands, everything after it against files in the
current directory.

<BashBlock scenario="small-project" label="Have a look around" />

Try `ls`, then `cd src`, then `pwd`. The prompt follows you.

## A block with a starting script

Pass `commands` and the block gains a Run button that plays them into the
same terminal. The prompt stays live afterwards, so a reader can keep
going from wherever the script left them.

<BashBlock
  scenario="log-files"
  label="Find the failures"
  commands={`grep ERROR app.log
grep ERROR app.log | wc -l`}
/>

## The file strip

Every block carries a one-line summary of the working directory, collapsed
by default. Open it to see the tree, with the paths your last command
touched highlighted.

<BashBlock
  scenario="small-project"
  label="Redirection writes a file"
  expandState
  commands={`wc -l notes.txt > count.txt
cat count.txt`}
/>

## State really persists

This is the part a textarea cannot do. Run these one at a time and watch
the prompt change, then define a function and call it on a later line.

<BashBlock
  scenario="small-project"
  label="cd, variables, functions"
  commands={`cd src
pwd
NAME=world
echo "hi $NAME"
greet() { echo "hello, $1"; }
greet there`}
/>

## Color

just-bash has no `ls --color`, but it passes escape sequences straight
through, so anything you print with them renders as color. The palette is
the classic 16 ANSI terminal colors rather than the Dataslope ramp,
because output colored with `31m` should look the way it looks in a
terminal.

<BashBlock
  scenario="empty"
  label="ANSI escapes"
  commands={"printf '\\033[31mred\\033[0m \\033[1;32mbold green\\033[0m \\033[33myellow\\033[0m\\n'"}
/>

## Text processing

`cut`, `sort`, `uniq` and `awk` are all present.

<BashBlock
  scenario="sales-csv"
  label="Revenue by region"
  commands={`cut -d, -f2 sales.csv | tail -n +2 | sort | uniq -c
awk -F, 'NR>1 {sum[$2] += $4} END {for (r in sum) print r, sum[r]}' sales.csv`}
/>

## find and xargs

<BashBlock
  scenario="messy-names"
  label="Clean up the scratch files"
  expandState
  commands={`find . -name '*.tmp'
find . -name '*.tmp' | xargs rm

/>

## Blocks that share a directory

Blocks with the same `dir` id share one working directory, including the
shell state, so a `cd` in the first is still in effect in the second.
Blocks without one are isolated.

<BashBlock
  dir="pipeline"
  scenario="log-files"
  label="Step 1: extract"
  commands={`grep ERROR app.log > errors.log`}
/>

<BashBlock
  dir="pipeline"
  scenario="log-files"
  label="Step 2: count what you extracted"
  expandState
  commands={`wc -l < errors.log`}
/>

## Errors

A failing command shows its real message and a non-zero exit code, the
same as a terminal.

<BashBlock
  scenario="small-project"
  label="A file that is not there"
  commands={`cat missing.txt
echo "exit code: $?"`}
/>

## Props

| Prop | Type | Default | Notes |
| --- | --- | --- | --- |
| `commands` | `string` | none | Optional starting script, played by the Run button. Without it the block is just a prompt. |
| `scenario` | `string` | `small-project` | `empty`, `small-project`, `log-files`, `sales-csv`, `messy-names`. |
| `dir` | `string` | none | Share a working directory and shell state with blocks carrying the same id. |
| `expandState` | `boolean` | `false` | Open the file listing on mount. |
| `label` | `string` | none | Caption in the block header. |
| `rows` | `number` | `10` | Terminal height, in rows, before it scrolls. |

### Keys

| Key | Does |
| --- | --- |
| `Enter` | Run the line. |
| `↑` / `↓` | Walk back and forward through history. |
| `Tab` | Complete a command or a filename. |
| `Ctrl-L` | Clear the scrollback. |
| `Ctrl-C` | Abandon the line without running it. |

The real `<input>` is off-screen and only holds the value and the caret;
the line you see is rendered text, which is what lets the cursor be a
blinking block rather than an I-beam. Clicking anywhere in the terminal
puts focus back on the prompt.

```jsx
<BashBlock scenario="log-files" label="Find the failures" />
```
