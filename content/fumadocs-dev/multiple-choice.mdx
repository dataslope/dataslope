---
title: Multiple Choice Questions
description: Markdown-authored quiz cards that learners can submit, retry, and learn from.
---

The `<MultipleChoice>` component lets MDX authors embed quiz-style
questions directly inside a Learn page. Each question is a single
Markdown document, there are no JSON arrays of choices to keep in sync
with the prose.

## Syntax

| Element | Syntax |
| --- | --- |
| Question body | Everything before the first `-`&nbsp;choice line |
| Incorrect choice | `- Choice text` |
| Correct choice | `- [o] Choice text` |
| Per-choice explanation | `> Explanation` (indented blockquote under the choice) |
| Multi-line choice | Indent continuation lines by 2+ spaces |
| Code-block choice | Open fence on the choice line (e.g. `` - ```python ``), indent all code lines and the closing fence by 2+ spaces |
| Overall explanation | Any text after the choices block (no marker needed) |

### Notes

- Mark the correct choice with `[o]`. Each question has exactly one
  correct answer.
- Use `*` or `1.` for lists inside the question body, `-` is reserved
  for choices.
- Math works anywhere, `$x^2$` for inline and `$$\int_0^\infty$$` for
  display equations.
- Learners pick an answer, see per-choice feedback, and can click **Try
  again** to keep iterating.
- Code blocks in choices are fully highlighted (Python, SQL, JS, and
  many other languages are auto-detected by highlight.js).

## 2. With math equations

Inline math (`$…$`) and display math (`$$…$$`) render through KaTeX, so
authors can drop equations into the body, choices, per-choice
explanations, or the overall explanation.

<MultipleChoice
  markdown={`What is $\\frac{d}{dx}[x^2]$?

- $x$
- [o] $2x$
  > Applying the power rule: bring down the exponent and reduce it by 1.
- $x^2$
- $2$

The power rule states that $\\frac{d}{dx}[x^n] = nx^{n-1}$.`}
/>

````markdown
What is $\frac{d}{dx}[x^2]$?

- $x$
- [o] $2x$
  > Applying the power rule: bring down the exponent and reduce it by 1.
- $x^2$
- $2$

The power rule states that $\frac{d}{dx}[x^n] = nx^{n-1}$.
````

## 3. Rich question body

The question body is full Markdown, lists, inline code, **bold**, and
fenced code blocks all work. Remember to use `*` or `1.` for any lists
inside the body so the parser doesn't mistake them for choices. Code
blocks in the body are syntax-highlighted automatically.

<MultipleChoice
  markdown={`A Python function is defined as:

\`\`\`python
def total(prices, tax_rate=0.07):
    return sum(prices) * (1 + tax_rate)
\`\`\`

What does \`total([10, 20, 30])\` return?

- 60
  > That's the pre-tax total, the function also applies a 7% tax.
- [o] 64.2
  > \`60 * 1.07 = 64.2\`.
- 70.0
- An error, \`tax_rate\` must be supplied.
  > \`tax_rate\` has a default value of \`0.07\`, so it's optional.

The function multiplies the sum of \`prices\` by \`1 + tax_rate\`. With the default
tax rate of 7 %, the result is \`60 × 1.07 = 64.2\`.`}
/>

````markdown
A Python function is defined as:

```python
def total(prices, tax_rate=0.07):
    return sum(prices) * (1 + tax_rate)
```

What does `total([10, 20, 30])` return?

- 60
  > That's the pre-tax total, the function also applies a 7% tax.
- [o] 64.2
  > `60 * 1.07 = 64.2`.
- 70.0
- An error, `tax_rate` must be supplied.
  > `tax_rate` has a default value of `0.07`, so it's optional.

The function multiplies the sum of `prices` by `1 + tax_rate`. With the default
tax rate of 7 %, the result is `60 × 1.07 = 64.2`.
````

## 4. Code blocks as choices

Choices can be fenced code blocks, ideal for questions that ask learners
to identify the correct snippet. Open the fence right after `- ` (or
`- [o] `), then indent all code lines and the closing fence by 2 spaces.
Blank lines inside the block are preserved exactly as authored.

<MultipleChoice
  markdown={`Which snippet correctly creates a pandas DataFrame with columns A and B?

- \`\`\`python
  import pandas as pd

  pd = pd.DataFrame({"A": [1, 2, 3], "B": [4, 5, 6]})
  \`\`\`
  > \`pd\` is reassigned here, shadowing the pandas module, any subsequent use of \`pd\` as a module (e.g. \`pd.Series(...)\`) would raise a \`TypeError\`.
- \`\`\`python
  import numpy as np

  df = np.array({"A": [1, 2, 3], "B": [4, 5, 6]})
  \`\`\`
  > \`np.array\` doesn't accept a dict and would raise a \`TypeError\`.
- [o] \`\`\`python
  import pandas as pd
  import numpy as np

  df = pd.DataFrame({"A": [1, 2, 3], "B": [4, 5, 6]})
  \`\`\`
  > \`pd.DataFrame\` accepts a dict of column name → values.

A \`DataFrame\` is pandas's primary 2-D data structure. Pass a plain dict
where each key becomes a column label and each value is the column's data.`}
/>

````markdown
Which snippet correctly creates a pandas DataFrame with columns A and B?

- ```python
  import pandas as pd

  pd = pd.DataFrame({"A": [1, 2, 3], "B": [4, 5, 6]})
  ```
  > `pd` is reassigned here, shadowing the pandas module, any subsequent use of `pd` as a module (e.g. `pd.Series(...)`) would raise a `TypeError`.
- ```python
  import numpy as np

  df = np.array({"A": [1, 2, 3], "B": [4, 5, 6]})
  ```
  > `np.array` doesn't accept a dict and would raise a `TypeError`.
- [o] ```python
  import pandas as pd
  import numpy as np

  df = pd.DataFrame({"A": [1, 2, 3], "B": [4, 5, 6]})
  ```
  > `pd.DataFrame` accepts a dict of column name → values.

A `DataFrame` is pandas's primary 2-D data structure. Pass a plain dict
where each key becomes a column label and each value is the column's data.
````
